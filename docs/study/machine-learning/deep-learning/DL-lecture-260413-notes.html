Advanced Optimization II — Modern Techniques, and Introduction to CNNs

Pretraining · Knowledge Distillation · Curriculum Learning · Motivation and Computation of Convolution

1 Full Overview

2 Part I. Modern Techniques to Aid Optimization

2.1 Batch Normalization — Key Review and Limitations

Batch normalization (BN) is, strictly speaking, not an optimization algorithm but an adaptive reparameterization technique for parameters being trained. It normalizes the activation values of the mini-batch \(H\) to a mean \(\mu\) and a standard deviation \(\sigma\) to group the training and test data into similar statistical ranges:

\[ H' = \frac{H - \mu}{\sigma}, \qquad \text{테스트 시에는 학습 중 누적한 running } \mu, \sigma \text{ 사용} \]

WarningSide effects of BN: Loss of expressiveness

Forcing normalization of the mean and variance can result in the loss of information contained in the magnitude of the activation values. This is a negative effect that kills information that could be useful for generalization. To compensate for this, learnable scale/shift parameters are introduced:

\[ H \;\leftarrow\; \gamma H' + \beta \]

Since \(\gamma, \beta\) is learned from data, it secures degrees of freedom to “reverse” normalization if the network needs to.

NoteTrends of the Times: Why BN Is Used Less These Days

BN was very effective in the MLP and CNN era, but its usage has decreased significantly since Transformers became mainstream. Because Transformers learn weights based on query-key similarity, the benefits of batch-level statistical normalization are small, and instead, layer normalization has become the standard. This is a good example that the validity of a technique depends on the architectural paradigm.

Wireless Communication Perspective: BN is similar to Automatic Gain Control (AGC) of a received signal + removal of the DC offset. Normalizing the signal to a constant dynamic range stabilizes post-processing (quantization, detection), but if the received power itself is information (e.g., RSSI-based distance estimation), that information is lost — \(\gamma, \beta\) corresponds to a learning gain stage that compensates for this loss.

2.2 Pretraining: Classical Motives and Modern Reversals

2.2.1 Classical pretraining — from small to large

The traditional motivation is as follows: If a model is large and complex, it is difficult to optimize it directly from the start. Therefore:

  1. Train a small (simple) model on a simple task first.
  2. Expand into complex tasks of interest by gradually increasing complexity.

The method of greedily breaking this down into task units and learning them one by one is greedy supervised pretraining. For example, when training a deep network, a shallow subnetwork is first trained with the loss value, and then a new layer is added on top of it and fine-tuned. Since the lower layers trained earlier already contain information common to various semantics, they serve as a good starting point for training new layers, resulting in faster convergence than training the entire thing from scratch.

The background of this approach lies in the constraints of an era when training data was extremely scarce. Such stepwise optimization was necessary to reach a good local minimum with a small number of samples.

2.2.2 Modern Pretraining — The Philosophy of Opposites

ImportantParadigm reversal

Modern pretraining is exactly opposite to classical motivation:

\[ \text{거대 데이터} \;\Rightarrow\; \text{거대 모델을 먼저 학습} \;\Rightarrow\; \text{downstream task의 좋은 초기점으로 사용} \]

Instead of growing from a small model, a massive model is trained on massive data from the start and then brought over as a starting point for various downstream tasks. A pre-trained model that serves as the foundation for multiple downstream tasks in this way is called a foundation model.

Classification Classical pretraining Modern pretraining
Data size Very small Very large (Huge data pool)
Model Growth Direction Small Model → Adding Complexity Large Model from the Start
Objective Gradually alleviate difficult optimizations Provide a good starting point for downstream tasks
Representative method Greedy supervised pretraining Foundation model + fine-tuning

2.2.3 MAML: Model-Agnostic Meta-Learning

A representative modern pretraining technique is MAML (Finn, Abbeel, Levine, ICML 2017). The name contains two core keywords:

  • Model-agnostic: Not dependent on a specific architecture and applicable to all models using gradient-based optimization.
  • Fast adaptation: A pre-trained model can be adapted to a downstream task with very few iterations (e.g., 1–2 epochs of fine-tuning).

The idea is simple — to pretrain simultaneously on a wide variety of small tasks. By pre-training on tasks with different purposes, such as image classification, segmentation, next-token prediction, and action prediction, the model becomes ready to achieve high performance with only a small number of gradient updates, regardless of the downstream task. Technically, this is implemented by simultaneously applying gradient updates for multiple tasks and shares a similar spirit with instruction fine-tuning. In practice, this technique is actively used in robotics to adapt foundation models universally to various manipulation tasks.

Wireless Communication Perspective: MAML can be likened to a general-purpose channel estimator trained simultaneously in various channel environments (urban/suburban/indoor). An estimator overfitted to specific channel statistics must be retrained from scratch when the environment changes, whereas an estimator meta-trained with various channel distributions converges quickly in a new environment with only a small number of pilots (a few adaptation steps).

2.3 Knowledge Distillation

2.3.1 Key Idea

This is a technique that trains a small student network using the output (soft label, logit) of a large teacher network as supervision (Hinton, Vinyals, Dean, 2015). The procedure is:

  1. First, train a large teacher network.
  2. When training the student network, the teacher’s soft label is used as additional supervision along with the cross-entropy loss** on the original one-hot correct answer.

Interestingly, this paper was not submitted to a conference but was published only on arXiv — although the idea was in a form that would have been difficult to pass conference review because it was “too simple,” it actually worked very well and is still widely used to this day (even utilized in training recent DeepSeek series models). It is also a lesson that simplicity and usefulness are separate axes.

2.3.2 Why soft labels are helpful

Reason 1 — Categories are interrelated. Let’s consider oranges and grapefruits. The two fruits share shape and texture, and their essential difference is merely the color of the flesh. However, one-hot encoding enforces overly assertive supervision regarding an image, labeling it “Grapefruit 100%, Orange 0%.” This is a distinction that even humans cannot be certain of based on appearance alone. Creating soft labels by asking people for probabilities is also subjective and difficult to trust. On the other hand, a teacher network provides outputs such as “Grapefruit 75%, Orange 20%, Other 5%,” and this distribution tells more about the semantic structure of the image than hard one-hot encoding. In other words, soft labels relax the ambiguous boundaries between classes.

Reason 2 — A single hard label itself is subjective and noisy. Labels on ImageNet were determined by majority vote after asking three people about the same image. An image might contain a woman, sunglasses, a hand, and lipstick, yet the label is “lipstick,” and in a photo of a couple inside a car, a seatbelt measuring just a few pixels might be labeled. As such, hard labels are often “wrong” in a sense. Soft labels buffer this noise.

Reason 3 — Ensemble Effect. Using multiple teachers provides more stable and useful supervision through the ensemble of teacher outputs.

Wireless Communication Perspective: This is exactly the same structure as the difference between hard decision vs. soft decision in channel decoding. If the demodulator cuts the bits into 0s and 1s and transmits them (hard), reliability information is lost; however, if it transmits soft information in the form of LLR (log-likelihood ratio), the performance of the downstream decoder (LDPC/Turbo) is significantly improved. The Teacher’s logit corresponds exactly to this LLR, and the one-hot label corresponds to the hard decision.

2.4 Better Architecture — Design that “helps” optimize

Although not strictly an optimization technique, the architecture itself enables convergence to a better optimal solution. Examples include the evolution from MLP to CNN to Transformer, and the numerous CNN variations in between (ResNet, DenseNet, U-Net, etc.).

Notably, ResNet provides a gradient highway through skip (highway) connections to prevent gradients from vanishing as they pass through deep layers.

TipUnderstanding via Causal Mechanism Chains

Instead of memorizing “ResNet helps with learning” as a single line, let’s connect it to the mechanism: skip connection \(y = F(x) + x\) → Add identity component \(\frac{\partial y}{\partial x} = \frac{\partial F}{\partial x} + I\) to the Jacobian → The term multiplied by the gradient during backpropagation does not collapse near zero → Meaningful gradient transmission to lower layers even in deep networks → Stable optimization of deeper models is possible.

2.5 Continuation Methods and Curriculum Learning

2.5.1 Continuation methods

Instead of directly optimizing the cost function \(J(\theta)\), we sequentially optimize a series of increasingly difficult cost functions \(\{J^{(0)}, J^{(1)}, \dots, J^{(n)}\}\). \(J^{(0)}\) is the smoothest and easiest function, and \(J^{(n)}\) is the actual objective function with many local curvatures. By using the solution obtained from the easy function as the initial point for the next step, we can induce the initial point/weights so that the local optimization spends most of its time in a well-behaved region, thereby increasing the probability of finally reaching a better local minimum.

2.5.2 Curriculum learning (shaping)

One implementation of the Continuation Method is curriculum learning. Like human learning, it trains easy tasks first and difficult tasks later.

NoteIntuition vs. Empirical Verification, and Contemporary Importance

While intuitively very plausible, the performance gains in general supervised learning are often insignificant. However, it is crucial in areas where training is difficult, such as reinforcement learning or weakly supervised learning. Particularly in the era of foundation models, curriculum design—specifically regarding “what data to feed and in what order”—became a key issue that determined the very GPU cost required to train massive models.

Wireless Communication Perspective: It is helpful to think of the incremental redundancy in HARQ. Instead of sending at the lowest code rate (relative to the most difficult condition) from the start, it begins with an easy condition (high code rate) and gradually adds redundancy as needed — it resembles a structure that uses resources efficiently by progressively increasing the difficulty of the problem.

3 Part II. Introduction to CNNs — Why Convolution?

3.1 Starting Point: The Paradox of the Universal Approximation Theorem

To recap, the Universal Approximation Theorem (UAT) states that a feed-forward network of a single hidden layer and a finite number of neurons can approximate a continuous function over a compact subset of \(\mathbb{R}^n\) with arbitrary precision under weak assumptions about the activation function (Cybenko, 1989, first proven for sigmoid).

Although standard rigorous proofs of the same form for CNNs and Transformers are not presented, they can be viewed as variations of MLPs with different inductive biases (structural constraints) — differing only in architecture, built upon the same optimization procedure and learning paradigm. This, then, creates a paradox:

ImportantKey Questions

According to UAT, MLPs can approximate almost any function. Then why are other architectures like CNNs and Transformers needed?

Key to the answer: UAT only speaks of representability (existence), not whether the solution is learnable with finite data and computation. The inductive bias of the architecture determines the statistical and computational efficiency of learning.

3.2 Viewing Images with MLPs — The Curse of Permutation Invariance

Let’s assume we classify sports sedan images using an MLP. The MLP assigns independent weights to each pixel, stacks hidden layers to reach the semantic level, and then learns through backpropagation. Here is a critical thought experiment:

Does an MLP learn something different if you shuffle all the pixel locations of an image? — No. Only the order of the weights is shuffled in the same way; it learns exactly the same thing. In other words, from an MLP perspective, the original image and the pixel-shuffled image are completely identical problems.

For humans, it is easy to recognize a car in the original image but impossible in a scrambled one. For MLPs, both are just as difficult as the latter — because they cannot utilize the powerful cue of spatial structure at all. As a result, mapping images to the label space requires a massive number of training samples.

TipA pixel is meaningless on its own

One key lesson reached by decades of computer vision research: Do not encode pixels individually. Like Kim Chun-su’s poem “Flower”—which was nothing more than a gesture before being given a name—individual pixels have no meaning and only acquire meaning when grouped together with neighboring pixels. Therefore, images must be encoded in units of patches. This is the biggest motivation for moving from MLPs to CNNs, and it implants an inductive bias in the network that “a patch is the basic unit of understanding 2D information.”

3.3 The Idea of a Filter — Two Fundamental Questions

Let’s assume we want to recognize an image of the number “5”. If there is a weight window (filter) that perfectly matches the image, the normalized correlation score becomes 1, and since we know the meaning of the filter, we can be confident that “this image is 5”. If we apply a different filter, the correlation score will be low, so we can reject it.

However, if we were to use a filter that matches the entire image, we would need as many filters as there are images in the world — which is clearly inefficient. So, we shift our thinking: Let’s break the image into patches and train patch-level “fragment filters” as a kind of basis to represent an arbitrary input. Then, two questions remain.

  1. What filter set is needed?
  2. Where on the image should that filter be applied?

3.3.1 History of Question 1 — From Hand-Designed Filters to Learned Filters

Early computer vision relied on filters designed by humans: Gaussian filters, filters created by rotating anisotropic Gaussians by multiple angles (capturing directional information + noise smoothing), followed by HOG (Histogram of Oriented Gradients), which aggregates edge components into angle-based histograms, and the similar series SIFT (Scale-Invariant Feature Transform). While these worked well for some applications, they did not work for all — they encountered the No Free Lunch theorem, which implies that if a new feature set must be designed for every application, generalization is impossible. The promise of CNNs comes from this: Let’s learn from data instead of designing filters by hand.

3.3.2 History of Question 2 — Full scan from interest point

Initially, we first identified distinctive locations (interest points) to apply the filter to, and then extracted and aggregated histograms from the surrounding areas. However, reliably extracting interest points for various image transformations was a difficult problem in itself. Therefore, we shifted to a practical solution: sweep all locations with the filter and take the response from the location where the filter reacts most strongly. This is the motive behind max pooling operations within CNNs — “Wherever this filter needs to react, we only need to look at the maximum response.”

3.4 Convolution Operation — Definition and Three Correlation Operations

3.4.1 Definition

Convolution (symbol \(*\)) is an operation that creates a third function from two functions. It is the operation familiar from signals and systems. In one dimension:

\[ (f * g)(t) = \int_{-\infty}^{\infty} f(\tau)\, g(t - \tau)\, d\tau \]

Flip one function (along the vertical axis) and slide from \(-\infty\) to \(+\infty\), assigning the integral value of the overlapping region of the two functions to the value of the third function. The result is the same regardless of which function is flipped (commutative property). Essentially, this calculates the correlation (due to the shift) between two functions, and 2D convolution performs the same operation on two axes—that is, it is the very sweep operation we wanted, which computes 2D spatial information and calculates similarity.

3.4.2 Convolution vs. Cross-correlation vs. Autocorrelation

Operation Whether to flip Target Definition (1D continuum)
Convolution flip one function two different functions \(\int f(\tau)g(t-\tau)d\tau\)
Cross-correlation No flip Two distinct functions \(\int f(\tau)g(t+\tau)d\tau\)
Autocorrelation No flip Self \(\int f(\tau)f(t+\tau)d\tau\)
Note“CNN” is actually a cross-correlation network

Actual CNN implementations are cross-correlation rather than convolution. The reason is simple: when training filters, the round-trip flip of “flip when saving → flip back when applying” becomes meaningless redundancy. Even if the flip is omitted, the network learns exactly the same filter (in its flipped form). However, “cross-correlation neural network” is cumbersome to say, and “convolution” sounds cooler, so the name simply stuck. Section 7.2 of d2l.ai also clarifies this point.

Wireless Communication Perspective: This distinction is exactly the same picture as a matched filter. The impulse response of a matched filter that maximizes SNR in AWGN is \(h(t) = s^\ast(T-t)\) — the time flip of the transmitted pulse. Therefore, the output of matched filtering (convolution) is ultimately identical to the correlator output of the received signal and the template. The CNN filter is a 2D matched filter bank learned from the data, and the feature map can be read as the correlation output for each template.

3.5 Core assumption of CNN: Stationarity

CNNs stand on one major assumption for understanding 2D information (LeCun, 1998):

ImportantStationarity assumption

The statistics of an image patch are identical regardless of location. In the language of generative models: There is a single data-generating distribution for a patch, and an image can be viewed as a spliced collection of patches sampled from that distribution. (In fact, modern image/video generative models learn such massive distributions from vast amounts of images.)

Why is this natural? Let’s assume two people take pictures of the same mountain. A patch that is in the top left of one person’s photo can appear in the center of the other person’s photo — since the same patch can appear at any location when the same 3D world is projected into 2D, it is reasonable to assume that the patch comes from a single distribution regardless of location when considering the “set of images that a person can take.”

The reward for this family is massive:

  • Weight sharing: Each hidden unit is connected to a small input patch, but the same filter can be reused at all spatial locations. This is a convolution layer, and a network containing this is a CNN.
  • Since there is no need to train separate filters for each location, the number of parameters and required data amount are dramatically reduced. Data efficiency is also improved because patches at all locations contribute to learning a single distribution.

Wireless Communication Perspective: This serves the same role as the WSS (wide-sense stationarity) assumption in stochastic processes. Assuming the channel is WSS(-US), the correlation function depends only on the time difference rather than the absolute time point; therefore, observations from different time points can all be utilized in a single statistical model estimation (e.g., Doppler spectrum estimation based on the Jakes model). If stationarity is broken, statistics must be estimated separately for each time point, causing the required number of observations to skyrocket — this corresponds exactly to the situation in CNNs where position-specific filters must be trained separately.

3.5.1 Alternative: Locally connected layer — intentionally breaking stationarity

There are also locally connected layers where each location is connected only to a small patch but does not share weights. Since different filters are learned for each location, a large amount of data is required, but this can be useful in domains where images are registered. Examples: passport photos (where the positions of eyes, nose, and mouth are fixed), MRI/CT scans (where images are registered to the body shape) — because the distribution of specific locations carries location-specific meanings such as “shape of the eyes” or “shape of the liver,” breaking stationarity and applying location-specific filters captures more specialized information. However, in general non-registered images, location-specific statistics are mixed up, so it is almost always better to assume stationarity for data utilization.

3.6 Convolution layer operation

Let’s assume we apply the \(5 \times 5 \times 3\) filter to the \(32 \times 32 \times 3\) (RGB) image. We slide the filter spatially over the image and, at each position, generate a single number by the sum of element-wise products (= dot product) of the filter value and the image value. The 2D array of these output values is called the activation map (feature map) — since each value is the correlation (similarity) score between the filter and the input, it is a response map of the semantic information encoded by the filter.

Key Rules:

  • The number of channels in the filter automatically follows the number of input channels. Even if you say “\(5\times5\) filter,” if the input is 3 channels, the actual filter is \(5\times5\times3\).
  • One feature map is produced per filter. If there are \(K\) filters, the output is \(K\) channels.
  • The output value is assigned to the center pixel location of the filter. For this reason, the filter size is conventionally odd (\(3\times3, 5\times5, 7\times7\)) — if it were even, the center would fall between pixels.
  • Therefore, if the \(5\times5\) filter is applied without padding, the boundaries are cut off by 2 pixels each on the top, bottom, left, and right sides, resulting in \(32\times32 \to 28\times28\).

3.6.1 Stride

Instead of convolution at every pixel, it can be applied by skipping a few pixels (stride \(S\)). Since responses at adjacent locations are often very similar to each other, this reduces redundant information and reduces computational load. It is particularly useful for high-resolution inputs (such as 4K).

  • e.g.: \(7\times7\) input, \(3\times3\) filter, stride 2 → output \(3\times3\) (if stride 1, \(5\times5\)).
  • Example: With the same settings, stride 3 → the filter does not match all the way, so some areas are missing from the encoding. The stride must be chosen to match the input and filter sizes.

3.6.2 Padding

If you want to avoid losing boundary information (or keep the output size the same as the input), fill virtual values outside the boundary to allow the filter to perform operations beyond the boundary.

Padding Type Method Remarks
Zero padding Filled with zeros Most common. Multiplies weights by virtually zero at boundaries to prevent noise information from being injected
Repeat(replicate) padding Repeat boundary values If pixel value is 0.5, padding is also 0.5, 0.5, …
Mirror(reflect) padding Boundary-based mirror reflection […, 0.5, 1.0] If the ends are padded by 2 pixels, it reflects like […, 0.5, 1.0, 0.5, …]

(If the pixel value range is 0–255, 255 padding corresponds to a white border, and 0 padding corresponds to a black border.)

3.6.3 Output Size Formula

When input side size \(N\), filter size \(F\), stride \(S\), padding \(P\):

\[ O = \frac{N - F + 2P}{S} + 1 \]

(The last \(+1\) corresponds to the location where the first filter is applied.) Although the library calculates this automatically, you must be able to verify it manually for testing and design sense.

TipPractice Problem 1 — Output volume size

What is the output volume when input \(32\times32\times3\), filter \(5\times5\) 10 items, stride 1, padding 2?

\[ O = \frac{32 - 5 + 2\cdot 2}{1} + 1 = 32 \;\Rightarrow\; \textbf{32} \times \textbf{32} \times \textbf{10} \]

The space size is the same as the input (so-called “same” padding), and the number of channels is determined by the number of filters = 10.

TipPractice Problem 2 — Number of Parameters (Common Pitfall)

What is the number of parameters for this layer with the same settings (\(5\times5\) 10 filters, 3 input channels)?

Common incorrect answer: \(5\times5\times10 = 250\).

Correct calculation: Since the filter automatically includes the input channel, it is \(5\times5\times\mathbf{3}\), and for each filter there is 1 bias (\(wx + b\)Z’s \(b\), scalar):

\[ (5 \times 5 \times 3 + 1) \times 10 = 76 \times 10 = \textbf{760} \]

3.6.4 Efficiency compared to MLP — Quantitative comparison

When the same \(32\times32\times3\) input is received by a fully-connected layer, per neuron, \(32\times32\times3 = 3072\) weights are required. On the other hand, the convolution layer above uses 10 filters and has a total of 760. If we summarize the gain provided by this inductive bias (patch-unit encoding + weight sharing) as a chain of mechanisms:

Reduced number of parameters → Reduced degrees of freedom to fill, resulting in a reduced amount of training data (data efficiency) → Simultaneously, instead of learning “pixel–edge relationships” individually from the data, it is modularized into a patch structure → Observations from all spatial locations contribute to learning a single filter → Computational efficiency and statistical efficiency are secured simultaneously. In addition, the multi-channel output of one layer (e.g., 10 channels) becomes the input channel of the next convolution layer, so the next filter automatically takes the form \(F\times F\times 10\) — stacked hierarchically in this way.

3.7 Pooling

3.7.1 Why “pooling”?

It is called pooling because it is an operation that selects one from a pool of numbers (the verbification of the noun ‘pool’ — like bottle → bottling). The type of pooling is determined by the rule used to select one from a pool of response values obtained by applying filters at multiple locations.

Pooling Selection Rules When Is It Natural
Max pooling Maximum value When the operation is Similarity (Correlation/Inner Product) — Strongest response = Best-fit position
Min pooling minimum value when the operation is distance (e.g., Euclidean) — minimum distance = best fit position
Mean(average) pooling Average When you want to summarize the average response of the entire domain
Warningmean vs. min — Terminology Trap

Do not confuse min and mean. Min pooling is the minimum value, and mean pooling is the average.

Connecting the meaning of max pooling back to synchronization: It is an operation that, when sweeping a filter across all locations, takes only the maximum response at locations where the filter should respond and discards the noisy response occurring at locations where it should not respond. In other words, it retains only “where (how strongly) the pattern corresponding to this filter exists in the image.”

3.7.2 Why max fits “similarity” — Geometry of the inner product

Each positional operation in Convolution is the dot product of two vectors (filters, patches). The geometric meaning of the dot product is the product of the length and magnitude of the projection of one vector in the direction of another vector:

\[ \langle \mathbf{a}, \mathbf{b} \rangle = \|\mathbf{a}\|\,\|\mathbf{b}\|\cos\theta \]

If is a unit vector, the inner product \(\cos\theta\) itself — it measures how aligned the two directions are (angular distance). \(\theta \to 0\) represents the maximum (perfect alignment), while \(\theta \to 90°\) represents 0 (orthogonality = irrelevant). Therefore, in an inner product-based response, a larger value indicates a better match, so taking the maximum is correct; in a distance-based response, a smaller value indicates a better match, so the minimum should be taken. The meaning of the operation determines the selection rule for pooling. (The inner product / orthogonal projection section in Math4ML provides the cleanest rigorous derivation of projection and inner product.)

Wireless Communication Perspective: This is the same story as the two equivalent perspectives of receiver design — correlator receiver vs. minimum-distance receiver. In AWGN, ML detection is equivalent to minimizing the Euclidean distance (\(\min\)) between the received vector and the candidate signal point, and maximizing the correlation (\(\max\)) (if the two are isenergetic). Max pooling corresponds to selecting the maximum correlation branch from the correlator bank, while min pooling corresponds to selecting the nearest candidate in distance-based detection.

In addition, pooling layers have the effect of expanding the input area viewed by a single output neuron, i.e., the receptive field — as the depth increases, it summarizes a wider spatial context.

3.8 Part II Summary and Next Topic

  • Despite UAT, MLPs have severe data and parameter inefficiencies because they cannot utilize spatial structures for 2D inputs (regardless of pixel order).
  • The solution is an inductive bias consisting of patch-unit encoding + learned filters + a full position sweep, and the assumption justifying this is stationarity (the positional invariance of patch statistics).
  • The actual implementation is a cross-correlation without flipping, with an output size of \(O = (N - F + 2P)/S + 1\) and a number of parameters of \((F \cdot F \cdot C_{in} + 1) \times K\).
  • Pooling is a selection operation in a response pool, where the meaning of the operation (similarity vs. distance) determines the selection of max/min.

5 Appendix: Verification with Python

Directly check the output size formula and the number of parameters using PyTorch.

import torch
import torch.nn as nn

# ---------- 1. 출력 크기 공식 검증 ----------
def out_size(N, F, S, P):
    return (N - F + 2 * P) // S + 1

# 32x32, 5x5 filter, no padding, stride 1 -> 28
print(out_size(32, 5, 1, 0))   # 28

# 7x7, 3x3 filter, stride 2 -> 3
print(out_size(7, 3, 2, 0))    # 3

# 32x32, 5x5 filter, stride 1, pad 2 -> 32 ("same")
print(out_size(32, 5, 1, 2))   # 32

# PyTorch로 동일 설정 확인
x = torch.randn(1, 3, 32, 32)
conv = nn.Conv2d(in_channels=3, out_channels=10,
                 kernel_size=5, stride=1, padding=2)
print(conv(x).shape)           # torch.Size([1, 10, 32, 32])

# ---------- 2. 파라미터 수 검증: (5*5*3 + 1) * 10 = 760 ----------
n_params = sum(p.numel() for p in conv.parameters())
print(n_params)                # 760
print(conv.weight.shape)       # [10, 3, 5, 5]  -> 750
print(conv.bias.shape)         # [10]           -> +10

# ---------- 3. MLP와의 비교: 뉴런 1개당 가중치 ----------
fc = nn.Linear(32 * 32 * 3, 1)
print(sum(p.numel() for p in fc.parameters()))  # 3073 (3072 + bias 1)
# 뉴런 1개만으로 conv layer 전체(760)의 4배 이상

# ---------- 4. convolution = flip된 cross-correlation ----------
import torch.nn.functional as Fn
sig    = torch.tensor([1., 2., 3., 4.]).view(1, 1, -1)
kernel = torch.tensor([1., 0., -1.]).view(1, 1, -1)

xcorr = Fn.conv1d(sig, kernel, padding=2)                 # PyTorch의 "conv" = cross-correlation
conv  = Fn.conv1d(sig, kernel.flip(-1), padding=2)        # 진짜 convolution = flip 후 적용
print(xcorr)   # tensor([[[-2., -2., -2., -2.,  3.,  4.]]]) 형태
print(conv)    # flip된 결과 — 둘은 커널 반전 관계

# ---------- 5. max vs min pooling: 유사도 vs 거리 ----------
patchs  = torch.randn(8, 25)          # 8개의 5x5 patch (flatten)
template = torch.randn(25)

sim  = patchs @ template              # 내적(유사도) -> max가 best match
dist = ((patchs - template) ** 2).sum(dim=1)  # 거리 -> min이 best match
print(sim.argmax().item(), dist.argmin().item())
# SymPy로 출력 크기 공식을 기호적으로 다뤄보기
import sympy as sp
N, F, S, P = sp.symbols('N F S P', positive=True, integer=True)
O = (N - F + 2*P) / S + 1

# "same" 출력 조건: O = N, S = 1 일 때 필요한 padding
P_same = sp.solve(sp.Eq(O.subs(S, 1), N), P)[0]
print(P_same)        # (F - 1)/2  ->  F=5 이면 P=2, F=3 이면 P=1
