1 One-page summary

NoteKey line

Two fundamental challenges in sequence modeling are (1) long-term dependency and (2) context encoding. RNN families (Vanilla → LSTM/GRU → Seq2Seq) are attempts to solve these two problems using sequential and fixed weights, while Transformers are an alternative that solves the same problems better using attention that changes weights based on input.

2 What is Sequence Modeling

2.1 Direct answer

The data dealt with so far was fixed-length ‘snapshots’ — images (numbers, objects), graphs, etc. On the other hand, sequence modeling aims to learn from data of variable length. Representative example:

  • Language (Text) — Variable-length sequence of words/characters
  • Time Series (Stocks) — Values on the time axis
  • Video — Sequence of frames
  • Audio — Waveform/Spectrogram

Major applications include computer vision (image analysis, e.g., YOLO), natural language processing (text analysis, e.g., GPT), and speech recognition (e.g., voice assistants), and sequence modeling is particularly key in NLP.

TipWireless communication perspective analogy

Sequence modeling is like a receiver processing a variable-length symbol stream. Each packet has a different length, and the meaning of a single symbol depends on the preceding and succeeding symbols (channel state, preamble). Just as a memoryless detector that only sees the “current symbol” cannot demodulate a channel with ISI (inter-symbol interference), a sequence model must carry past states.

3 RNN: Sequence encoder as a dynamical system

3.1 Direct answer

RNN is a dynamic system that recursively updates the state over time. By reusing the same function \(f\) and the same parameters \(\theta\) at every time step, it compresses variable-length inputs into a fixed-size state.

3.2 Mathematical expansion

Classical form of a dynamical system without external signals:

\[ s^{(t)} = f\!\left(s^{(t-1)};\, \theta\right) \]

When external input \(x^{(t)}\) is received:

\[ s^{(t)} = f\!\left(s^{(t-1)},\, x^{(t)};\, \theta\right) \]

In this case, state \(s^{(t)}\) contains information of the entire past sequence. If we call this state the hidden state \(h^{(t)}\), then that is the RNN:

\[ \boxed{\,h^{(t)} = f\!\left(h^{(t-1)},\, x^{(t)};\, \theta\right)\,} \]

  • Input: Current data \(x^{(t)}\) and past hidden state \(h^{(t-1)}\)
  • Output: Model output at the current time point and hidden state to be passed to the next time point

The essence of a one-step RNN is revealed when contrasted with a non-recursive form:

\[ \begin{aligned} \text{비재귀:}\quad & f(x_t) = w x_t + b\\ \text{슬라이딩 윈도(이동평균):}\quad & f(x_t, x_{t-1}) = w_1 x_t + w_2 x_{t-1} + b\\ \text{한 스텝 재귀:}\quad & f(x_t, x_{t-1}) = w_1 x_t + w_2\, f(x_{t-1}, x_{t-2}) + b \end{aligned} \]

The recursive term \(f(x_{t-1},x_{t-2})\) makes this go back infinitely far into the past.

3.3 Two gains of recursive structures

NoteWhy Recursion Is Good
  1. The input size is always the same regardless of the sequence length. The trained model handles arbitrary lengths.
  2. Parameters such as the same transfer function \(f\) can be reused at every time step (parameter sharing).

3.4 Three types of RNNs

Type Structure Features
Type 1 Output at every time step + recursive connection between hidden states Most common · Highly expressive
Type 2 Output at every time step + Output → Next Hidden State connection (Teacher forcing) Easy to parallelize / No hidden state connection, so past is forgotten more easily
Type 3 Hidden state recursion + Read entire sequence and single output at the end Classification/Summary type
ImportantPrecise definition of Teacher forcing (Type 2)
  • During training: Feed the correct answer output \(y^{(t)}\) (extracted from the train set) as the input to the next step’s hidden state \(h^{(t+1)}\).
  • During inference: Since the correct answer is unknown, approximate \(o^{(t)}\) with the model output \(y^{(t)}\) and feed it back.

This is precisely where the exposure bias between the learning and inference distributions occurs. The advantage is that by breaking output dependencies, it is possible to separate learning by time point → parallelize.

4 Long-term Dependency Problem: Why RNNs Are Insufficient

4.1 Direct answer

When simple non-linear functions are combined multiple times, the resulting composite function becomes extremely non-linear. The time progression of an RNN is precisely this composition, and as a result, gradients vanish (mostly) or explode (rare but fatal), making it difficult to incorporate information from the distant past into learning.

4.2 Mathematical expansion (Eigenvalue decomposition perspective)

Let’s look at the linearly approximated RNN transition \(h^{(t)} = W^\top h^{(t-1)}\). If we perform eigenvalue decomposition \(W = Q\,\Lambda\, Q^{-1}\) on \(W\):

\[ h^{(t)} = \left(W^\top\right)^{t} h^{(0)} = Q\, \Lambda^{t}\, Q^{-1} h^{(0)} \]

Since \(\Lambda^{t} = \mathrm{diag}(\lambda_1^t, \dots, \lambda_n^t)\) here,

\[ \boxed{\;|\lambda_i| < 1 \Rightarrow \lambda_i^{t}\to 0 \ (\text{소실}), \qquad |\lambda_i| > 1 \Rightarrow \lambda_i^{t}\to \infty \ (\text{폭발})\;} \]

, that is, for time depth \(t\), the contribution is exponentially attenuated/amplified. Only the boundary at exactly \(|\lambda_i|=1\) preserves information, but it is virtually impossible to maintain this during learning.

TipWireless communication perspective analogy

This is equivalent to the cumulative channel gain in a multi-hop relay. If the gain of each hop is \(\lambda\), the signal after \(t\) is \(\lambda^t\). If \(|\lambda|<1\), the signal sinks below the noise (\(\to\) information loss), and if \(|\lambda|>1\), it clips and diverges due to non-linear amplification (\(\to\) explosion). Just as the gain is grouped near 1 using AGC (Automatic Gain Control) for stable transmission, the RNN must also control the spectral radius near 1.

4.3 Key Prescription: Gating

Let’s create a direct connection between the past and the present (or future).

The representative implementation is gating. Replace the simple product \(f(x)=a\cdot x,\ a\in[0,1]\) with the following:

\[ f(x) = a\cdot x + (1-a)\cdot m \]

where \(m\) is memory. This is an intuition similar to momentum/moving averages — it retains information for a long time by weighting the current input with past memory. Two representative implementations: LSTM (1997) and GRU (2014).

5 LSTM: Long Short-Term Memory

5.1 Direct answer

LSTM is an explicit memory cell \(c_t\) and three gates (forget, input, output) + gate gate**, which maintains long-term information by softly controlling how much of the cell contents to forget, how much to rewrite, and how much to send out.

5.2 Mathematical expansion

Combine the previous hidden state \(h_{t-1}\) and the current input \(x_t\) as input. All gates are sigmoid \(\sigma(\cdot)\in(0,1)\), and the candidate is \(\tanh\):

\[ \begin{aligned} f_t &= \sigma\!\left(W_f\,[h_{t-1}, x_t] + b_f\right) && \text{(망각 gate)}\\ i_t &= \sigma\!\left(W_i\,[h_{t-1}, x_t] + b_i\right) && \text{(입력 gate)}\\ o_t &= \sigma\!\left(W_o\,[h_{t-1}, x_t] + b_o\right) && \text{(출력 gate)}\\ g_t &= \tanh\!\left(W_g\,[h_{t-1}, x_t] + b_g\right) && \text{(gate gate / 후보 메모리)}\\[4pt] c_t &= f_t \odot c_{t-1} + i_t \odot g_t && \text{(셀 상태 갱신)}\\ h_t &= o_t \odot \tanh(c_t) && \text{(은닉상태 출력)} \end{aligned} \]

Role of each gate:

  • \(f_t\)(Forgetting): How long to retain previous cell content \(c_{t-1}\) — Throttling the cell’s self-loop connection.
  • \(i_t\)(Input): How much current information to write to the cell.
  • \(g_t\)(Gate Gate): The candidate content itself to be used in the cell.
  • \(o_t\)(Output): How much of the cell content to output/hide.
ImportantLSTM has two streams

While vanilla RNNs propagate only one hidden state \(h\) over time, LSTMs propagate two cell states \(c\) (dedicated memory) and hidden states \(h\) together. The key point is that the cell state path is updated only by multiplication by the forget gate plus the addition of the input, so it can flow along a path where the gradient is close to 1** (the Jacobian of \(c_{t-1}\to c_t\) is \(\mathrm{diag}(f_t)\)). This is the mechanism for preserving long-term information.

5.3 Geometry/Intuition

When the forget gate is close to 1, the cell state becomes a ‘conveyor belt’ where data flows almost unchanged. Since information is processed and stored via gates rather than stored as is, it retains data longer than a vanilla RNN, but still cannot retain data infinitely. (It is like eating sausage instead of raw meat—the original flavor is partially lost due to processing.)

TipWireless communication perspective analogy

The cell state \(c_t\) is a leaky integrator-based channel estimator/trace filter. The forget gate \(f_t\) is an adaptive version of RLS (Recursive Least Squares) with a forgetting factor \(\lambda\): if the channel is static, it averages for a long time with \(f_t\to1\), and if it is volatile, it discards the past quickly with \(f_t\downarrow\). The input gate corresponds to the confidence (Kalman gain) of the new observation.

6 GRU: Gated Recurrent Unit

6.1 Direct answer

GRU is a gating unit that implements almost the same idea as LSTM in a simpler way, has 3 gates (update, reset, and candidate), and has no separate cell state. It achieves equivalent performance with fewer parameters compared to LSTM.

6.2 Mathematical expansion

\[ \begin{aligned} r_t &= \sigma\!\left(W_r\,[h_{t-1}, x_t] + b_r\right) && \text{(reset gate)}\\ z_t &= \sigma\!\left(W_z\,[h_{t-1}, x_t] + b_z\right) && \text{(update gate)}\\ \tilde{h}_t &= \tanh\!\left(W_h\,[\,r_t \odot h_{t-1},\, x_t\,] + b_h\right) && \text{(후보 상태)}\\[4pt] h_t &= (1 - z_t)\odot h_{t-1} + z_t \odot \tilde{h}_t && \text{(상태 갱신)} \end{aligned} \]

  • reset gate \(r_t\): How much to reflect the previous state in the candidate calculation (reset degree).
  • update gate \(z_t\): The ratio for mixing past states and new candidates — a form combining the forget and input gates of an LSTM into one.

Note that the last diet is exactly in the form of the gating prescription \(f(x)=z\cdot(\text{새것}) + (1-z)\cdot(\text{메모리})\).

6.3 LSTM vs GRU Comparison

WarningPrecise attention to ‘parameter half’

If we count only the gate-specific weight matrices, 4 LSTMs vs 3 GRUs results in \(3/4\). The commonly cited “about 1/2” is a loose approximation that includes cell state path elimination and practical simplification, while the strict gate-weight ratio is closer to \(3/4\). Either way, the conclusion is the same: GRU achieves equivalent performance with fewer parameters.

7 Other solutions for long-term dependency

In addition to gating, there are five ideas for carrying past information far and wide.

Idea 1 — Skip connection through time. Instead of relying solely on processed cell content, add a direct connection from the past to the present. This concept shifts the spatial skip connection of Vision’s DenseNet/ResNet to the time axis, preserving memory for longer without gate effects.

Idea 2 — Leaky units. Maintain inputs that move slowly in the form of a moving average (\(W_{rec}\): recursive weights, \(W_{in}\): input weights):

\[ \mu^{(t)} = \alpha\,\mu^{(t-1)} + (1-\alpha)\,(\cdot) \]

Warning‘Leaky unit’ ≠ ‘Leaky ReLU’

Although their names are similar, they are completely different. Leaky ReLU is an activation function that allows some negative inputs to pass through. Leaky unit is a state update mechanism that slowly leaks and integrates information over time. Both their motivations and roles are different.

Idea 3 — Gating (LSTM/GRU). Covered above.

Idea 4 — Optimization Trick. - Gradient Clipping → Explosive Gradient Correspondence (Step size limiting in locally distorted loss regions). - Normalization that encourages information flow → Vanishing gradient correspondence.

Idea 5 — Explicit Memory. Like a Memory Network, it stores all past point-in-time information exactly as it is in storage, and reads it via a weighted sum when necessary, adding it to the current input. The concept is “Don’t try to remember; just hold onto everything.”

NoteModern Extension: KV Cache and Long Context

This idea leads to today’s KV caches and large input tokens (long context). The fact that modern LLMs accept tens to hundreds of K tokens as input is a strategy to avoid the difficulties of compressed memory and provide the entire history as input. Memory architecture remains an active research topic.

8 Second Difficulty: Context Encoding

8.1 Direct answer

To interpret information, one must look at the context. Since the role and meaning of even the same word change depending on the context, using fixed weights results in converting the same word into the same vector every time, making it impossible to encode different meanings.

8.2 Classic example: “Buffalo buffalo …”

Grammatically correct sentence in English:

Buffalo buffalo Buffalo buffalo buffalo buffalo Buffalo buffalo.

Here, Buffalo alternates between three roles: (1) a city name in New York State, (2) an animal ‘buffalo (American bison)’, and (3) a verb ‘to scare/to harass’. Without context, it is impossible to know whether a buffalo is a noun or a verb. The same problem applies to homonyms in Korean — the same spelling of “gamda” plays completely different roles depending on the context, such as (to close eyes) / (to wind thread) / (to wash hair).

8.3 Why can’t fixed weights be used

Deterministic functions like word2vec always assign the same word to the same vector. If you multiply that by fixed weights \(W\), the result is always the same. If so, how do we distinguish the different roles of the same word?

  • What if you use a stabilistic function? The weights change every time, but it is uncontrollable — you cannot control what meaning it will produce.
  • Solution: Change weights based on the input itself → Attention, and stack them into Transformers.
TipWireless communication perspective analogy

Fixed weight = Fixed equalizer. It is ineffective when the channel (context) changes. Attention = Adaptive equalizer: Estimates and applies tap coefficients from the received symbol (input) itself every time. This is equivalent to demodulating the same transmitted symbol differently depending on the channel state.

9 Context-Conditional RNN and Bidirectional RNN

9.1 Contextual Conditional RNN (Type 4)

Idea: Looking at past outputs improves future prediction. It performs sequential prediction using a single input as context and establishes a reverse connection from the future.

To encode the context for the sequence input, use both the backward hidden state output and the backward output as inputs for the current hidden state.

ImportantDecisive difference from Type 2 (teacher forcing)

Type 2 breaks the chain to the output connection for computational efficiency (parallelization). On the other hand, context-conditional RNNs use hidden state connections as well for better output — so they forgo parallelization (serial cascade) but carry the context better. In other words, although they look the same, their purposes are the exact opposite.

9.2 Bidirectional RNN (Type 5)

Idea: Reading twice—forward to backward and backward to forward—enhances the context of each word. Introduce a forward hidden state and another hidden state for the reverse direction. Although the number of parameters increases because dedicated weights are required for each hidden state, the context at each time point becomes richer.

10 Seq2Seq: Encoder-Decoder Model (Type 6)

10.1 Direct answer

Seq2Seq is a general-purpose sequence modeling architecture consisting of two RNNs (encoder and decoder). An encoder (Type 3) reads the entire input and summarizes it into a fixed-size context vector \(C\), and a decoder receives \(C\) to generate an output sequence.

10.2 Structure and Learning

  • Encoder (Type 3): Reads the input to the end and creates a context variable \(C\), which is a semantic summary.
  • Decoder (Type 4): Receives \(C\) and the current input and produces output at every time step. \(C\) affects all output timestamps.
Code 
flowchart LR
    x1 --> E1["인코더"] --> E2["인코더"] --> E3["인코더"] --> C(("C\n문맥벡터"))
    C --> D1["디코더"] --> y1["y₁"]
    C --> D2["디코더"] --> y2["y₂"]
    D1 --> D2 --> D3["디코더"] --> y3["y₃"]
    C --> D3

Learning: In the case of machine translation (e.g., French → English), the source text is fed into the encoder, and the loss is reduced by targeting the correct answer (gold standard) of the decoder output. The gradient of the loss is backpropagated in reverse time from decoder → context → encoder. Because the path is long, it is vulnerable to gradient vanishing and forgetting.

Inference: Since the answer is unknown, the decoder starts from the start token (<sos>) and generates one token at a time by feeding its own output back as the next input.

10.3 Application

  • QA System: Input=Question, Output=Answer
  • Conversational System (Chatbot): Input=User Utterance, Output=Response
  • Machine Translation: Input=Language A, Output=Language B
NoteInsights into Bottlenecks

Compressing the entire variable-length input into a single fixed size \(C\)** is both the elegance and the weakness of Seq2Seq. The longer the sentence, the more severe the information bottleneck \(C\) becomes — this limitation later becomes the direct motivation for attention (where the decoder directly references all hidden states of the encoder).

TipWireless communication perspective analogy

Encoder = Source encoder compressing a message into a fixed-length codeword \(C\). Decoder = A decoder that restores the message from that codeword. The dimension of \(C\) is the rate of rate-distortion, and if it is too short, it cannot contain a long sequence, so the distortion increases.

11 Deep RNN and Recursive Neural Network

11.1 Deep RNN

If \(f\) inside Seq2Seq is replaced with a multilayer MLP (or CNN/diffusion, etc.) instead of a single matrix multiplication, expressiveness increases. Deep operations placed inside recursion are called Deep RNNs.

11.2 Recursive Neural Network

As another generalization of RNN, it uses a computational graph of a tree structure instead of a chain structure.

  • Search complexity reduced to \(\tau \to \log(\tau)\) (since it is a tree).
  • Call the same architecture recursively, but expect it to perform different roles at each point/node.
  • Application: Scene parsing — Each hidden node corresponds to an object in the scene, forming a tree that decomposes and synthesizes images into semantic units.
WarningTerminology Note (Two types of RNN)

The abbreviation RNN is typically reserved for Recurrent Neural Networks (chain structure). Recursive Neural Networks (tree structure) are a generalization of this; while theoretically feasible, practical implementation is difficult because each node must learn a different role (it often fails due to capacity limitations, etc.).

12 Sequence Modeling Summary and the Bridge to Transformers

NoteSummary up to here
  • Two key challenges in sequence modeling: long-term dependency + context encoding.
  • RNN (and LSTM/GRU/Seq2Seq) are solutions that handle both, but they are not sufficient — context is difficult to distinguish due to fixed weights, cannot be parallelized because they are serial, and long-term dependencies are not complete.
  • Transformers are an alternative to RNNs that tackle the difficult problem of context encoding head-on with input-dependent dynamic weights.

13 Transformers: Transforming Weights

13.1 Direct answer

The Transformer is a Seq2Seq model that changes weights for each word and context. Even for the same word, it analyzes its neighbors (context) and transforms it into different embeddings for each situation to distinguish its role and meaning. The name ‘Transformer’ comes from the weights that change their form (transform) depending on the input.

The meaning of each word’s embedding is determined by looking at neighboring words (context). Therefore, the two buffaloes in Buffalo buffalo have different embeddings as city/bison, respectively.

14 Key Point 1: Tokens

14.1 Direct answer

A token is a vector of neurons, that is, a bundle that encapsulates information. Transformers perform operations at the token level rather than on individual neurons.

14.2 Tokenization

Split the input into chunks and project each chunk onto a vector. Performance is determined by how tokens are defined (tokenization method) — a form of input engineering.

Input Type Tokenization Method
Image Divided into patch units and vectorized (ViT)
Language Character / Syllable / Word / Byte-Pair Encoding etc.
Audio Time interval division, or waveform → spectrogram → patch
NoteEmpirical Conclusions of Language Tokenization

As a result of trying various units such as characters, syllables, BPEs, and words, there was no significant intrinsic superiority among them. Therefore, the word unit, which is the simplest and has the fewest tokens, is widely used. Non-linearity is not introduced during the tokenization stage, and that role is delegated to Transformer encoding — tokenization is simple, and non-linear encoding is handled by the Transformer.

Operations on a set of tokens consist of linear combinations of tokens + token-wise nonlinearity. (The “node attributes/feature descriptors” of GNNs are also effectively tokens.)

15 Key Point 2: Attention

15.1 Direct answer

Attention is a weighted sum method that dynamically determines weights based on the input. Unlike fixed weights, it takes the input itself as input, modifies the weights, and then applies those modified weights to the input. Therefore, even the same input can encode different roles or meanings depending on the context.

15.2 Motivation: Limitations of CNN (VQA Example)

Let’s look at VQA (Voice Question Answering) like “How many birds are in this image?” CNNs are built on the assumptions of spatial stationarity and locality, where each filter responds to the same pattern regardless of location. However:

  • Counting requires different meanings (first bird vs. second bird) at each position — max-pooling loses counts by passing only the strongest reaction to the next layer.
  • Long-distance relationships (Are the two birds at opposite ends of the image the same species?) are difficult to capture with local filters.
  • Selective focus (answer by looking only at this area) is needed, but CNNs treat all locations equally.

In other words, the locality and stationarity of CNNs are unsuitable for long-distance relationships and context-dependent processing.

Training Target \(W\) (Trained with data, fixed) Attention Function \(a(\cdot)\) — Trained with data but takes input and applies to input
Context processing Impossible Possible

15.4 Implementing with Query–Key–Value

The idea of “taking input and calculating weights” is implemented using three elements: Query \(Q\), Key \(K\), Value \(V\). (These three elements are fully integrated into the Transformer, and while it does not necessarily have to be in this form, it has become the standard.)

TipWireless communication perspective analogy

Attention is a beamforming/spatial match filter. While fixed weights are fixed beams (receiving only in a specific direction), attention estimates the channel from the received signal (input) and adapts the beam weights every time. Query = desired direction, Key = direction each antenna faces, Value = signal in that direction — greater weight is given to values with a higher degree of match (correlation) between the Query and Key. This is the same principle as a matched filter, which weights based on correlation with the signal.

16 Formula for self-attention

16.1 Direct answer

Self-attention refines the representation of each patch/token by taking into account neighbors, by weighting the values by weights determined by the query-key match.

16.2 Scaled Dot-Product Attention

Create three projections from the input token matrix \(X \in \mathbb{R}^{n\times d}\):

\[ Q = X W_Q,\qquad K = X W_K,\qquad V = X W_V \]

Attention output:

\[ \boxed{\;\mathrm{Attention}(Q,K,V) = \underbrace{\mathrm{softmax}\!\left(\frac{Q K^\top}{\sqrt{d_k}}\right)}_{A:\ \text{어텐션 행렬}\ (n\times n)} V\;} \]

  • \(QK^\top\): Similarity (Dot Product) of all token pairs — How well the query of token \(i\) and the key of token \(j\) match.
  • \(\sqrt{d_k}\) Scaling: If \(d_k\) is large, the variance of the inner product increases proportionally to \(d_k\), causing the softmax to saturate (vanishing of gradients). This is to normalize the variance to 1.
  • \(\mathrm{softmax}\): each row as a probability distribution — attention weights distributed by token \(i\) to other tokens.
  • \(A V\): Dynamic pooling (query-based) of values with those weights.

This is a “query-based dynamic pooling operation” that refines the semantic representation of a patch by considering neighboring patches. (An example is a visualization in self-supervised ViTs like DINO where related patches are highlighted together when a specific patch is labeled ‘dog’.)

16.3 Masked Attention

Sometimes you want to restrict which tokens pay attention to which tokens. Implement this by masking the attention matrix:

\[ A_{ij} = \begin{cases} \mathrm{softmax}\ \text{값} & \text{허용}\\ 0\ (\text{스코어}=-\infty) & \text{금지} \end{cases} \]

is primarily used in decoders and blocks the upper triangle (causal mask) to pay attention only to past tokens rather than future tokens. It is also utilized for optional data encoding in multimodal inputs.

16.4 Multi-Head Self-Attention (MHSA)

A single \(Q,K,V\) projection set is insufficient to encode all aspects of the data. Let’s place multiple sets of attention in parallel:

\[ \begin{aligned} \mathrm{head}_h &= \mathrm{Attention}(X W_Q^h,\, X W_K^h,\, X W_V^h)\\ \mathrm{MHSA}(X) &= \mathrm{Concat}(\mathrm{head}_1,\dots,\mathrm{head}_H)\, W_O \end{aligned} \]

Each head has its own \(Q,K,V\) function, which is executed in parallel and then combines the output token vectors. It is particularly useful for language context encoding (capturing multiple types of relationships simultaneously).

TipWireless communication perspective analogy

Multihead = Multi-spatial streams of MIMO. A single head (single beam) captures only one type of relationship, but multiple heads separate and receive signals in parallel into different subspaces. Each head observes different directions/relationships with different antenna weights (different \(Q,K,V\)) and combines them at the end.

17 Key Point 3: Positional Encoding

17.1 Direct answer

Self-attention is permutation equivariant, so it does not know the order of tokens. To inject positional information, a different code value is added to the input for each position.

17.2 Why it is necessary: Permutation equivariance

Attention \(A=\mathrm{softmax}(QK^\top/\sqrt{d_k})\) treats tokens like sets. Changing the input order simply changes the output to the same order (equivariance), but it does not distinguish the order itself. However, “Cheolsu saw Younghee” and “Younghee saw Cheolsu” are different — the order changes the meaning.

17.3 Implementation: Positional code addition

Add codes for position \(pos\) and dimension \(i\) so that patches at different locations have different inputs (sine/cosine form):

\[ \begin{aligned} PE_{(pos,\,2i)} &= \sin\!\left(\frac{pos}{10000^{\,2i/d}}\right)\\ PE_{(pos,\,2i+1)} &= \cos\!\left(\frac{pos}{10000^{\,2i/d}}\right) \end{aligned} \]

Then \(\tilde{x}_{pos} = x_{pos} + PE_{pos}\). This makes the model not permutation invariant and allows it to recognize order.

TipWireless communication perspective analogy

Positional encoding is equivalent to a position pilot created with orthogonal frequency tones. Just as OFDM distinguishes symbols using subcarriers (frequencies), different frequency components of sine and cosine assign a unique ‘fingerprint’ to each position. Thanks to the exponential frequency spectrum (\(10000^{2i/d}\)), a phase pattern is created where nearby positions are similar and far positions are distinctly different.

Assembling the three core components results in an encoder-decoder transformer. The encoder contextualizes the input, and the decoder generates the output autoretroactively (using a causal mask).

19 Application: Language Models and Autoregressive Transformers

19.1 Language Model (LM)

LM is a probabilistic model that predicts the next word given a previous word sequence (assuming a fixed-size window). On a large scale, it becomes an LLM (e.g., GPT).

\[ p(w_1,\dots,w_T) = \prod_{t=1}^{T} p\!\left(w_t \mid w_{1:t-1}\right) \]

19.2 Autoregressive Transformers and GPT

When trained using causal attention (future token masking), each position predicts the next token by looking only at the past. GPT (Generative Pretrained Transformer) is a Transformer trained with this structure. A small implementation example is minGPT (karpathy).

NoteLearning = massive teacher forcing

Autoregressive LM training performs “guessing the next token” in parallel at every position — it is parallelizing the teacher forcing of a Type 2 RNN with masked self-attention. Unlike RNNs, there is no serial dependency between time points, so it calculates all positions at once (the core advantage of Transformers).

20 The Limits of Transformers

  1. Context outside the window cannot be encoded. The context window is the limit of the field of view.
  2. Computational complexity \(O(n^2)\) — \(n\) is the window size. Due to the attention matrix of all token pairs.

\[ \text{어텐션 행렬}\ A \in \mathbb{R}^{n\times n} \ \Rightarrow\ \text{시간·메모리}\ O(n^2 d) \]

There is much research aimed at reducing this (Efficient Transformers). Computationally efficient alternatives such as Mamba (state-space model) are proposed.

TipWireless communication perspective analogy

\(O(n^2)\) Attention is equivalent to estimating the channels of every pair of nodes in a fully connected network. \(n\) As this increases, the pilot/computation overhead explodes quadratically. Efficient Transformer/Sparse Attention corresponds to estimating only meaningful links through clustering and localization.

import numpy as np
np.random.seed(3)

def softmax(x, axis=-1):
    x = x - x.max(axis=axis, keepdims=True)
    e = np.exp(x)
    return e / e.sum(axis=axis, keepdims=True)

def attention(Q, K, V, causal=False):
    d_k = Q.shape[-1]
    scores = Q @ K.T / np.sqrt(d_k)

        mask = np.tril(np.ones((n, n), dtype=bool))

    A = softmax(scores, axis=-1)
    return A @ V, A

# What is Sequence Modeling {#sec-seq-intro}

## Direct answer

The data dealt with so far was **fixed-length 'snapshots'** — images (numbers, objects), graphs, etc. On the other hand, sequence modeling aims to learn from data of **variable** length. Representative example:

- **Language (Text)** — Variable-length sequence of words/characters
- **Time Series (Stocks)** — Values on the time axis
- **Video** — Sequence of frames
- **Audio** — Waveform/Spectrogram

Major applications include computer vision (image analysis, e.g., YOLO), natural language processing (text analysis, e.g., GPT), and speech recognition (e.g., voice assistants), and sequence modeling is particularly key in NLP.

::: {.callout-tip title="Wireless communication perspective analogy"}
Sequence modeling is like a **receiver processing a variable-length symbol stream**. Each packet has a different length, and the meaning of a single symbol depends on the preceding and succeeding symbols (channel state, preamble). Just as a memoryless detector that only sees the "current symbol" cannot demodulate a channel with ISI (inter-symbol interference), a sequence model must carry past states.
:::

# RNN: Sequence encoder as a dynamical system {#sec-rnn-basic}

## Direct answer

RNN is a **dynamic system that recursively updates the state over time**. By reusing the same function $f$ and the same parameters $\theta$ at every time step, it compresses variable-length inputs into a fixed-size state.

## Mathematical expansion

Classical form of a dynamical system without external signals:

$$
s^{(t)} = f\!\left(s^{(t-1)};\, \theta\right)
$$

When external input $x^{(t)}$ is received:

$$
s^{(t)} = f\!\left(s^{(t-1)},\, x^{(t)};\, \theta\right)
$$

In this case, state $s^{(t)}$ contains **information of the entire past sequence.** If we call this state the hidden state $h^{(t)}$, then that is the RNN:

$$
\boxed{\,h^{(t)} = f\!\left(h^{(t-1)},\, x^{(t)};\, \theta\right)\,}
$$

- **Input:** Current data $x^{(t)}$ and past hidden state $h^{(t-1)}$
- **Output:** Model output at the current time point and hidden state to be passed to the next time point

The essence of a one-step RNN is revealed when contrasted with a non-recursive form:

$$
\begin{aligned}
\text{비재귀:}\quad & f(x_t) = w x_t + b\\
\text{슬라이딩 윈도(이동평균):}\quad & f(x_t, x_{t-1}) = w_1 x_t + w_2 x_{t-1} + b\\
\text{한 스텝 재귀:}\quad & f(x_t, x_{t-1}) = w_1 x_t + w_2\, f(x_{t-1}, x_{t-2}) + b
\end{aligned}
$$

The recursive term $f(x_{t-1},x_{t-2})$ makes this go back infinitely far into the past.

## Two gains of recursive structures

::: {.callout-note title="Why Recursion Is Good"}
1. **The input size is always the same regardless of the sequence length.** The trained model handles arbitrary lengths.
2. **Parameters such as the same transfer function $f$ can be reused at every time step** (parameter sharing).
:::


## Three types of RNNs {#sec-rnn-types}

| Type | Structure | Features |
|---|---|---|
| **Type 1** | Output at every time step + **recursive connection between hidden states** | Most common · Highly expressive |
| **Type 2** | Output at every time step + **Output → Next Hidden State** connection (Teacher forcing) | Easy to parallelize / No hidden state connection, so past is forgotten more easily |
| **Type 3** | Hidden state recursion + Read entire sequence and **single output at the end** | Classification/Summary type |

::: {.callout-important title="Precise definition of Teacher forcing (Type 2)"}
- **During training:** Feed the correct answer output $y^{(t)}$ (extracted from the train set) as the input to the next step's hidden state $h^{(t+1)}$.
- **During inference:** Since the correct answer is unknown, approximate $o^{(t)}$ with the model output $y^{(t)}$ and feed it back.

This is precisely where the exposure bias between the learning and inference distributions occurs. The advantage is that by breaking output dependencies, it is possible to **separate learning by time point → parallelize**.
:::

# Long-term Dependency Problem: Why RNNs Are Insufficient {#sec-longterm}

## Direct answer

When simple non-linear functions are combined multiple times, the resulting composite function becomes **extremely non-linear**. The time progression of an RNN is precisely this composition, and as a result, **gradients vanish (mostly) or explode (rare but fatal)**, making it difficult to incorporate information from the distant past into learning.

## Mathematical expansion (Eigenvalue decomposition perspective)

Let's look at the linearly approximated RNN transition $h^{(t)} = W^\top h^{(t-1)}$. If we perform eigenvalue decomposition $W = Q\,\Lambda\, Q^{-1}$ on $W$:

$$
h^{(t)} = \left(W^\top\right)^{t} h^{(0)} = Q\, \Lambda^{t}\, Q^{-1} h^{(0)}
$$

Since $\Lambda^{t} = \mathrm{diag}(\lambda_1^t, \dots, \lambda_n^t)$ here,

$$
\boxed{\;|\lambda_i| < 1 \Rightarrow \lambda_i^{t}\to 0 \ (\text{소실}), \qquad |\lambda_i| > 1 \Rightarrow \lambda_i^{t}\to \infty \ (\text{폭발})\;}
$$

, that is, for time depth $t$, the contribution is exponentially attenuated/amplified. Only the boundary at exactly $|\lambda_i|=1$ preserves information, but it is virtually impossible to maintain this during learning.

::: {.callout-tip title="Wireless communication perspective analogy"}
This is equivalent to the **cumulative channel gain in a multi-hop relay**. If the gain of each hop is $\lambda$, the signal after $t$ is $\lambda^t$. If $|\lambda|<1$, the signal sinks below the noise ($\to$ information loss), and if $|\lambda|>1$, it clips and diverges due to non-linear amplification ($\to$ explosion). Just as the gain is grouped near 1 using AGC (Automatic Gain Control) for stable transmission, the RNN must also control the spectral radius near 1.
:::

## Key Prescription: Gating

> Let's create a direct connection between the past and the present (or future).

The representative implementation is **gating**. Replace the simple product $f(x)=a\cdot x,\ a\in[0,1]$ with the following:

$$
f(x) = a\cdot x + (1-a)\cdot m
$$

where $m$ is **memory**. This is an intuition similar to momentum/moving averages — it retains information for a long time by weighting the current input with past memory. Two representative implementations: **LSTM** (1997) and **GRU** (2014).

# LSTM: Long Short-Term Memory {#sec-lstm}

## Direct answer

LSTM is an **explicit memory cell $c_t$** and three gates (forget, input, output) + gate gate**, which maintains long-term information by *softly* controlling how much of the cell contents to forget, how much to rewrite, and how much to send out.

## Mathematical expansion

Combine the previous hidden state $h_{t-1}$ and the current input $x_t$ as input. All gates are sigmoid $\sigma(\cdot)\in(0,1)$, and the candidate is $\tanh$:

$$
\begin{aligned}
f_t &= \sigma\!\left(W_f\,[h_{t-1}, x_t] + b_f\right) && \text{(망각 gate)}\\
i_t &= \sigma\!\left(W_i\,[h_{t-1}, x_t] + b_i\right) && \text{(입력 gate)}\\
o_t &= \sigma\!\left(W_o\,[h_{t-1}, x_t] + b_o\right) && \text{(출력 gate)}\\
g_t &= \tanh\!\left(W_g\,[h_{t-1}, x_t] + b_g\right) && \text{(gate gate / 후보 메모리)}\\[4pt]
c_t &= f_t \odot c_{t-1} + i_t \odot g_t && \text{(셀 상태 갱신)}\\
h_t &= o_t \odot \tanh(c_t) && \text{(은닉상태 출력)}
\end{aligned}
$$

Role of each gate:

- $f_t$(**Forgetting**): How long to retain previous cell content $c_{t-1}$ — Throttling the cell's self-loop connection.
- $i_t$(**Input**): How much current information to write to the cell.
- $g_t$(**Gate Gate**): The candidate content itself to be used in the cell.
- $o_t$(**Output**): How much of the cell content to output/hide.

::: {.callout-important title="LSTM has two streams"}
While vanilla RNNs propagate **only** one hidden state $h$ over time, LSTMs propagate **two** cell states $c$ (dedicated memory) and **hidden states $h$ together. The key point is that the cell state path is updated only by multiplication by the forget gate plus the addition of the input, so **it can flow along a path where the gradient is close to 1** (the Jacobian of $c_{t-1}\to c_t$ is $\mathrm{diag}(f_t)$). This is the mechanism for preserving long-term information.
:::

## Geometry/Intuition

When the forget gate is close to 1, the cell state becomes a **'conveyor belt'** where data flows almost unchanged. Since information is processed and stored via gates rather than stored as is, it retains data longer than a vanilla RNN, but **still cannot retain data infinitely.** (It is like eating sausage instead of raw meat—the original flavor is partially lost due to processing.)

::: {.callout-tip title="Wireless communication perspective analogy"}
The cell state $c_t$ is a **leaky integrator-based channel estimator/trace filter**. The forget gate $f_t$ is an adaptive version of RLS (Recursive Least Squares) with a forgetting factor $\lambda$: if the channel is static, it averages for a long time with $f_t\to1$, and if it is volatile, it discards the past quickly with $f_t\downarrow$. The input gate corresponds to the confidence (Kalman gain) of the new observation.
:::

# GRU: Gated Recurrent Unit {#sec-gru}

## Direct answer

GRU is a gating unit that implements **almost the same idea as LSTM in a simpler way**, has 3 gates (update, reset, and candidate), and **has no separate cell state.** It achieves equivalent performance with fewer parameters compared to LSTM.

## Mathematical expansion

$$
\begin{aligned}
r_t &= \sigma\!\left(W_r\,[h_{t-1}, x_t] + b_r\right) && \text{(reset gate)}\\
z_t &= \sigma\!\left(W_z\,[h_{t-1}, x_t] + b_z\right) && \text{(update gate)}\\
\tilde{h}_t &= \tanh\!\left(W_h\,[\,r_t \odot h_{t-1},\, x_t\,] + b_h\right) && \text{(후보 상태)}\\[4pt]
h_t &= (1 - z_t)\odot h_{t-1} + z_t \odot \tilde{h}_t && \text{(상태 갱신)}
\end{aligned}
$$

- **reset gate $r_t$**: How much to reflect the previous state in the candidate calculation (reset degree).
- **update gate $z_t$**: The ratio for mixing past states and new candidates — a form combining the forget and input gates of an LSTM into one.

Note that the last diet is exactly in the form of the gating prescription $f(x)=z\cdot(\text{새것}) + (1-z)\cdot(\text{메모리})$.

## LSTM vs GRU Comparison

| Item | LSTM | GRU |
|---|---|---|
| Number of gates | 4 (forget, input, output, gate) | 3 (reset, update, candidate) |
| Memory Path | Cell State $c$ + Hidden $h$ (2) | Hidden $h$ (1) |
| Year of Proposal | 1997 | 2014 |
| Parameter | Standard | Less |
| Performance | Standard | Equivalent (on par) |
| Utility | — | Overfitting risk ↓, Training data and computational costs ↓ |

::: {.callout-warning title="Precise attention to 'parameter half'"}
If we count only the gate-specific weight matrices, 4 LSTMs vs 3 GRUs results in **$3/4$**. The commonly cited "about 1/2" is a **loose approximation** that includes cell state path elimination and practical simplification, while the strict gate-weight ratio is closer to $3/4$. Either way, the conclusion is the same: GRU achieves equivalent performance with fewer parameters.
:::

# Other solutions for long-term dependency {#sec-other-longterm}

In addition to gating, there are five ideas for carrying past information far and wide.

**Idea 1 — Skip connection through time.** 
Instead of relying solely on processed cell content, add a **direct connection** from the past to the present. This concept shifts the spatial skip connection of Vision's DenseNet/ResNet to the time axis, preserving memory for longer without gate effects.

**Idea 2 — Leaky units.** 
Maintain inputs that move slowly in the form of a moving average ($W_{rec}$: recursive weights, $W_{in}$: input weights):

$$
\mu^{(t)} = \alpha\,\mu^{(t-1)} + (1-\alpha)\,(\cdot)
$$

::: {.callout-warning title="'Leaky unit' ≠ 'Leaky ReLU'"}
Although their names are similar, they are completely different. **Leaky ReLU** is an *activation function* that allows some negative inputs to pass through. **Leaky unit** is a *state update* mechanism that slowly leaks and integrates information over time. Both their motivations and roles are different.
:::

**Idea 3 — Gating (LSTM/GRU).** Covered above.

**Idea 4 — Optimization Trick.**
- **Gradient Clipping** → Explosive Gradient Correspondence (Step size limiting in locally distorted loss regions).
- **Normalization that encourages information flow** → Vanishing gradient correspondence.

**Idea 5 — Explicit Memory.** 
Like a Memory Network, it **stores all past point-in-time information exactly as it is** in storage, and reads it via a weighted sum when necessary, adding it to the current input. The concept is "Don't try to remember; just hold onto everything."

::: {.callout-note title="Modern Extension: KV Cache and Long Context"}
This idea leads to today's **KV caches** and **large input tokens (long context)**. The fact that modern LLMs accept tens to hundreds of K tokens as input is a strategy to avoid the difficulties of compressed memory and **provide the entire history as input**. Memory architecture remains an active research topic.
:::

# Second Difficulty: Context Encoding {#sec-context}

## Direct answer

To interpret information, one must look at the **context**. Since the role and meaning of even the same word change depending on the context, using **fixed weights** results in converting the same word into the same vector every time, making it impossible to encode different meanings.

## Classic example: "Buffalo buffalo …"

Grammatically correct sentence in English:

> Buffalo buffalo Buffalo buffalo buffalo buffalo Buffalo buffalo.

Here, `Buffalo` alternates between three roles: (1) a city name in New York State, (2) an animal ‘buffalo (American bison)’, and (3) a verb ‘to scare/to harass’. Without context, it is impossible to know whether a `buffalo` is a noun or a verb. The same problem applies to homonyms in Korean — the same spelling of “gamda” plays completely different roles depending on the context, such as (to **close** eyes) / (to **wind** thread) / (to **wash** hair).

## Why can't fixed weights be used

Deterministic functions like word2vec always assign the same word to the same vector. If you multiply that by **fixed weights $W$**, the result is always the same. If so, how do we distinguish the *different roles* of the same word?

- What if you use a **stabilistic function**? The weights change every time, but it is **uncontrollable** — you cannot control what meaning it will produce.
- **Solution:** Change weights based on the input itself → **Attention**, and stack them into **Transformers**.

::: {.callout-tip title="Wireless communication perspective analogy"}
Fixed weight = **Fixed equalizer**. It is ineffective when the channel (context) changes. Attention = **Adaptive equalizer**: Estimates and applies tap coefficients from the received symbol (input) itself every time. This is equivalent to demodulating the same transmitted symbol differently depending on the channel state.
:::

# Context-Conditional RNN and Bidirectional RNN {#sec-context-rnn}

## Contextual Conditional RNN (Type 4)

**Idea:** Looking at past outputs improves future prediction. It performs sequential prediction using a single input as context and establishes a **reverse connection from the future**.

To encode the context for the sequence input, use both the **backward hidden state output** and the **backward output** as inputs for the current hidden state.

::: {.callout-important title="Decisive difference from Type 2 (teacher forcing)"}
Type 2 breaks the chain to the output connection for **computational efficiency (parallelization)**. On the other hand, context-conditional RNNs use *hidden state connections as well* for **better output** — so they forgo parallelization (serial cascade) but carry the context better. In other words, although they look the same, their *purposes* are the exact opposite.
:::

## Bidirectional RNN (Type 5)

**Idea:** Reading twice—forward to backward and backward to forward—enhances the context of each word. Introduce a forward hidden state and **another hidden state for the reverse direction**. Although the number of parameters increases because dedicated weights are required for each hidden state, the context at each time point becomes richer.

```{mermaid}
flowchart LR
    subgraph fwd["정방향"]
      f1["→h₁"] --> f2["→h₂"] --> f3["→h₃"]
    end
    subgraph bwd["역방향"]
      b3["←h₃"] --> b2["←h₂"] --> b1["←h₁"]
    end
    f1 & b1 --> y1["y₁"]
    f2 & b2 --> y2["y₂"]
    f3 & b3 --> y3["y₃"]
```

# Seq2Seq: Encoder-Decoder Model (Type 6) {#sec-seq2seq}

## Direct answer

Seq2Seq is a general-purpose sequence modeling architecture consisting of **two RNNs (encoder and decoder)**. An encoder (Type 3) reads the entire input and summarizes it into a **fixed-size context vector $C$**, and a decoder receives $C$ to generate an output sequence.

## Structure and Learning

- **Encoder (Type 3):** Reads the input to the end and creates a context variable $C$, which is a semantic summary.
- **Decoder (Type 4):** Receives $C$ and the current input and produces output at every time step. $C$ **affects all output timestamps**.

```{mermaid}
flowchart LR
    x1 --> E1["인코더"] --> E2["인코더"] --> E3["인코더"] --> C(("C\n문맥벡터"))
    C --> D1["디코더"] --> y1["y₁"]
    C --> D2["디코더"] --> y2["y₂"]
    D1 --> D2 --> D3["디코더"] --> y3["y₃"]
    C --> D3
```

**Learning:** In the case of machine translation (e.g., French → English), the source text is fed into the encoder, and the loss is reduced by targeting the correct answer (gold standard) of the decoder output. The gradient of the loss is backpropagated in reverse time from **decoder → context → encoder**. Because the path is long, it is vulnerable to gradient vanishing and forgetting.

**Inference:** Since the answer is unknown, the decoder starts from the start token (`<sos>`) and generates one token at a time by feeding its own output back as the next input.

## Application

- **QA System:** Input=Question, Output=Answer
- **Conversational System (Chatbot):** Input=User Utterance, Output=Response
- **Machine Translation:** Input=Language A, Output=Language B

::: {.callout-note title="Insights into Bottlenecks"}
Compressing the entire variable-length input into a single fixed size $C$** is both the elegance and the weakness of Seq2Seq. The longer the sentence, the more severe the information bottleneck $C$ becomes — this limitation later becomes the direct motivation for attention (where the decoder directly references *all* hidden states of the encoder).
:::

::: {.callout-tip title="Wireless communication perspective analogy"}
Encoder = **Source encoder** compressing a message into a fixed-length codeword $C$. Decoder = A decoder that restores the message from that codeword. The dimension of $C$ is the rate of **rate-distortion**, and if it is too short, it cannot contain a long sequence, so the distortion increases.
:::

# Deep RNN and Recursive Neural Network {#sec-deep-recursive}

## Deep RNN

If $f$ inside Seq2Seq is replaced with a **multilayer MLP** (or CNN/diffusion, etc.) instead of a single matrix multiplication, expressiveness increases. Deep operations placed inside recursion are called Deep RNNs.

## Recursive Neural Network

As another generalization of RNN, it uses a computational graph of a **tree structure** instead of a chain structure.

- Search complexity reduced to $\tau \to \log(\tau)$ (since it is a tree).
- Call the same architecture **recursively**, but expect it to perform *different roles* at each point/node.
- Application: **Scene parsing** — Each hidden node corresponds to an object in the scene, forming a tree that decomposes and synthesizes images into semantic units.

::: {.callout-warning title="Terminology Note (Two types of RNN)"}
The abbreviation **RNN** is typically reserved for **Recurrent** Neural Networks (chain structure). **Recursive** Neural Networks (tree structure) are a generalization of this; while theoretically feasible, practical implementation is difficult because each node must learn a different role (it often fails due to capacity limitations, etc.).
:::

# Sequence Modeling Summary and the Bridge to Transformers {#sec-bridge}

::: {.callout-note title="Summary up to here"}
- **Two key challenges in sequence modeling: long-term dependency + context encoding.**
- RNN (and LSTM/GRU/Seq2Seq) are solutions that handle both, but they are **not sufficient** — context is difficult to distinguish due to fixed weights, cannot be parallelized because they are serial, and long-term dependencies are not complete.
- **Transformers** are an alternative to RNNs that tackle the difficult problem of context encoding head-on with *input-dependent dynamic weights*.
:::

# Transformers: Transforming Weights {#sec-transformer-intro}

## Direct answer

The Transformer is a **Seq2Seq model that changes weights for each word and context**. Even for the same word, it analyzes its neighbors (context) and transforms it into *different* embeddings for each situation to distinguish its role and meaning. The name 'Transformer' comes from the weights that change their form (transform) depending on the input.

The meaning of each word's embedding is determined by looking at **neighboring words (context)**. Therefore, the two buffaloes in `Buffalo buffalo` have different embeddings as city/bison, respectively.

## Three Key Ideas

# Key Point 1: Tokens {#sec-tokens}

## Direct answer

A token is a **vector of neurons**, that is, a bundle that encapsulates information. Transformers perform operations at the **token level** rather than on individual neurons.

## Tokenization

Split the input into chunks and project each chunk onto a vector. Performance is determined by how tokens are defined (tokenization method) — a form of input engineering.

| Input Type | Tokenization Method |
|---|---|
| Image | Divided into **patch** units and vectorized (ViT) |
| Language | Character / Syllable / Word / Byte-Pair Encoding etc. |
| Audio | Time interval division, or waveform → spectrogram → patch |

::: {.callout-note title="Empirical Conclusions of Language Tokenization"}
As a result of trying various units such as characters, syllables, BPEs, and words, **there was no significant intrinsic superiority among them.** Therefore, the **word unit**, which is the simplest and has the fewest tokens, is widely used. Non-linearity is not introduced during the tokenization stage, and that role is delegated to Transformer encoding — tokenization is simple, and non-linear encoding is handled by the Transformer.
:::

Operations on a set of tokens consist of **linear combinations of tokens** + **token-wise nonlinearity**. (The "node attributes/feature descriptors" of GNNs are also effectively tokens.)

---

# Key Point 2: Attention {#sec-attention}

## Direct answer

Attention is a **weighted sum method that dynamically determines weights based on the input**. Unlike fixed weights, it takes the input itself as input, modifies the weights, and then applies those modified weights to the input. Therefore, even the same input can encode different roles or meanings depending on the context.

## Motivation: Limitations of CNN (VQA Example)

Let's look at **VQA (Voice Question Answering)** like "How many birds are in this image?" CNNs are built on the assumptions of **spatial stationarity and locality**, where each filter responds to the same pattern regardless of location. However:

- **Counting** requires *different* meanings (first bird vs. second bird) at each position — max-pooling loses counts by passing only the strongest reaction to the next layer.
- **Long-distance relationships** (Are the two birds at opposite ends of the image the same species?) are difficult to capture with local filters.
- **Selective focus** (answer by looking only at this area) is needed, but CNNs treat all locations equally.

In other words, the locality and stationarity of CNNs are unsuitable for long-distance relationships and context-dependent processing.

## Fixed Weights vs. Self-Attention

| | Fixed weights | (Self) Attention |
|---|---|---|
| Weight | **Fixed** regardless of input | **Varies depending on input** (Trigger = Input) |
| Training Target | $W$ (Trained with data, fixed) | Attention Function $a(\cdot)$ — Trained with data but **takes input and applies to input** |
| Context processing | Impossible | Possible |

## Implementing with Query–Key–Value

The idea of "taking input and calculating weights" is implemented using three elements: **Query $Q$, Key $K$, Value $V$**. (These three elements are fully integrated into the Transformer, and while it does not necessarily have to be in this form, it has become the standard.)

::: {.callout-tip title="Wireless communication perspective analogy"}
Attention is a **beamforming/spatial match filter**. While fixed weights are fixed beams (receiving only in a specific direction), attention **estimates the channel from the received signal (input) and adapts the beam weights every time**. Query = desired direction, Key = direction each antenna faces, Value = signal in that direction — greater weight is given to values with a higher degree of match (correlation) between the Query and Key. This is the same principle as a matched filter, which weights based on correlation with the signal.
:::

# Formula for self-attention {#sec-self-attention}

## Direct answer

Self-attention refines the representation of each patch/token by taking into account *neighbors*, by **weighting the values by weights determined by the query-key match**.

## Scaled Dot-Product Attention

Create three projections from the input token matrix $X \in \mathbb{R}^{n\times d}$:

$$
Q = X W_Q,\qquad K = X W_K,\qquad V = X W_V
$$

Attention output:

$$
\boxed{\;\mathrm{Attention}(Q,K,V) = \underbrace{\mathrm{softmax}\!\left(\frac{Q K^\top}{\sqrt{d_k}}\right)}_{A:\ \text{어텐션 행렬}\ (n\times n)} V\;}
$$

- $QK^\top$: **Similarity (Dot Product)** of all token pairs — How well the query of token $i$ and the key of token $j$ match.
- $\sqrt{d_k}$ **Scaling**: If $d_k$ is large, the variance of the inner product increases proportionally to $d_k$, causing the softmax to saturate (vanishing of gradients). This is to normalize the variance to 1.
- $\mathrm{softmax}$: each row as a probability distribution — attention weights distributed by token $i$ to other tokens.
- $A V$: **Dynamic pooling (query-based)** of values with those weights.

This is a "query-based dynamic pooling operation" that **refines the semantic representation of a patch by considering neighboring patches**. (An example is a visualization in self-supervised ViTs like DINO where related patches are highlighted together when a specific patch is labeled 'dog'.)

## Masked Attention

Sometimes you want to **restrict** which tokens pay attention to which tokens. Implement this by **masking** the attention matrix:

$$
A_{ij} =
\begin{cases}
\mathrm{softmax}\ \text{값} & \text{허용}\\
0\ (\text{스코어}=-\infty) & \text{금지}
\end{cases}
$$

is primarily used in **decoders** and blocks the upper triangle (causal mask) to **pay attention only to past tokens rather than future tokens**. It is also utilized for optional data encoding in multimodal inputs.

## Multi-Head Self-Attention (MHSA)

A single $Q,K,V$ projection set is insufficient to encode all aspects of the data. Let's **place multiple sets of attention in parallel**:

$$
\begin{aligned}
\mathrm{head}_h &= \mathrm{Attention}(X W_Q^h,\, X W_K^h,\, X W_V^h)\\
\mathrm{MHSA}(X) &= \mathrm{Concat}(\mathrm{head}_1,\dots,\mathrm{head}_H)\, W_O
\end{aligned}
$$

Each head has its own $Q,K,V$ function, which is executed in parallel and then combines the output token vectors. It is particularly useful for language context encoding (capturing multiple types of relationships simultaneously).

::: {.callout-tip title="Wireless communication perspective analogy"}
Multihead = **Multi-spatial streams of MIMO**. A single head (single beam) captures only one type of relationship, but multiple heads separate and receive signals in parallel into different subspaces. Each head observes different directions/relationships with different antenna weights (different $Q,K,V$) and combines them at the end.
:::

# Key Point 3: Positional Encoding {#sec-positional}

## Direct answer

Self-attention is **permutation equivariant**, so it does not know the order of tokens. To inject positional information, **a different code value is added to the input for each position.**

## Why it is necessary: Permutation equivariance

Attention $A=\mathrm{softmax}(QK^\top/\sqrt{d_k})$ treats tokens like sets. Changing the input order simply changes the output to the same order (equivariance), but it does not distinguish the order itself. However, "Cheolsu saw Younghee" and "Younghee saw Cheolsu" are different — the order changes the meaning.

## Implementation: Positional code addition

Add codes for position $pos$ and dimension $i$ so that patches at different locations have different inputs (sine/cosine form):

$$
\begin{aligned}
PE_{(pos,\,2i)} &= \sin\!\left(\frac{pos}{10000^{\,2i/d}}\right)\\
PE_{(pos,\,2i+1)} &= \cos\!\left(\frac{pos}{10000^{\,2i/d}}\right)
\end{aligned}
$$

Then $\tilde{x}_{pos} = x_{pos} + PE_{pos}$. This makes the model **not permutation invariant** and allows it to recognize order.

::: {.callout-tip title="Wireless communication perspective analogy"}
Positional encoding is equivalent to a **position pilot** created with orthogonal frequency tones. Just as OFDM distinguishes symbols using subcarriers (frequencies), different frequency components of sine and cosine assign a unique 'fingerprint' to each position. Thanks to the exponential frequency spectrum ($10000^{2i/d}$), a phase pattern is created where nearby positions are similar and far positions are distinctly different.
:::

# Transformer entire architecture {#sec-transformer-arch}

Assembling the three core components results in an encoder-decoder transformer. The encoder contextualizes the input, and the decoder generates the output autoretroactively (using a causal mask).

```{mermaid}
flowchart TB
    subgraph ENC["인코더 (×N)"]
      ie["입력 임베딩 + PE"] --> mha["Multi-Head Self-Attention"]
      mha --> an1["Add & Norm"]
      an1 --> ff1["FeedForward"]
      ff1 --> an2["Add & Norm"]
    end
    subgraph DEC["디코더 (×N)"]
      oe["출력 임베딩 + PE"] --> mmha["Masked Multi-Head Attention"]
      mmha --> an3["Add & Norm"]
      an3 --> cross["Cross-Attention (Q=디코더, K,V=인코더)"]
      cross --> an4["Add & Norm"]
      an4 --> ff2["FeedForward"]
      ff2 --> an5["Add & Norm"]
    end
    an2 -. "K, V" .-> cross
    an5 --> lin["Linear + Softmax"] --> out["출력 확률"]
```

- **Add & Norm:** Preserve gradient flow with residual linking (skip) + Stabilize with LayerNorm.
- **Cross-Attention:** The decoder query pays attention to the encoder output (key·value) — Generalized from the context vector $C$ of Seq2Seq to *dynamic references to all encoder positions*.

# Application: Language Models and Autoregressive Transformers {#sec-application}

## Language Model (LM)

LM is a **probabilistic model that predicts the next word given a previous word sequence** (assuming a fixed-size window). On a large scale, it becomes an **LLM** (e.g., GPT).

$$
p(w_1,\dots,w_T) = \prod_{t=1}^{T} p\!\left(w_t \mid w_{1:t-1}\right)
$$

## Autoregressive Transformers and GPT

When trained using **causal attention** (future token masking), each position predicts the next token by looking only at the past. **GPT (Generative Pretrained Transformer)** is a Transformer trained with this structure. A small implementation example is `minGPT` (karpathy).

::: {.callout-note title="Learning = massive teacher forcing"}
Autoregressive LM training performs "guessing the next token" in parallel at every position — it is *parallelizing* the teacher forcing of a Type 2 RNN with masked self-attention. Unlike RNNs, there is no serial dependency between time points, so it calculates all positions at once (the core advantage of Transformers).
:::

---

# The Limits of Transformers {#sec-limitations}

1. **Context outside the window cannot be encoded.** The context window is the limit of the field of view.
2. **Computational complexity $O(n^2)$** — $n$ is the window size. Due to the attention matrix of all token pairs.

$$
\text{어텐션 행렬}\ A \in \mathbb{R}^{n\times n} \ \Rightarrow\ \text{시간·메모리}\ O(n^2 d)
$$

There is much research aimed at reducing this (Efficient Transformers). Computationally efficient alternatives such as **Mamba** (state-space model) are proposed.

::: {.callout-tip title="Wireless communication perspective analogy"}
$O(n^2)$ Attention is equivalent to **estimating the channels of every pair of nodes in a fully connected network**. $n$ As this increases, the pilot/computation overhead explodes quadratically. Efficient Transformer/Sparse Attention corresponds to **estimating only meaningful links through clustering and localization**.
:::

# Full Summary {#sec-summary}

::: {.callout-note title="Conclusion of this note"}
- **Two major challenges in sequence modeling:** Long-term dependency, context encoding.
- **RNN Lineage:** Vanilla → (Gating) LSTM/GRU → (Skip/Leak/Optimization/Explicit Memory) → (Bidirectional/Context-Conditional) → Seq2Seq. Inherent limitations of serial and fixed weights.
- **The three cores of Transformers:** Tokens, attention, and positional encoding. Explicitly handles context with *input-dependent dynamic weights* and also achieves parallelism.
- **Applications:** GPT (Autoregressive LM), ViT (Image Patch Token).
- **Limitations and Alternatives:** $O(n^2)$ Complexity and Window Limitations → Efficient Transformer, Mamba, etc.
:::

## B. LSTM cell forward

```{python}
import numpy as np
np.random.seed(1)
sigmoid = lambda x: 1.0 / (1.0 + np.exp(-x))

def lstm_step(x, h, c, P):
    z = np.concatenate([h, x])
    f = sigmoid(P['Wf'] @ z + P['bf'])   # 망각
    i = sigmoid(P['Wi'] @ z + P['bi'])   # 입력
    o = sigmoid(P['Wo'] @ z + P['bo'])   # 출력
    g = np.tanh (P['Wg'] @ z + P['bg'])  # gate gate
    c = f * c + i * g                    # 셀 상태
    h = o * np.tanh(c)                   # 은닉상태
    return h, c

H, X = 3, 2
mk = lambda a, b: np.random.randn(a, b) * 0.1
P = {k: mk(H, H + X) for k in ['Wf', 'Wi', 'Wo', 'Wg']}
P.update({k: np.zeros(H) for k in ['bf', 'bi', 'bo', 'bg']})

h, c = np.zeros(H), np.zeros(H)
for t in range(5):
    h, c = lstm_step(np.random.randn(X), h, c, P)
```

## C. GRU cell forward + parameter count comparison

```{python}
import numpy as np
np.random.seed(2)
sigmoid = lambda x: 1.0 / (1.0 + np.exp(-x))

def gru_step(x, h, P):

    r = sigmoid(P['Wr'] @ z_in + P['br'])         # reset
```

## D. Scaled Dot-Product Attention (+ causal mask)

```{python}
import numpy as np
np.random.seed(3)

def softmax(x, axis=-1):
    x = x - x.max(axis=axis, keepdims=True)
    e = np.exp(x)
    return e / e.sum(axis=axis, keepdims=True)

def attention(Q, K, V, causal=False):
    d_k = Q.shape[-1]
    scores = Q @ K.T / np.sqrt(d_k)
    if causal:
        n = Q.shape[0]
        mask = np.tril(np.ones((n, n), dtype=bool))
        scores = np.where(mask, scores, -1e9)
    A = softmax(scores, axis=-1)
    return A @ V, A

n, d = 4, 8
Q, K, V = (np.random.randn(n, d) for _ in range(3))

out, A = attention(Q, K, V)
```

## E. Sine/Cosine Positional Encoding

```{python}
import numpy as np

def positional_encoding(L, d):
    pos = np.arange(L)[:, None]
    i = np.arange(d)[None, :]
    angle = pos / np.power(10000.0, (2 * (i // 2)) / d)
    pe = np.zeros((L, d))
    pe[:, 0::2] = np.sin(angle[:, 0::2])
    pe[:, 1::2] = np.cos(angle[:, 1::2])
    return pe

pe = positional_encoding(50, 16)
print("PE shape =", pe.shape, "| 값 범위 =", round(pe.min(), 2), "~", round(pe.max(), 2))
# 서로 다른 위치는 서로 다른 코드를 가짐 (행벡터가 모두 구별됨)
print("위치 0 vs 1 코드가 다른가 :", not np.allclose(pe[0], pe[1]))
```
