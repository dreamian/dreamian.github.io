Machine Learning Basics — Part I

Capacity · Bias–Variance · VC Dimension · Inductive Bias · MLE · MAP

Published

1 Learning Objectives

This summarizes the statistical inference and generalization theories essential for a deep understanding of deep learning. There are two main pillars.

  1. Theory of Generalization — capacity, bias–variance tradeoff, VC dimension, inductive bias, Occam’s razor, No Free Lunch.
  2. Parameter Estimation — Maximum Likelihood Estimation (MLE), Maximum a Posteriori (MAP), and the Bayesian perspective connecting them.
NoteOne-line summary

A “good model” is not a model that fits training data well, but a model that works well on unseen data (test). Almost every concept in this note is a variation of this single sentence.

Intuition for Wireless Communications Majors: The estimation theory in this note corresponds one-to-one with detection/estimation theory in receiver design. MLE ↔︎ ML detection, MAP ↔︎ MAP detection, prior ↔︎ a priori symbol probability or channel statistics, bias–variance ↔︎ estimator MSE decomposition. 2 Capacity, Overfitting, and Bias–Variance Tradeoff

2.1 Three errors: training / true / test

Let’s consider the linear basis model \(f(\mathbf{x};\mathbf{w}) = \sum_i w_i h_i(\mathbf{x})\). If we use squared error (L2) in regression, the training error is

\[ \mathrm{error}_{\text{train}}(\mathbf{w}) \;=\; \frac{1}{N_{\text{train}}}\sum_{j=1}^{N_{\text{train}}}\Big(t(\mathbf{x}_j) - \sum_i w_i h_i(\mathbf{x}_j)\Big)^2 . \]

What we obtain through learning is the parameter that minimizes this training error.

\[ \mathbf{w}^{*} = \arg\min_{\mathbf{w}} \sum_j \Big(t(\mathbf{x}_j) - \sum_i w_i h_i(\mathbf{x}_j)\Big)^2 . \]

However, what we really care about is the true error (prediction error) for all possible inputs.

\[ \mathrm{error}_{\text{true}}(\mathbf{w}) \;=\; \mathbb{E}_{(\mathbf{x},t)\sim p}\Big[\big(t(\mathbf{x}) - f(\mathbf{x};\mathbf{w})\big)^2\Big] \;=\; \int \big(t(\mathbf{x}) - f(\mathbf{x};\mathbf{w})\big)^2 \, p(\mathbf{x})\, d\mathbf{x}. \]

The integral is generally uncalculable. This is because \(t(\mathbf{x})\) is unknown for all \(\mathbf{x}\), and the input distribution \(p(\mathbf{x})\) is also unknown. Therefore, we approximate with Monte Carlo using the iid sample \(\{\mathbf{x}_1,\dots,\mathbf{x}_M\}\sim p(\mathbf{x})\).

\[ \mathrm{error}_{\text{true}}(\mathbf{w}) \;\approx\; \frac{1}{M}\sum_{m=1}^{M}\big(t(\mathbf{x}_m) - f(\mathbf{x}_m;\mathbf{w})\big)^2 . \]

2.2 Why does training error underestimate true error?

The equation for the training error and the equation for the true error approximated by Monte Carlo are almost identical in form. Nevertheless, the reason why the training error is a poor estimate of the true error is key.

ImportantOptimistically biased estimate
  • For a single fixed \(\mathbf{w}\), the training error is the unbiased estimate of the true error.
  • However, we optimized \(\mathbf{w}\) for that very training set. In other words, we selected \(\mathbf{w}^{*}\), which best fits that sample.
  • Therefore, the training error measured with the same data is optimistically biased. It is as if the model “took the test with the correct answer already seen.”

The solution is to separate the data into a training set and a test set. By obtaining \(\mathbf{w}^{*}\) as the training set and measuring the error on the test set, which has never been used for optimization, we obtain an unbiased estimate of the generalization error.

Error Estimator Characteristics Application
Ground truth (true error) Ideal standard (uncalculable) The value we truly want
Training error Optimistically biased Learning objective function
Test error Final measurement (unbiased) Reported value of generalization performance

2.3 Bias–Variance Tradeoff

The act of selecting a hypothesis class itself introduces learning bias.

  • More complex classes → Reduced bias: With more functions to represent, we can get closer to the true function.
  • More complex classes → Increased variance: The solution fluctuates significantly even with small variations (noise) in the data.

As model complexity increases, training error decreases monotonically, but true/test error follows a U-shaped curve. The left side represents underfitting (high bias), the right side represents overfitting (high variance), and the valley represents optimal complexity.

TipFormal definition of overfitting

Given a data distribution \(D(X,Y)\) and a hypothesis space \(H\), if the hypothesis \(h\in H\) has a \(h'\in H\) satisfying the following, then \(h\) overfits. \[ \mathrm{error}_{\text{train}}(h) < \mathrm{error}_{\text{train}}(h') \quad\text{이면서}\quad \mathrm{error}_{\text{true}}(h) > \mathrm{error}_{\text{true}}(h'). \] In other words, it means that there exists another hypothesis that is better in training but worse in true.

NoteBenign overfitting (recent phenomenon)

From a traditional bias–variance perspective, performance should deteriorate if the number of parameters is excessive. However, severely overparameterized deep neural networks achieve near-optimal generalization error on unseen data while perfectly interpolating noisy data (zero training error). This is called benign overfitting and challenges the traditional tradeoff. Contrasting concepts include tempered overfitting and catastrophic (traditional) overfitting.

Wireless communication support

Tip📡 Bias–Variance ↔︎ Estimator MSE Decomposition

The mean squared error of the estimator \(\hat\theta\) follows exactly the same decomposition. \[ \mathrm{MSE}(\hat\theta) = \underbrace{\big(\mathbb{E}[\hat\theta]-\theta\big)^2}_{\text{bias}^2} + \underbrace{\mathrm{Var}(\hat\theta)}_{\text{variance}}. \]

  • LS Channel Estimator vs. MMSE Channel Estimator: LS is unbiased but has high variance. MMSE reduces variance by intentionally introducing bias using channel statistics as a prior — the same principle as regularization to lower model complexity.
  • Diagonal loading of MVDR beamforming: The variance of covariance estimation explodes when there are few snapshots. Diagonal loading \(\hat{\mathbf{R}}+\epsilon\mathbf{I}\) is a normalization that suppresses variance at the expense of bias.
  • Select AR/Channel Tap Order: Increasing the number of taps (model order) improves training fit but models noise as well, leading to overfitting. Selecting order = selecting capacity.

3 Quantification of Capacity: VC Dimension

Capacity is “how many different functions a model can fit.” A method to control this is the selection of the hypothesis space (e.g., first-order polynomial = linear, second-order polynomial = quadratic curve), and the quantification metric is the Vapnik–Chervonenkis (VC) dimension.

3.1 Definition: shattering

The VC dimension \(h\) of classifier \(f\) is the maximum number of points that \(f\) can shatter. Here, “shatter” means that \(f\) can realize all possible binary label assignments for those points without error. In other words, \(h\) = the maximum number of training points that can be classified accurately.

  • 2D Plane Linear Classifier: \(h = 3\) (All 8 ± assignments are possible for any 3 points at any position, but generally 4 points are not possible).

3.2 Generalization boundary (Vapnik, 1971)

Assumption: All training/test samples are drawn from the same distribution as iid. Then with probability \(1-\eta\)

\[ \underbrace{\mathrm{TESTERR}}_{\text{일반화 오차}} \;\le\; \mathrm{TRAINERR} \;+\; \sqrt{\dfrac{h\big(\log(2R/h)+1\big) - \log(\eta/4)}{R}}, \]

Here, \(h\) is the VC dimension, and \(R\) is the number of training samples. The second term is the capacity penalty, which increases when \(h\) is large (complex model) and decreases when \(R\) is large (large amount of data). This is the mathematical basis for the intuition that the more data there is, the safer one can use complex models.

Classifier VC dimension
\(d\) Dimensional Linear Classifier (+ Constant Term \(b\)) \(d+1\)
Neural Network \(\approx\) Number of Parameters
1-nearest neighbor \(\infty\)

The fact that the VC dimension of a 1-NN is infinite means that it can memorize any label assignment with always 0 training error — a typical overfitting machine.

Wireless communication support

Tip📡 VC bound ↔︎ Model order selection / Sample complexity

The \(R\) (sample size) of the generalization boundary plays the same role as the number of training symbols in channel estimation. In massive MIMO, as the channel dimension \(h\) to be estimated increases, the number of training symbols \(R\) required for the same performance increases proportionally — this is the curse of dimensionality and sample complexity.

4 Inductive Bias and Generalization

To better predict the future (test) with a limited training sample, the model must be regularized by adding assumptions. This assumption is the inductive bias and is introduced in the form of a regularizer.

4.1 Representative inductive bias

Principle Content Applications
Maximum conditional independence Assuming maximum conditional independence Naïve Bayes
Minimum cross-validation error Select Minimum CV Error Hypothesis Select General Model
Maximum margin Maximizing decision boundary margin SVM
Minimum description length Prefer shorter description (Occam) Decision tree
Minimum features Remove useless features Feature selection
Nearest neighbor Neighbor majority labeling k-NN

4.2 Occam’s Razor

“Pluralitas non est ponenda sine necessitate” — Do not complicate things unnecessarily.

  • Argument for favoring short hypotheses: Short hypotheses have a low probability of fitting the data by chance (long hypotheses have a high chance of fitting by chance).
  • Counterargument: It is merely an assumption that the hypothesis space is small; there is nothing inherently special about the length of the hypothesis itself.

4.3 No Free Lunch Theorem

ImportantSummary (Wolpert & Macready, 1997)

If you average over all possible data generation distributions, all classification algorithms have the same error rate when classifying unseen points. \(\Rightarrow\) Generally, there is no machine learning algorithm that is superior to all other algorithms.

Therefore, we must design algorithms to operate well on specific tasks. Since the most suitable model varies for each task, we design and build a model tailored to it whenever we encounter a new task.

NoteDoes the Foundation model violate the NFL?

The trend of reusing a single massive foundation model across multiple tasks may seem like a contradiction to the NFL, but it is not. To use a foundation model effectively for a specific task, it must also undergo a process called fine-tuning (or sophisticated modifications) to regulate and adapt it to that task. The NFL is a mathematically proven theorem, and in practice, foundation models are practically effective because “their mean” differs from the distributions we encounter.

5 Hyperparameters and Verification

5.1 Parameter vs Hyperparameter

  • Parameter: Value learned from data (e.g., weight \(\mathbf{w}\), coin example \(p\)). training = parameter tuning.
  • Hyperparameter: Controls the model/training with values specified by a user. Examples: Regularization coefficient \(\lambda\), learning rate, number of layers, layer width (plane/space size), etc.

Key Question: How do you choose hyperparameters? Since the goal is to generalize as much as possible to the model on unseen data, you must select them by evaluating them on data that was not used for training.

5.2 Held-out(validation/development) data

Separate data not used during training is set aside (held-out) and used to sneak peek at the model’s generalization performance during training. There are several names for the same data.

Name Emphasis
Held-out set The point that it was set aside from training
Validation set The point that generalization validates
Development set The point of viewing the model while developing
WarningDisadvantages of Held-out

This data is not used for training. When data is expensive and scarce, setting aside a portion for validation is a waste of valuable resources.

5.3 k-fold Cross-Validation

Cross-validation is a technique that verifies without explicit held-outs to mitigate waste issues.

  1. Divide the training data into \(k\) subsets (folds). Example: \(\{1,2,3,4,5\}\).
  2. Round 1: Train with fold \(\{2,3,4,5\}\) and validate with fold \(\{1\}\) → Evaluate one hyperparameter candidate.
  3. Round 2: Train with fold \(\{1,3,4,5\}\) and validate with fold \(\{2\}\) → Another candidate.
  4. Rotate so that every fold becomes a validation set once.
  5. The hyperparameter is determined by combining the \(k\) results using majority voting/average.

This way, all data is used for training while maintaining the benefits of held-out validation.

Wireless communication support

Tip📡 Validation ↔︎ Pilot/Data Symbols, CV ↔︎ Resource Reuse

The channel is estimated (=trained) using the frame’s pilot symbols, and performance is evaluated using data symbols. As pilots become more expensive (overhead), a trade-off identical to the “wasting data on validation” problem arises. The fold rotation in CV is analogous to the idea of maximizing the recycling of limited pilot resources.

6 Maximum Likelihood Estimation (MLE)

6.1 What is Likelihood

Likelihood is the amount of “how well your theoretical model fits the observations (data).” We want to adjust the model’s parameters so that the model fits the observations as closely as possible (this adjustment is learning).

Regression Intuition: When fitting a linear model to data points, if we define the goodness of fit between the data and the model probabilistically and maximize it, the shape of the model becomes as similar as possible to the shape of the data. “Measuring the amount of fit by probability” is the essence of likelihood.

6.2 Coin Toss Example

There is a biased coin. \(p\) = the probability of getting heads. It was tossed \(n\) times and got heads \(k\) times. Intuitively, it is \(\hat p = k/n\), but justifying this mathematically is MLE.

Modeling: Assume each throw is iid and treat it as Bernoulli/binomial.

\[ P(\text{Head}) = p,\qquad P(\text{Tail}) = 1-p,\qquad \text{flips are i.i.d.} \]

The probability (=likelihood) of the sequence \(\mathcal{D}\), observed as heads \(\alpha_H=k\) and tails \(\alpha_T=n-k\), is

\[ P(\mathcal{D}\mid p) \;=\; \binom{n}{\alpha_H}\, p^{\alpha_H}(1-p)^{\alpha_T}. \]

NoteLikelihood vs Posterior — Pay attention to the direction of the condition
  • Likelihood \(P(\mathcal{D}\mid p)\): Assuming a model (parameters), how well that model explains the data. A partial plot of “Model → Data”.
  • Posterior \(P(p\mid \mathcal{D})\): Give data and view the entire distribution of parameters. It is a complete picture of the entire parameter space, from which data can also be generated → generative perspective.

If the direction of the condition variable changes, the meaning changes completely. MLE maximizes likelihood, while MAP/Bayesian maximizes posterior.

6.3 Why log-likelihood?

Maximize log-likelihood instead of ||| likelihood.

\[ \ell(p) \;=\; \log P(\mathcal{D}\mid p) \;=\; \alpha_H\log p + \alpha_T\log(1-p) + \text{const}. \]

There are three reasons.

  1. Argmax Invariant: \(\log\) is a monotonically increasing function. Composing monotonically increasing functions does not change the locations of the extrema. Therefore, \(\arg\max_p P(\mathcal{D}\mid p) = \arg\max_p \ell(p)\). (Although the magnitudes of the values change, the optimal \(p\) remains the same.)
  2. Product → Sum: If iid, the likelihood is product, but if we take \(\log\), it becomes sum. Addition is computationally cheaper and more stable than multiplication.
  3. Underflow/Overflow Prevention: The product of small probabilities results in a very small number that exceeds the computer’s floating-point range (underflow). \(\log\) provides numerical stability by “saturating” such values into a manageable range.

\(p\to 0\) has the side effect of \(\log p \to -\infty\), but in realistic estimation, cases where the probability becomes exactly 0 are rare, so it is not a big problem.

6.4 MLE Solution Derivation

Since the objective function is concave (in this example) for \(p\), we set the first derivative to 0 to find the maximum.

\[ \frac{d\ell}{dp} = \frac{\alpha_H}{p} - \frac{\alpha_T}{1-p} = 0 \;\Longrightarrow\; (1-p)\,\alpha_H = p\,\alpha_T \;\Longrightarrow\; \boxed{\;\hat p_{\text{MLE}} = \frac{\alpha_H}{\alpha_H + \alpha_T} = \frac{k}{n}\;} \]

The intuitive guess \(k/n\) is derived. (This is also a common interview question.)

ImportantIn reality, there are almost no closed suns

This coin example is a rare case where a closed-form solution exists. In reality, 99% of the time the objective function is neither convex nor concave, so it cannot be solved simply by setting the derivative to zero. Therefore, an approximate optimal solution is found using gradient descent.

6.5 Conditional Log-Likelihood (Generalized form of supervised learning)

Most supervised learning models the probability \(y\) of the label \(P(y\mid x;\theta)\) given the input \(x\). If the sample is iid

\[ \theta^{*} = \arg\max_\theta \prod_{i=1}^{N} P(y_i\mid x_i;\theta) = \arg\max_\theta \sum_{i=1}^{N} \log P(y_i\mid x_i;\theta). \]

NoteSemicolon notation \(P(y\mid x;\theta)\)

\(\theta\) is both a condition and a model parameter. To highlight this duality, a semicolon is sometimes used instead of a comma: \(P(y\mid x;\theta)\). The meaning is the same.

6.5.1 Why model \(p(y\mid x)\) instead of \(p(x)\)

This is because the label space \(y\) is much simpler semantically than the input space \(x\).

  • Example: One 4K image ≈ \(3840\times2160\times3 \approx 2.4\times10^7\) pixels. Video is 60–120 frames per second. The dimensions of the input space \(x\) are astronomical.
  • On the other hand, \(y\) is a concept of prime numbers like “cat/dog”. Solving \(P(y\mid x)\) is much easier to handle (discriminative).

Conversely, if \(p(x)\) itself (the complete distribution of the input) is modeled, images, video, and audio can be generated → generative model. (This is the branch leading to generative models in subsequent lectures.)

Wireless communication support

Tip📡 MLE ↔︎ ML detection, log-likelihood sum ↔︎ MRC
  • ML Symbol Detection: \(\hat{s}_{\text{ML}}=\arg\max_s p(\mathbf{y}\mid s)\). Maximizing only the likelihood under the implicit prior that symbols have equal probability — this is exactly MLE.
  • Product → Sum = Diversity Combination: The combination likelihood of independent receiving branches \(L\) is a product, and taking the logarithm gives a sum. Maximizing this sum of log-likelihoods in AWGN is structured the same as the decision statistics of MRC (maximal-ratio combining).
  • Discriminative vs Generative: A detector that only makes decisions \(p(s\mid \mathbf{y})\) (discriminative), while modeling the entire distribution of the received signal \(p(\mathbf{y})\) corresponds to generative modeling of channel interference.

7 Bayesian Learning and MAP

7.1 Motivation: Let’s use prior knowledge

Let’s assume we have prior knowledge that the coin is approximately “50–50”. MLE is risky when observations are scarce. If we toss the coin 10 times and get heads 3 times, MLE says \(\hat p=0.3\), but we know this is inaccurate. The more limited the observations, the more we want to stabilize the estimate using already known knowledge.

Don’t be hooked solely on observation; weigh what I believe against what I see to make better decisions — this is the philosophy of MAP/Bayesian.

7.2 Bayes’ Theorem

Instead of a single \(p\) value, obtain the entire distribution for \(p\).

\[ \underbrace{P(p\mid\mathcal{D})}_{\text{Posterior}} = \frac{\overbrace{P(\mathcal{D}\mid p)}^{\text{Likelihood}}\,\overbrace{P(p)}^{\text{Prior}}}{\underbrace{P(\mathcal{D})}_{\text{Evidence (normalization)}}}, \qquad P(\mathcal{D}) = \int P(\mathcal{D}\mid p)\,P(p)\,dp . \]

  • Likelihood \(P(\mathcal{D}\mid p)\): Usually easily obtained (reads data probabilities from PDF when model parameters are provided).
  • Prior \(P(p)\): Expert knowledge. Often easy to obtain.
  • Evidence \(P(\mathcal{D})\): Integration over the entire data space/Monte Carlo is required, so it is very difficult. (e.g., how do you calculate the “probability of dog image data”?)

7.3 MAP avoids Evidence

Fortunately, all we want is \(\hat p\) which maximizes the posterior. Since the evidence \(P(\mathcal{D})\) is not a function of \(p\) but merely a constant, it cancels out of \(\arg\max\).

\[ \hat p_{\text{MAP}} = \arg\max_p P(p\mid\mathcal{D}) = \arg\max_p P(\mathcal{D}\mid p)\,P(p). \]

ImportantCase where MAP reduces to MLE

If there is no prior (=unknown), set the prior to uniform. Since the uniform distribution is a constant, it does not affect \(\arg\max\). \[ P(p)=\text{const}\;\Longrightarrow\; \arg\max_p P(\mathcal{D}\mid p)P(p) = \arg\max_p P(\mathcal{D}\mid p). \] In other words, MLE is a special case of a “MAP that assumes uniform priors.” (It is more accurate to say that MLE assumes uniform priors, rather than ignoring them.)

7.4 Conjugate Prior and Beta Distribution

To obtain a posterior in a closed form, one must choose the prior carefully. A conjugate prior is a prior that makes the posterior belong to the same distribution family as the prior.

  • Advantage: Algebraic convenience — The posterior comes out in a closed form.
  • Educational Advantage: Clearly demonstrates how likelihood updates the prior (the distribution family remains the same, only the parameters change).

The conjugate prior of binomial likelihood is the Beta distribution (Beta belongs to the exponential family).

\[ P(p) = \frac{p^{\beta_H-1}(1-p)^{\beta_T-1}}{B(\beta_H,\beta_T)} \sim \mathrm{Beta}(\beta_H,\beta_T). \]

Shape Intuition: \(\mathrm{Beta}(1,1)\) is a uniform distribution, \(\mathrm{Beta}(2,2)\)·\(\mathrm{Beta}(3,2)\) have peaks, and \(\mathrm{Beta}(30,20)\) looks like a skewed Gaussian with a narrow, pointed shape.

7.5 Posterior and MAP Estimators

When the Beta prior is multiplied by the binomial likelihood, the exponents are added so that the posterior becomes Beta again (conjugation).

\[ P(p\mid\mathcal{D}) = \frac{p^{\alpha_H+\beta_H-1}(1-p)^{\alpha_T+\beta_T-1}}{B(\beta_H+\alpha_H,\ \beta_T+\alpha_T)} \sim \mathrm{Beta}(\beta_H+\alpha_H,\ \beta_T+\alpha_T). \]

Maximizing this posterior (the same differentiation trick as before) yields the MAP estimator.

\[ \boxed{\;\hat p_{\text{MAP}} = \arg\max_p P(p\mid\mathcal{D}) = \frac{\alpha_H+\beta_H-1}{\alpha_H+\beta_H+\alpha_T+\beta_T-2}\;} \]

TipPrior = “Imaginary additional observation”

When comparing the MAP equation with the MLE equation \(\frac{\alpha_H}{\alpha_H+\alpha_T}\), the prior \(\beta_H,\beta_T\) acts like a fictitious number of throws (extra/pseudo tosses) held through experience, which were not actually thrown. In other words, the prior adds “experience from a previous life” to the observation.

  • Data explosion(\(N\to\infty\)): \(\alpha_H,\alpha_T \gg \beta_H,\beta_T\) becomes prior is forgotten → MAP \(\to\) MLE.
  • Small Sample: For example, if there are 10 observations vs. 1,000 prior observations, the prior dominates the estimation → stable estimation.
NoteConnection with large-scale learning

When observations are virtually infinite (e.g., large models learning with billions of tokens), we forget about priors and rely on the data. Conversely, in early stages with limited data and small-scale problems, relying on priors is necessary for stability. The principle of “use data when data is sufficient, and prior knowledge when data is scarce” forms the philosophical basis of modern large-scale learning.

Wireless communication support

Tip📡 MAP ↔︎ MAP detection, Beta pseudo-count ↔︎ Bayesian channel estimation
  • MAP Symbol Detection: \(\hat{s}_{\text{MAP}}=\arg\max_s p(\mathbf{y}\mid s)\,P(s)\). The a-priori probability of the symbol \(P(s)\) is the prior. If the symbol has equal probability, \(P(s)\) becomes a constant, so MAP = ML — Exactly the same structure as “uniform prior → MAP = MLE” in the text.
  • Prior ↔︎ Channel Statistics: MMSE/Bayesian channel estimation obtains stable estimates with a small number of pilots by using the channel’s prior statistics \(\mathbf{R}_h\) as a prior. Just as the pseudo-count of Beta is a “virtual observation,” MMSE attracts estimates using the prior covariance as a “virtual measurement.”
  • Small Sample ↔︎ Few Snapshots: The fewer the pilot/snapshots, the greater the weight of the prior (channel statistics); the more there are, the more the measurement data dominates — equivalent to the prior being forgotten in \(N\to\infty\).

8.2 Conclusion at a Glance

  1. The Bias-variance tradeoff is a central concept in understanding generalization.
  2. Inductive bias (especially Occam’s razor) is a common tool for preventing overfitting.
  3. VC dimension is a quantitative measure of classifier capacity and explains the relationship between data volume and model complexity as a generalization boundary.
  4. No Free Lunch: There is no universally best algorithm — design for the task.
  5. Hyperparameters must be tuned (via cross-validation, etc.).
  6. MLE is a widely used estimation tool, and MAP is a generalization more widely used in practice that provides better estimates with the help of priors.

9 Appendix: Coin Example Numerical Experiment

Directly check how MLE and MAP differ in small samples and how priors are “forgotten”.

In small samples, the MAP is pulled toward the prior (\(p\approx0.5\)) and is stable, and as \(N\) increases, both MLE and MAP converge to the true value and the difference between the two disappears (=prior is forgotten). This is the numerical representation of “If \(N\to\infty\), the prior is forgotten” in the text Section 7.5.
