비스킷 분배

algorithm
digit-dp
bitmask
x명에게 동일한 맛의 합 y를 나눠줄 수 있는 서로 다른 y의 개수를 구하는 문제. 핵심은 feasibility의 특성화를 통한 MSB→LSB digit DP + 다중 상한선 동시 관리다.
Published

May 18, 2026

1 문제 이해

지현이에게 \(N\) 종류의 비스킷이 있다. \(i\)번 종류 (\(0 \le i \le N-1\)) 비스킷은 맛이 \(2^i\)이고 개수가 \(A_i\)개다. 모든 비스킷의 맛의 합은 \(10^{18}\)을 넘지 않는다.

\(x\)명에게 비스킷을 나눠줄 때 각자 받는 맛의 합이 \(y\)로 동일해야 한다. 비스킷을 아예 안 줘도 되고, 남겨도 된다. 가능한 서로 다른 \(y\)의 개수를 세어라.

제약: - \(1 \le N \le 60\), \(1 \le x \le 10^{18}\) - \(0 \le A_i\), \(\sum A_i \cdot 2^i \le 10^{18}\) - 최대 1002개의 테스트 케이스

2 핵심 관찰: Feasibility 특성화

\(y\)가 feasible하다 \(\iff\) \(x\)명 각자가 비스킷들의 부분집합으로 정확히 \(y\)를 만들 수 있는 분배가 존재한다.

이것이 언제 성립하는지를 비트별로 정리하면 깔끔한 조건을 얻을 수 있다.

2.1 누적 합 \(S_i\)

\[S_i = \sum_{j=0}^{i} A_j \cdot 2^j\]

\(S_i\)는 레벨 \(i\) 이하 비스킷만으로 만들 수 있는 최대 맛의 합이다.

2.2 핵심 부등식

각 사람 \(p\)가 받은 비스킷의 맛을 비트별로 분해하면, 레벨 \(i\) 이하 비스킷의 기여만으로도 \(y \bmod 2^{i+1}\)를 만족시켜야 한다. 이를 \(x\)명 합산하면:

\[x \cdot (y \bmod 2^{i+1}) \leq S_i\]

따라서:

\[y \text{ feasible} \iff \forall i \in \{0, \ldots, N-1\}: \; y \bmod 2^{i+1} \leq \underbrace{\left\lfloor \frac{S_i}{x} \right\rfloor}_{\text{Limit}[i]}\]

Note

왜 하위 비트는 하위 레벨 비스킷에서 오는가?

레벨 \(i+1\) 이상의 비스킷 한 개의 맛은 \(2^{i+1}\) 이상이므로, \(y \bmod 2^{i+1}\)에 기여하지 않는다. 따라서 \(y\)의 하위 \(i+1\) 비트는 오로지 레벨 \(i\) 이하 비스킷들의 기여로만 결정된다.

3 풀이: MSB → LSB Digit DP

조건은 결국 “y의 여러 비트 prefix가 각각 상한을 넘으면 안 된다”는 것이다. 이를 \(y\)의 비트를 큰 자리(MSB)부터 작은 자리(LSB)로 결정하는 digit DP로 해결한다.

3.1 Tight/Loose 개념

\(y \leq U\)를 보장하는 표준 digit DP에서, 비트를 결정하면서 두 상태를 추적한다.

  • Tight: 지금까지 결정한 \(y\)의 비트가 \(U\)의 같은 위치 비트와 정확히 일치 → 다음 비트도 신중히 결정해야 한다.
  • Loose: 이미 \(y < U\)가 확정됨 → 이후 비트는 자유롭게 선택 가능.

한 번 loose가 되면 \(U\)를 절대 넘지 않으므로 영구적으로 자유 상태가 된다.

3.2 다중 상한선 → mask

이 문제는 상한이 \(N\)개다. 각 상한 \(\text{Limit}[c]\)마다 독립적으로 tight/loose 여부를 추적해야 한다. \(N\)개의 boolean을 비트마스크 하나로 압축한다.

\[\text{mask의 비트 } c = 1 \iff \text{조건 } c \text{가 아직 tight 상태}\]

Tip

mask는 y의 비트 위치가 아니다. mask의 \(c\)번째 비트는 조건 \(c\) (Limit[\(c\)])가 아직 tight한가를 나타낸다.

3.3 조건 활성화 타이밍

조건 \(c\)는 \(y \bmod 2^{c+1} \leq \text{Limit}[c]\)이며, 이는 \(y\)의 비트 \(c\) 이하에만 관여한다. 따라서 비트 \(c\)를 처리하는 시점에 처음으로 활성화한다.

비트 59 처리 시:  조건 N-1만 활성 (최종 상한, 처음부터 active)
비트 i  처리 시:  조건 i 새로 등장 (valid_cond[i]가 참인 경우)

3.4 Vacuous 조건 가지치기

\(y \bmod 2^{i+1}\)은 자연히 \(\{0, 1, \ldots, 2^{i+1}-1\}\) 범위이므로, \(\text{Limit}[i] \geq 2^{i+1}\)이면 조건이 항상 자동 만족된다(vacuous). 이런 조건은 mask에 추가하지 않아 상태 공간을 줄인다.

\[\text{valid\_cond}[i] \iff \text{Limit}[i] < 2^{i+1}\]

마지막 조건 \(i = N-1\)은 \(y\)의 절대 상한이므로 vacuous 검사 없이 무조건 활성화한다.

3.5 DP 정의 및 전이

\[\text{solve}(i, \text{mask}) = \text{"비트 } i \text{ 이상은 확정됨. 비트 } i \text{부터 0까지를 mask의 tight 조건들을 지키면서 채울 수 있는 경우의 수"}\]

종료 조건:

\[\text{solve}(-1, \text{mask}) = 1 \quad \text{(모든 비트 결정 완료 → y 하나 확정)}\]

비트 \(i\)에서의 전이 (\(\text{val} \in \{0, 1\}\)):

활성 조건 \(c\)마다 \(\text{Limit}[c]\)의 \(i\)번째 비트를 \(\text{req\_bit}\)라 할 때:

비교 의미 처리
\(\text{val} > \text{req\_bit}\) 상한 초과 이 \(\text{val}\) 선택 불가
\(\text{val} = \text{req\_bit}\) 여전히 tight \(\text{new\_mask}\)에 \(c\) 추가
\(\text{val} < \text{req\_bit}\) loose 전환 \(\text{new\_mask}\)에서 \(c\) 제거

new_mask는 0에서 시작해서 tight 유지 조건만 켜므로, 아무것도 안 하면 자동으로 mask에서 빠진다.

Important

메모이제이션이 필요한 이유

다른 상위 비트 경로도 같은 tight 조건 집합에 도달할 수 있다. 예를 들어 조건 \(c_2\)가 “일찍 loose”된 경로와 “늦게 loose”된 경로가 동일한 \((\text{idx}, \text{mask})\) 상태에 도달하면, 이후의 경우의 수는 같으므로 재계산이 불필요하다.

4 예제 손 추적

\(N=2\), \(x=2\), \(A=[3,1]\):

  • \(S_0 = 3\), \(\text{Limit}[0] = 1 = 01_2\)
  • \(S_1 = 5\), \(\text{Limit}[1] = 2 = 10_2\)
solve(1, mask={1})            (비트 1, 조건 1만 active)
├─ val=0:  Limit[1] 비트1=1,  0 < 1 → loose  →  solve(0, {})
│    └─ 조건 0 등장, val=0,1 모두 OK  →  solve(-1) + solve(-1) = 2  (y=0, y=1)
└─ val=1:  1 = 1 → tight      →  solve(0, {1})
     └─ 조건 0 등장, next_mask={0,1}
          ├─ val=0: 조건0 loose, 조건1 tight (Limit[1] 비트0=0, 0=0)  →  1  (y=2)
          └─ val=1: 조건1 위반 (1>0)  →  0
     = 1

총합: 2 + 1 = 3  ✓  (y = 0, 1, 2)

5 구현 세부사항

비트 범위: \(y \leq S_{N-1}/x \leq 10^{18}/1 = 10^{18} < 2^{60}\)이므로 비트 59부터 처리한다.

128비트 주의: \(S_i = \sum A_j \cdot 2^j\)는 \(A_j\)가 크면 중간 계산에서 unsigned long long을 넘을 수 있다. 단, 문제에서 \(\sum A_i \cdot 2^i \leq 10^{18}\)을 보장하므로 최종 \(S_i\) 값 자체는 64비트 안에 들어온다.

dp 초기화: 테스트 케이스가 여러 개이므로 매 케이스마다 dp[0..59]를 전부 클리어해야 한다.

6 코드

#include <stdio.h>
#include <unordered_map>

using ull = unsigned long long int;
int n;
ull x, a[60], ub[60];
std::unordered_map<ull, ull> dp[60];

ull solve(int idx, ull mask)
{
    if (idx < 0) return 1;
    if (dp[idx].find(mask) != dp[idx].end()) return dp[idx][mask];
    ull& ans = dp[idx][mask] = 0;

    ull constraints = mask;
    if (idx < n) {
        if (ub[idx] < (1ULL << (idx + 1))) {
            constraints |= (1ULL << idx);
        }
    }

    for (int val = 0; val <= 1; ++val) {
        bool is_valid = true;
        ull new_mask = 0x00;

        for (int c = 0; c < n; ++c) {
            if ((constraints >> c) & 1) {
                int req_bit = ((ub[c] >> idx) & 1);
                if (val > req_bit) {
                    is_valid = false;
                    break;
                }
                if (val == req_bit) {
                    new_mask |= (1LL << c);
                }
            }
        }
        if (is_valid) {
            ans += solve(idx - 1, new_mask);
        }
    }

    return ans;
}

int main(void)
{
    int t;
    scanf("%d", &t);
    while (t--) {
        ull s = 0;
        scanf("%d %llu", &n, &x);
        for (int i = 0; i < 60; ++i) dp[i].clear();
        for (int i = 0; i < n; ++i) {
            scanf("%llu", &a[i]);
            s += a[i] << i;
            ub[i] = s / x;
        }

        printf("%llu\n", solve(59, (1ULL << n - 1)));
    }
}
