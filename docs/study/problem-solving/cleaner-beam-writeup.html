2026년 8월 27일

1 문제 정의와 채점기 모델

청소부가 \(100\times100\) 격자 위의 집들을 청소한다. 각 집에는 재료 \(m\in\{1,\dots,6\}\)가 있고, 그 집을 청소하면 가격 \(P_m\)을 얻는다. 하루는 720분이며, nextDay()를 최대 30번 호출할 수 있어 총 31개의 근무일 구간을 쓴다. 핵심은 위치가 날을 넘겨 이어진다는 점이다 — 오늘 끝난 자리에서 내일이 시작한다.

한 번의 move(y,x) 호출은 다음 순서로 처리된다.

  • 이동: 맨해튼 거리만큼 시간 소모. 그 결과 \(>720\)이면 SCORE=0(그날까지 누적 점수 몰수).
  • 청소: 목표 칸이 집이면 \(c_m = 30m+30\)분 소모. 역시 \(>720\)이면 SCORE=0.
  • 보상: \(P_m\) 획득. 그리고 종료 시각이 480분을 넘겼다면 초과근무 보너스 \(200\times(\text{종료}-\max(480,\text{시작}))\)를 추가로 얻는다(이동 시간까지 보너스에 포함).

가격과 청소시간, 그리고 청소 1분당 가치는 다음과 같다.

\(m\) \(c_m\)(청소분) \(P_m\) \(P_m/c_m\)
1 60 80,000 1,333
2 90 140,000 1,556
3 120 180,000 1,500
4 150 240,000 1,600
5 180 250,000 1,389
6 210 300,000 1,429
노트채점 구조의 함정

SCORE는 10개 테스트케이스에 걸쳐 누적되며, 한 번이라도 \(>720\)을 만들면 그때까지의 누적이 0으로 리셋된다. 따라서 “빈 칸으로 이동해 시간을 낭비하는” 포지셔닝 이동은 순전한 위험이다. 우리 접근은 오직 집으로만 이동해 desync·리셋을 원천 차단한다.

2 정식화 — 시간종속 이익을 갖는 주기적 Orienteering Problem

이 문제는 사실 Orienteering Problem(OP) — “예산 안에서 방문할 노드의 부분집합과 순서를 정해 수집 점수를 최대화” — 의 변형이다. 방문 집합 \(S\)와 순서 \(\pi=(\pi_1,\dots,\pi_K)\), 그리고 하루 경계 지시자 \(z_k\in\{0,1\}\)(\(z_k=1\)이면 \(\pi_{k-1}\) 다음 날이 바뀜)를 결정변수로 둔다.

\(k\)번째 청소의 시작 \(a_k\)·종료 \(b_k\) 시각은 채점기 시계를 그대로 옮긴 재귀로 정의된다(이동은 날이 바뀌어도 이전 위치에서 출발한다).

\[ a_1=0,\quad b_1=d(0,\pi_1)+c_{\pi_1},\qquad a_k=(1-z_k)\,b_{k-1},\quad b_k=a_k+d(\pi_{k-1},\pi_k)+c_{\pi_k} \]

제약과 목적함수는 다음과 같다. \((\cdot)^+=\max(0,\cdot)\).

\[ b_k\le 720\ (\forall k),\qquad \sum_{k\ge2} z_k \le 30, \] \[ \boxed{\ \max_{S,\pi,z}\ \Phi=\sum_{k=1}^{K}\Big[P_{\pi_k}+200\big((b_k-480)^+-(a_k-480)^+\big)\Big]\ } \]

\(\rho=0\)(초과근무 제거) + 하루 분할 무시 → 고전 OP. 여기에 하루 분할(각 \(\le720\))과 위치 carryover, 시간종속 이익(초과근무) 이 얹힌 형태다.

중요정식화가 준 결정적 통찰

목적함수가 하루별 기여의 합이며, 하루끼리의 유일한 결합은 시작 위치 carryover 뿐이다. 이 가법성이 뒤에서 문제를 분해하는 근거가 된다.

3 1차 접근과 정체 — 그리고 잘못된 천장 결론

처음에는 전역 tour 하나를 만들고 하루로 잘라 담는 틀에서 여러 방법을 시도했다.

  • value-density greedy: 현재 위치에서 \(P_m/(\text{이동}+c_m)\)가 최대인 집을 탐욕적으로 선택 → 319.5M.
  • GRASP(무작위화 재시작), or-opt / 2-opt(국소 탐색), LNS(destroy–repair) 를 차례로 얹었다.
방법 SCORE
value-density greedy 319.5M
GRASP (RCL=3, 2000 restarts) 320.6M
or-opt 320.8M
강력 LNS (40k iters) 321.8M

다섯 방법이 전부 320~322M에 수렴했다. 이동 무시·밀도 knapsack 상한이 356M이었기에, 나는 “356M은 이동/기하를 무시한 느슨한 값이고, 여러 독립 방법이 322M로 수렴하니 그게 실질 천장 — 330M은 도달 불가”라고 결론지었다.

경고이 결론은 틀렸다

뒤에서 보듯 실제 최적은 훨씬 높았다. 이 오판은 이 글의 핵심 교훈으로 다시 다룬다.

4 전환점 — 하루 단위 분해와 beam search

정식화의 가법성을 되짚으면, 각 하루를 “720분 예산의 소형 OP”로 보고 near-optimal하게 풀면 그 결과가 31번 누적된다. 위치 carryover만 순차적으로 넘겨주면 된다. 이 관점에서 하루를 beam search로 최적화하도록 다시 짰다.

핵심 구성:

  • 후보 사전선별: 하루마다 현재 위치 기준 \(P_m - \lambda\,c_m - \mu\,d\) 상위 63개만 남겨 분기폭을 묶는다(\(\lambda=1450,\ \mu=1000\)). 하루 최대 청소 수는 \(720/60=12\)이므로 63개면 충분하다.
  • beam 탐색: 상태 \(=(\text{방문 mask}, \text{prize}, t, \text{마지막 후보}, \text{route})\). 깊이 \(\le12\), 폭 3800. 각 상태에서 \(P_j-\nu\,\text{cost}\) 상위 16개만 확장한다(\(\nu=1500\)).
  • 초과근무-인지 rank로 pruning: \(\text{rank}=\text{prize}-1500\cdot\min(t,480)-1300\cdot(t-480)^+\). 480분 이전은 1500/분, 초과근무는 1300/분으로 덜 벌한다 — 초과근무 1분이 200 보너스를 벌므로 “더 싼 시간”임을 반영한다. 즉 \(\text{rank}\approx \text{finalReward}-1500\,t\) 형태의 potential이다.
  • 채택은 진짜 목적함수로: \(\text{finalReward}=\text{prize}+200\cdot(t-480)^+\)가 최대인 하루 route를 고른다. 탐색용 대리목적(rank)과 실제 목적(finalReward)을 분리한 것이 핵심이다.

결과는 332.10M(시드 110), 미지 시드 1120에서도 330.83M으로 일반화되었고 리셋은 0이었다. 밀도 greedy 대비 +3.9%. 내가 “도달 불가”라 했던 330M을 여유롭게 넘었다.

5 왜 이기고, 나는 왜 놓쳤는가

이 부분이 방법론적으로 가장 중요하다.

내가 시도한 다섯 방법(greedy·GRASP·or-opt·2-opt·LNS)은 전부 “하나의 전역 tour + 그리디 day-packing” 이라는 동일한 표현을 공유했다. 즉 서로 독립이 아니라 같은 맹점을 공유한 상관된 방법들이었고, 같은 basin에 갇혀 같은 값으로 수렴했다. “다중 방법 수렴 = 최적 근접”이라는 검증 휴리스틱이 여기서 무너졌다 — 방법들이 진짜로 독립일 때만 성립하는 논리였다.

반면 beam은 표현 자체를 바꿨다: 전역 tour를 포기하고 하루를 독립 서브문제로 최적화한다. 하루 내부의 “어떤 부분집합을 어떤 순서로” 라는 선택이 사실 작은 OP이고, 그리디 day-packing은 이를 형편없이 풀고 있었던 것이다. 356M 상한도 알고 보니 그렇게까지 느슨하지 않았다(beam이 그 93%에 도달). 상한이 아니라 내 탐색 이웃구조가 약했던 것이 문제였다.

중요교훈: 상관된 방법의 착시

“여러 방법이 같은 값에 수렴한다”는 관찰은, 그 방법들이 같은 해 표현·같은 이웃구조를 공유하면 최적성의 증거가 되지 못한다. 진짜 검증은 표현을 근본적으로 바꾼 방법이 필요하다.

6 천장 진단 — 이동이 유일한 지렛대

beam 해의 점수를 성분 분해하니 남은 여지가 명확해졌다(시드 110, 10 TC 합).

성분 값 여지
초과근무 14.86M \(=\) 이론상 최대(14.88M)의 99.9% 없음(포화)
유휴 88분 없음(\(\approx0\))
이동 15,182분 (예산의 6.8%) 유일

초과근무와 유휴가 포화이므로 가격만이 목표다. 그리고 \(\text{가격}=\text{청소시간}\times\text{밀도}\), \(\text{청소시간}=\text{예산}-\text{이동}-\text{유휴}\)이므로, 가격을 올리는 유일한 길은 이동을 줄여 청소시간을 확보하는 것이다. 이동 15,182분 중 아침(하루 첫 이동)은 3,303분뿐이고 나머지 11,879분은 beam이 이미 근사 최적화한 하루 내부 이동이다. 따라서 현실적 천장은 약 336M이며, 356M은 이동을 0으로 가정한 도달 불가값이다.

7 근시안 공략 — 2일 beam lookahead

beam은 하루를 탐욕적으로 최적화하므로, 오늘 최고 route를 고르느라 끝 위치가 내일 밀집지에서 멀어지는 하루 간 근시안이 남는다. 이를 공략하려 오늘의 상위 \(K\)개 route 후보 각각에 대해 “오늘 보상 + 내일 추정 보상”이 최대인 것을 선택했다.

힌트추정기의 편향이 방향을 가른다

내일 보상을 그리디로 추정하면 오히려 점수가 하락했다(332.10M → 330.25M). 그리디는 체계적으로 편향돼 오늘 route 선택을 오도한다. 반면 내일을 작은 폭의 beam으로 추정하면(실제 채점 방식과 일관되게) 개선된다. 추정기는 실제 평가와 일관돼야 한다.

beam 추정 lookahead의 score시간 프론티어(BEAM_WIDTH=3800 고정):

설정 (\(K\), LA_BEAM) SCORE \(-O0\) 시간
없음 (base) 332.10M 6.9s
(4, 400) — 채택 333.03M 9.3s
(8, 1000) 333.09M 19s
(10, 2000) 333.41M 36s

무거운 설정은 계속 오르지만 시간이 급증한다. \(K=4,\ \text{LA\_BEAM}=400\)이 \(\sim10\)초 예산에 들어가는 최댓값이라 이를 채택했다. 이 버전의 분해는 가격 318.17M(+0.93M), 이동 15,182$\(14,566, 청소 1,574\)$1,587채이며, 미지 시드 1120에서도 331.78M으로 일반화되고 리셋은 0이다.

8 복잡도·메모리 분석

기호: \(N\)=집 수(\(\le399\)), \(C=63\)(후보), \(B=3800\)(beam 폭), \(L=12\)(깊이), \(K\)=lookahead 후보 수.

  • 하루 beam 1회: 후보 선별·부분정렬 \(O(N\cdot C)\), 확장 \(O(L\cdot B\cdot C)\)가 지배적. \(12\times3800\times63\approx2.9\times10^6\).
  • 하루당 lookahead 포함: 메인 beam(폭 \(B\)) + 내부 lookahead beam \(K\)회(폭 \(\text{LA\_BEAM}\)). 채택값에서 내부는 폭 400으로 훨씬 싸다.
  • 전체: \(31\ \text{days}\times10\ \text{TC}\)에 위를 곱한 값. 실측 \(-O0\) 9.3초.

메모리는 \(3\times(B\cdot\text{NEXT\_COUNT})\)개의 State가 지배적이다. \(3\times60{,}800\times32\text{B}\approx5.8\)MB이며, 전역(BSS) 영역이라 스택 제약(1MB)과 무관하다.

노트rank와 finalReward의 분리

pruning은 potential형 rank로, 최종 채택은 진짜 목적 finalReward로 한다. 대리목적으로 탐색 공간을 좁히되 편향된 대리목적이 최종 답을 오염시키지 않게 하는 표준 패턴이다.

9 교훈

  1. 표현을 바꾸는 것이 파라미터를 바꾸는 것보다 강하다. 전역 tour → 하루 분해라는 표현 전환 한 번이 모든 메타휴리스틱 튜닝을 합친 것보다 큰 도약을 줬다.
  2. 상관된 방법의 수렴은 최적성의 증거가 아니다. 같은 해 표현을 공유하는 방법들의 합의는 착시일 수 있다. 근본적으로 다른 접근으로 반증을 시도해야 한다.
  3. 느슨해 보이는 상한도 함부로 폄하하지 말라. 356M을 “비현실적”이라 치부했지만, 실제 최적은 그 93%였다. 상한이 느슨한 게 아니라 내 하한(탐색)이 약했다.
  4. 성분 분해로 지렛대를 특정하라. 초과근무·유휴가 포화임을 확인하고 나서야 “이동만이 지렛대”라는 정확한 목표가 섰다.
  5. 대리목적과 실제목적을 분리하고, 추정기는 실제 평가와 일관되게. 그리디 추정 lookahead가 해를 악화시킨 것이 그 반례다.

    if (count == NEXT_COUNT && !pairBefore(v, top[count - 1])) return;
    int pos = count;
    if (pos == NEXT_COUNT) pos = NEXT_COUNT - 1; else ++count;
    while (pos > 0 && pairBefore(v, top[pos - 1])) { if (pos < NEXT_COUNT) top[pos] = top[pos - 1]; --pos; }
    top[pos] = v;
}
static int calcRank(int prize, int t) {
    return prize - PRE_LAMBDA * (t < OVERTIME ? t : OVERTIME) - POST_LAMBDA * (t > OVERTIME ? t - OVERTIME : 0);
}
static int finalReward(const State& s) {
    int overtime = s.t > OVERTIME ? (int)s.t - OVERTIME : 0;
    return s.prize + OT_BONUS * overtime;
}
static void stableSortStates(State data[], State buffer[], int count) {
    State* src = data; State* dst = buffer;
    for (int width = 1; width < count; width <<= 1) { int step = width << 1;
        for (int left = 0; left < count; left += step) {
            int mid = left + width; int right = left + step;
            if (mid > count) mid = count; if (right > count) right = count;
            int i = left; int j = mid; int out = left;
            while (i < mid && j < right) { if (src[i].rank >= src[j].rank) dst[out++] = src[i++]; else dst[out++] = src[j++]; }
            while (i < mid) dst[out++] = src[i++]; while (j < right) dst[out++] = src[j++]; }
        State* temp = src; src = dst; dst = temp; }
    if (src != data) { for (int i = 0; i < count; ++i) data[i] = src[i]; }
}
static void copyState(State& dst, const State& src) {
    dst.mask = src.mask; dst.prize = src.prize; dst.rank = src.rank; dst.t = src.t;
    dst.last = src.last; dst.len = src.len;
    for (int i = 0; i < src.len; ++i) dst.route[i] = src.route[i];
}
static void pushTopK(const State& s) {
    if (s.len == 0) return;
    int reward = finalReward(s);
    int last = candidate[s.route[s.len - 1]];
    int ey = houses[last].y, ex = houses[last].x;
    for (int i = 0; i < tkCount; ++i)
        if (tkReward[i] == reward && tkEndY[i] == ey && tkEndX[i] == ex) return;
    int pos = tkCount < TOPK ? tkCount : TOPK;
    if (pos == TOPK) { if (reward <= tkReward[TOPK - 1]) return; pos = TOPK - 1; }
    else ++tkCount;
    while (pos > 0 && reward > tkReward[pos - 1]) {
        if (pos < TOPK) {
            tkReward[pos] = tkReward[pos - 1]; tkLen[pos] = tkLen[pos - 1];
            tkEndY[pos] = tkEndY[pos - 1]; tkEndX[pos] = tkEndX[pos - 1];
            for (int k = 0; k < tkLen[pos]; ++k) tkRoute[pos][k] = tkRoute[pos - 1][k];
        }
        --pos;
    }
    tkReward[pos] = reward; tkLen[pos] = s.len; tkEndY[pos] = ey; tkEndX[pos] = ex;
    for (int k = 0; k < s.len; ++k) tkRoute[pos][k] = candidate[s.route[k]];
}
static void planDayTopK(int startY, int startX, int beamW) {
    tkCount = 0;
    int scoreCount = 0;
    for (int i = 0; i < nHouses; ++i) {
        if (!houses[i].active) continue;
        int service = (houses[i].m + 1) * 30;
        int distance = iabs(startY - houses[i].y) + iabs(startX - houses[i].x);
        candidateScore[scoreCount].score = PRICE[houses[i].m] - CAND_LAMBDA * service - CAND_MU * distance;
        candidateScore[scoreCount].idx = i; candidateScore[scoreCount].cost = 0; ++scoreCount;
    }
    if (scoreCount == 0) return;
    sortPairs(candidateScore, scoreCount);
    int candidateCount = scoreCount < CANDIDATE_COUNT ? scoreCount : CANDIDATE_COUNT;
    for (int i = 0; i < candidateCount; ++i) {
        int h = candidateScore[i].idx; candidate[i] = h;
        candY[i] = houses[h].y; candX[i] = houses[h].x; candM[i] = houses[h].m; candPrice[i] = PRICE[houses[h].m];
        startCost[i] = iabs(startY - candY[i]) + iabs(startX - candX[i]) + (candM[i] + 1) * 30;
    }
    for (int i = 0; i < candidateCount; ++i)
        for (int j = 0; j < candidateCount; ++j)
            moveCost[i][j] = (unsigned short)(iabs(candY[i] - candY[j]) + iabs(candX[i] - candX[j]) + (candM[j] + 1) * 30);
    State initial; initial.mask = 0ULL; initial.prize = 0; initial.rank = 0; initial.t = 0; initial.last = -1; initial.len = 0;
    stateA[0] = initial;
    State* current = stateA; State* next = stateB; int currentCount = 1;
    for (int depth = 0; depth < MAX_DEPTH; ++depth) {
        int nextCount = 0;
        for (int si = 0; si < currentCount; ++si) {
            const State& s = current[si];
            PairScore top[NEXT_COUNT]; int topCount = 0;
            for (int j = 0; j < candidateCount; ++j) {
                unsigned long long bit = 1ULL << j;
                if (s.mask & bit) continue;
                int cost = s.last < 0 ? startCost[j] : (int)moveCost[(int)s.last][j];
                int nt = (int)s.t + cost;
                if (nt > DAY_LIMIT) continue;
                PairScore p; p.score = candPrice[j] - NEXT_LAMBDA * cost; p.idx = j; p.cost = cost;
                insertTopPair(top, topCount, p);
            }
            if (topCount == 0) { pushTopK(s); continue; }
            for (int q = 0; q < topCount; ++q) {
                int local = top[q].idx; State& ns = next[nextCount++];
                copyState(ns, s);
                ns.t = (unsigned short)((int)s.t + top[q].cost);
                ns.last = (signed char)local; ns.mask = s.mask | (1ULL << local);
                ns.prize = s.prize + candPrice[local]; ns.rank = calcRank(ns.prize, ns.t);
                ns.route[ns.len++] = (unsigned char)local;
            }
            if (s.t >= OVERTIME) pushTopK(s);
        }
        if (nextCount == 0) break;
        if (nextCount > beamW) { stableSortStates(next, mergeBuffer, nextCount); nextCount = beamW; }
        State* temp = current; current = next; next = temp; currentCount = nextCount;
    }
    for (int i = 0; i < currentCount; ++i) pushTopK(current[i]);
}
// day-d routes copied out so nested lookahead beams don't clobber them
static int dLen[TOPK], dRoute[TOPK][MAX_DEPTH], dReward[TOPK], dEndY[TOPK], dEndX[TOPK], dCount;
void process(int board[][MAP_SIZE], int posY, int posX) {
    nHouses = 0;
    for (int y = 0; y < MAP_SIZE; ++y)
        for (int x = 0; x < MAP_SIZE; ++x) {
            if (board[y][x] == 0) continue;
            houses[nHouses].y = y; houses[nHouses].x = x; houses[nHouses].m = board[y][x]; houses[nHouses].active = 1; ++nHouses;
        }
    int currentY = posY; int currentX = posX;
    for (int day = 0; day <= 30; ++day) {
        planDayTopK(currentY, currentX, BEAM_WIDTH);
        if (tkCount == 0) { if (day < 30) nextDay(); continue; }
        // copy out day-d candidates
        dCount = tkCount;
        for (int r = 0; r < tkCount; ++r) {
            dLen[r] = tkLen[r]; dReward[r] = tkReward[r]; dEndY[r] = tkEndY[r]; dEndX[r] = tkEndX[r];
            for (int k = 0; k < tkLen[r]; ++k) dRoute[r][k] = tkRoute[r][k];
        }
        int pick = 0;
        if (day < 30 && dCount > 1) {
            long long bestPair = -1;
            for (int r = 0; r < dCount; ++r) {
                for (int k = 0; k < dLen[r]; ++k) houses[dRoute[r][k]].active = 0;
                planDayTopK(dEndY[r], dEndX[r], LA_BEAM);
                int tomo = tkCount > 0 ? tkReward[0] : 0;
                for (int k = 0; k < dLen[r]; ++k) houses[dRoute[r][k]].active = 1;
                long long pairScore = (long long)dReward[r] + tomo;
                if (pairScore > bestPair) { bestPair = pairScore; pick = r; }
            }
        }
        for (int i = 0; i < dLen[pick]; ++i) {
            int h = dRoute[pick][i]; if (!houses[h].active) continue;
            move(houses[h].y, houses[h].x); currentY = houses[h].y; currentX = houses[h].x; houses[h].active = 0;
        }
        if (day < 30) nextDay();
    }
}
