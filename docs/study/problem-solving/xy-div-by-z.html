X^Y ÷ Z의 소수 표현: Modular Arithmetic 트릭

algorithm
modular-arithmetic
number-theory
X^Y ÷ Z를 10진법으로 표현할 때, 소숫점 앞 3자리와 뒤 3자리를 구하는 문제를 mod (1000·Z) 트릭과 long division으로 해결하는 과정을 정리한 글
Published

April 13, 2026

1 문제 개요

세 자연수 X, Y, Z가 주어질 때, 유리수 \(\frac{X^Y}{Z}\)를 10진법으로 표현하여 소숫점 앞 최대 3자리와 소숫점 뒤 3자리를 출력하는 문제다.

  • \(1 \le X \le 10^9\), \(1 \le Y \le 10^9\), \(1 \le Z \le 10^6\)
  • 반올림을 하면 안 되고, 버림(truncation)만 허용된다.
  • 정수부가 4자리 이상이면 하위 3자리만 0-padding하여 출력하고, 3자리 이하면 그대로 출력한다.
Note핵심 난관

\(X^Y\)는 최대 \((10^9)^{10^9}\)까지 갈 수 있어서 직접 계산이 불가능하다. 그러나 필요한 것은 하위 3자리와 나머지뿐이므로, modular exponentiation으로 충분하다.

2 핵심 아이디어: mod (1000·Z) 트릭

2.1 목표 정리

\(X^Y\)를 \(Z\)로 나누면 몫 \(Q\)와 나머지 \(R\)이 나온다.

\[ X^Y = Q \cdot Z + R \quad (0 \le R < Z) \]

여기서 \(Q\)가 정수부, \(\frac{R}{Z}\)가 소수부다. 우리가 필요한 것은 \(Q \bmod 1000\) (정수부 하위 3자리)과 \(R\) (나머지)이다.

2.2 하나의 mod 연산으로 두 값을 동시에 얻기

\(Q\)를 1000으로 나누면

\[ Q = 1000k + q \quad (q = Q \bmod 1000) \]

이걸 원래 식에 대입하면

\[ X^Y = (1000k + q) \cdot Z + R = 1000kZ + qZ + R \]

양변에 \(\bmod\;(1000 \cdot Z)\)를 취하면, \(1000kZ\)는 \(1000Z\)의 배수이므로 사라진다.

\[ X^Y \bmod (1000 \cdot Z) = qZ + R \]

이것을 \(v\)라 하면

\[ v = qZ + R \]

따라서

\[ v / Z = q = Q \bmod 1000 \quad \text{(정수부 하위 3자리)} \]

\[ v \% Z = R \quad \text{(나머지)} \]

Tip왜 하나의 mod로 충분한가

\(\bmod\;(1000 \cdot Z)\)는 본질적으로 “\(Z\)로 나눈 나머지”와 “\(Z\)로 나눈 몫의 하위 3자리”를 하나의 값으로 인코딩한다. \(v\)를 \(Z\)로 나누면 두 정보가 자연스럽게 분리된다.

2.3 구체적 예시: X=11, Y=3, Z=13

\[ 11^3 = 1331, \quad 1331 \div 13 = 102 \;\cdots\; 5 \]

이제 mod (1000·Z) 방식으로 계산하면

\[ 1000 \cdot Z = 13000 \]

\[ v = 11^3 \bmod 13000 = 1331 \bmod 13000 = 1331 \]

\[ v / Z = 1331 / 13 = 102 \quad \text{(정수부 하위 3자리) ✓} \]

\[ v \% Z = 1331 \% 13 = 5 \quad \text{(나머지) ✓} \]

2.4 오버플로우 안전성

\(1000 \cdot Z \le 1000 \times 10^6 = 10^9\)이므로, modular exponentiation 도중 \(a \times a\)가 최대 \((10^9)^2 = 10^{18}\)으로 unsigned long long 범위 안에 들어온다.

3 소수부 계산: Long Division

나머지 \(R\)로부터 소수점 이하 3자리를 수동 나눗셈으로 구한다.

\[ R = 5, \quad Z = 13 \text{일 때:} \]

단계 계산 몫 (출력 자릿수) 나머지
1 \(5 \times 10 = 50\) \(50 / 13 = 3\) \(50 \% 13 = 11\)
2 \(11 \times 10 = 110\) \(110 / 13 = 8\) \(110 \% 13 = 6\)
3 \(6 \times 10 = 60\) \(60 / 13 = 4\) \(60 \% 13 = 8\)

결과: 102.384 ✓

이 과정은 우리가 손으로 나눗셈을 할 때와 정확히 같은 원리다. 나머지에 10을 곱하고, 제수로 나누고, 몫을 한 자리씩 뽑아낸다.

4 0-padding 판별 로직

4.1 문제 상황

정수부 \(Q\)의 크기에 따라 출력 포맷이 달라진다.

조건 예시 출력
\(Q \ge 1000\) (4자리 이상) \(Q = 152102057\) 057.xxx (하위 3자리, 0-padding)
\(Q < 1000\) (3자리 이하) \(Q = 1\) 1.xxx (그대로)

4.2 판별 방법: 실제 값과 mod 값 비교

\(Q < 1000\)이면 \(X^Y < 1000 \cdot Z\)이고, 이 경우 mod를 취해도 값이 변하지 않는다.

\[ X^Y < 1000 \cdot Z \quad \Longleftrightarrow \quad X^Y \bmod (1000 \cdot Z) = X^Y \]

따라서 실제 \(X^Y\)와 \(v\)가 같으면 mod가 아무 효과도 없었다는 뜻이고, 이는 원래 값이 작다는 의미다.

코드에서는 mypow(X, Y)로 실제 \(X^Y\)를 구하되, 오버플로우가 발생하면 충분히 큰 MAX를 반환한다.

mypow(X,Y) == v  →  정수부가 3자리 이하  →  "%lld" (padding 없음)
mypow(X,Y) != v  →  정수부가 4자리 이상  →  "%03lld" (padding 적용)
Importantmypow 구현 시 주의사항

mypow는 정확한 값이 아니라 “충분히 큰지”만 판별하면 되므로, 오버플로우 직전에 MAX를 반환하는 방식이면 충분하다. 단, 다음 두 가지를 반드시 지켜야 한다.

  1. MAX 값이 \(1000 \cdot Z_{\max} = 10^9\) 이상이어야 한다. MAX가 너무 작으면 실제로 \(X^Y < 1000Z\)인데도 MAX를 반환하여 잘못된 padding이 적용된다.

  2. base *= base(제곱)를 base <<= 1(×2)로 잘못 쓰면 안 된다. 비트 시프트는 2를 곱하는 연산이지 제곱이 아니다.

5 디버깅 과정에서 발견한 버그들

이 문제를 풀면서 단계적으로 발견한 실수들을 정리한다.

5.1 mod 1은 항상 0

처음에 cmp = get_out(x, y, 1)로 실제 값을 구하려 했으나, 어떤 수든 \(\bmod\;1 = 0\)이므로 이 값은 항상 0이다. 따라서 “out이 0인가?”만 검사하게 되어, padding 판별이 완전히 틀어진다.

5.2 base <<= 1은 제곱이 아니라 ×2

Fast exponentiation에서 짝수 지수 처리 시

power >>= 1;
base <<= 1;  // ← base × 2 (잘못됨)

base <<= 1은 비트 왼쪽 시프트이므로 2를 곱하는 연산이다. 올바른 코드는 base *= base다.

예를 들어 get_out(3, 4)를 추적하면, base <<= 1 방식은 3→6→12로 진행하여 최종 결과 12를 반환하지만, 실제 \(3^4 = 81\)이다.

5.3 base *= base 오버플로우

base가 \(X = 10^9\)일 때, 한 번 제곱하면 \(10^{18}\) (범위 내)이지만 두 번 제곱하면 \(10^{36}\)으로 오버플로우가 발생한다. ret에만 MAX 가드를 걸고 base에는 가드가 없으면 쓰레기 값이 생긴다.

// 수정: base 제곱 직후에도 가드 추가
power >>= 1;
if (base * base > MAX) return MAX;
base *= base;
WarningC/C++ 오버플로우 주의

이 문제에서 반복적으로 등장한 실수의 패턴: 값이 커질 수 있는 모든 곱셈 지점에서 오버플로우를 체크해야 한다. ret만 체크하고 base를 방치하면, fast exponentiation의 base *= base 단계에서 조용히 값이 망가진다.

6 전략적 교훈

이 문제에서 기억해둘 PS 전략을 정리한다.

  1. 필요한 자릿수만 modular arithmetic으로 추출한다. \(X^Y\) 전체를 계산할 수 없더라도, 하위 \(k\)자리만 필요하면 \(\bmod\;10^k\)으로 충분하다. 이 문제에서는 이를 \(\bmod\;(1000 \cdot Z)\)로 확장하여 나눗셈의 몫 하위 3자리와 나머지를 동시에 얻었다.

  2. 한 번의 modpow로 두 정보를 인코딩할 수 있다. mod 대상을 적절히 설계하면, 한 번의 modular exponentiation 결과에서 나눗셈과 자릿수 추출을 동시에 처리할 수 있다.

  3. “실제 값 == mod 값” 비교로 크기 판별이 가능하다. mod를 취해도 값이 변하지 않았으면 원래 값이 modulus보다 작다는 의미다.

Codes

#include <stdio.h>

using ull = unsigned long long int;

ull get_out(ull base, ull power)
{
    const ull MAX = 1'000'000'000ULL + 1;
    ull ret = 1;

    while (power != 0) {
        if (ret > MAX) {
            return MAX;
        }

        if ((power % 2) == 1) {
            ret *= base;
            --power;
            continue;
        }

        power >>= 1;
        if (base * base > MAX) {
            return MAX;
        }
        base *= base;
    }

    return ret;
}

ull get_out(ull base, ull power, ull mod)
{
    ull ret = base;

    if (power == 0) {
        return 1;
    } else if ((power % 2) == 1) {
        return ((ret % mod) * get_out(base, power - 1, mod)) % mod;
    } else {
        return (get_out((base * base) % mod, power >> 1, mod) % mod);
    }

    return ret;
}

int main(void)
{
    int t;
    scanf("%d", &t);
    while (t--) {
        ull x, y, z;
        scanf("%llu%llu%llu", &x, &y, &z);

        ull cmp = get_out(x, y);
        ull out = get_out(x, y, z * 1000);
        ull integer = out / z;
        ull decimal = out % z;
        decimal *= 1000;
        decimal /= z;
        if (cmp == out) {
            printf("%llu.%03llu\n", integer, decimal);
        } else {
            printf("%03llu.%03llu\n", integer, decimal);
        }
    }
}
