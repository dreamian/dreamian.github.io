다리 끊김 — 정점별 이벤트 + KRT + Tarjan Offline LCA

시간에 따라 그래프의 연결성이 단조감소하는 문제. 각 다리의 끊김 시각을 정점별 이벤트 배치 + 다리별 독립 계산 으로 효율적으로 구한 뒤, Kruskal Reconstruction Tree 와 Tarjan offline LCA 로 쿼리를 처리한다.

Published

May 13, 2026

1. 문제 요약

2D 평면 위에 \(N\) 개의 건물이 있고, 각 건물의 초기 위치는 \((x_i, y_i, 0)\). \(M\) 개의 다리가 두 건물을 연결하며, 각 다리에는 탄성 한계 \(l_e\) 가 있어서 잇는 두 정점 사이의 유클리드 거리가 \(l_e\) 를 초과하면 끊어진다.

\(K\) 일 동안 매일 한 건물의 \(z\) 좌표가 변화하고 (\(v_i\) 번 건물이 \(h_i\) 만큼), 한 번 끊어진 다리는 영영 못 쓴다.

\(Q\) 개의 쿼리는 두 건물 \(r, s\) 에 대해 “처음으로 통행이 불가능해지는 날짜” 를 묻는다. 끊어지지 않으면 \(-1\). 최종 출력은

\[ \sum_{i=1}^{Q} i \cdot \mathrm{ans}_i. \]

제약

  • \(2 \le N \le 5\times 10^5\)
  • \(1 \le M \le 3N\) (평면 그래프 제약)
  • \(1 \le K, Q \le 5\times 10^5\)
  • 좌표 \(|x|, |y| \le 10^8\), \(|h_i| \le 10^8\), \(l \le 10^9\)

2. 핵심 관찰

2.1 단조성

다리는 한 번 끊어지면 영영 끝.

이 한 줄이 모든 풀이의 출발점. 시간이 흐를수록 그래프의 연결성은 단조감소 만 한다. 날 \(t\) 에 살아있는 다리 집합

\[ \mathrm{Alive}(t) = \{ e : \mathrm{break}(e) > t \} \]

은 \(t\) 가 커질수록 줄어들기만 한다.

2.2 오프라인 처리

모든 변화 이벤트와 쿼리가 미리 주어진다. 그래서 시간 순서대로 인터랙티브하게 답할 필요가 없고, 시간을 거꾸로 보거나 다리별로 독립 처리하는 등의 오프라인 트릭이 자유롭게 가능.

2.3 3D 기하의 1D 환원

다리 \((u, v)\) 의 끊김 조건은

\[ (x_u - x_v)^2 + (y_u - y_v)^2 + (z_u - z_v)^2 > l_e^2. \]

\(x, y\) 는 고정이라 앞 두 항은 상수 \(C_{uv}\). 따라서

\[ \text{끊김 조건} \iff (z_u - z_v)^2 > l_e^2 - C_{uv} =: \mathrm{lb}_e. \]

기하 문제처럼 보이지만 본질은 시간축 위의 1D 신호 차이 추적.

3. 풀이 4단계

Note
  1. 각 다리의 끊김 시각 \(\mathrm{break}(e)\) 계산 — 정점별 이벤트 배치 + 다리별 독립 처리
  2. Kruskal Reconstruction Tree 구축 — \(\mathrm{break}\) 내림차순으로 합치며 트리화
  3. Tarjan Offline LCA — 모든 쿼리에 대한 LCA 를 \(O((N + Q)\,\alpha)\) 에 일괄 처리
  4. 답 집계 — 각 쿼리에 LCA 의 value 매칭, 가중합

각 단계가 표준 기법이지만, 이걸 조합 하는 것과 1단계의 효율적 구현이 핵심.

4. 1단계 — 다리별 끊김 시각 계산

4.1 자명한 walk 접근의 한계

가장 직관적인 시간 순방향 시뮬레이션:

for day in 1..K:
    v = winter[day].v
    z[v] += h[day]
    for each alive bridge e incident to v:
        if |z[e.u] - z[e.v]|^2 > lb_e:
            break(e) = day
            remove e

문제는 안쪽 루프의 총 작업량이 \(\sum_t \deg_{\text{alive}}(v_t)\) 라는 점. 별 그래프 + 중심이 K번 변화 같은 입력에서

\[ \sum_t \deg(v_t) \;\sim\; K \cdot (N-1) \;\approx\; 2.5 \times 10^{11} \]

까지 가서 무조건 TLE. 끊긴 다리를 양쪽 인접 리스트에서 즉시 splice 해도 (twin trick + 이중 연결 리스트), 살아있는 다리들의 재방문 은 못 막는다. asymptotic 한계가 그대로.

4.2 단조성 술어의 함정

“이분탐색으로 각 다리의 끊김 시각을 찾자” 라는 발상이 자연스럽지만 그대로는 작동 안 함.

Warning

\(|z_u(t) - z_v(t)|\) 은 \(t\) 에 대해 단조가 아니다.

고도 변화 \(h_i\) 가 양·음을 오갈 수 있어, 어떤 \(t^*\) 에 \(|z_u - z_v| > D\) 였다가 그 이후 다시 \(D\) 이하로 복귀 할 수 있다. mid 한 점만 보고 “끊김 여부” 를 판단하면 이미 끊어진 후 차이가 줄어든 케이스를 놓친다.

올바른 단조 술어는

\[ P(t, e) := \exists\, t' \le t,\ |z_u(t') - z_v(t')|^2 > \mathrm{lb}_e \]

이고, 이는 이력 의존 이라 mid 한 점으로 평가 불가. 평가하려면 결국 \([1, t]\) 의 이벤트를 다 봐야 하니 PBS 가 제공해야 할 \(\log K\) 배 절약 이 발생하지 않는다.

4.3 결정적 관찰 — 다리별 독립성

다리 \((u, v)\) 의 끊김 시각은 \(u\) 와 \(v\) 의 변화 이벤트만으로 결정된다.

다른 정점의 변화는 이 다리의 \(z\) 차이에 영향을 주지 않는다. 이 관찰로 알고리즘 구조를 시간축 walk 에서 다리 단위 계산 으로 뒤집을 수 있다.

4.4 정점별 이벤트 packing

각 정점 \(v\) 의 이벤트들을 연속된 메모리에 배치한다. prefix-sum 으로 구간을 잡고:

  • v_evt_start[v] ~ v_evt_start[v] + c_v 가 정점 \(v\) 의 이벤트 인덱스 구간
  • 각 위치에 다음 세 값 저장:
    • evt_day[i] — 이 이벤트가 일어난 날짜 (0-indexed)
    • evt_z[i] — 이 이벤트 직후의 \(z_v\) 누적 값
    • evt_max[i] — 이 이벤트까지의 \(|z_v|\) 누적 최댓값 (비감소 수열)

이렇게 두면 다리 \((u, v)\) 처리는 \(u\) 와 \(v\) 의 이벤트 구간만 보면 끝나고, 메모리도 캐시 친화적으로 흐른다.

4.5 다리별 분기 처리

다리 \((u, v)\) 에 대해 \(c_u, c_v\) (이벤트 수) 에 따라:

Case 1: \(c_u = c_v = 0\) (양쪽 정적)

\(z_u = z_v = 0\) 영원히. 다리 영원히 안 끊김. \(\mathrm{break}(e) = \infty\). 비용 \(O(1)\).

Case 2: 한쪽만 정적 (예: \(c_v = 0\), \(c_u > 0\))

\(z_v = 0\) 이므로 \(|z_u(t) - z_v(t)| = |z_u(t)|\). 끊김 조건

\[ |z_u(t)|^2 > \mathrm{lb}_e \]

가 처음 만족되는 이벤트 인덱스를 찾으면 됨.

evt_max[i] 가 비감소 라는 점이 핵심:

Tip

보조 정리. evt_max[i] > D 가 되는 가장 작은 \(i\) 는, \(|z_u(j)| > D\) 가 되는 가장 작은 \(j\) 와 같다.

증명. evt_max 가 비감소이고, \(i^* = \min\{i : \mathrm{evt\_max}[i] > D\}\) 라 하자. \(\mathrm{evt\_max}[i^* - 1] \le D\) 이고 \(\mathrm{evt\_max}[i^*] > D\) 이려면 그 증가의 원인이 \(|z_u(i^*)|\) 자체 이어야 한다 (다른 인덱스의 값으로는 \(i^*\) 시점에 max 가 바뀌지 않으니까). 즉 \(|z_u(i^*)| > D\). 그리고 \(i < i^*\) 면 \(\mathrm{evt\_max}[i] \le D\) 이므로 \(|z_u(i)| \le D\). ∎

따라서 이분탐색 으로 \(O(\log c_u)\):

int lo = su, hi = su + cu;
while (lo < hi) {
    int mid = (lo + hi) >> 1;
    ll mval = evt_max[mid];
    bool broken = (mval > SAFE_BND) || (mval * mval > lb_e);
    if (broken) hi = mid;
    else        lo = mid + 1;
}
if (lo < su + cu) bridge[e].broken_time = evt_day[lo] + 1;

Case 3: 양쪽 동적

두 이벤트 리스트를 시간순으로 머지 스캔. 한 스텝마다 \(z_u\) 또는 \(z_v\) 갱신 후 \(|z_u - z_v|^2 > \mathrm{lb}_e\) 검사. 처음 만족되는 날짜가 답. 비용 \(O(c_u + c_v)\).

4.6 왜 이게 빠른가

케이스 다리당 비용
양쪽 정적 \(O(1)\)
한쪽 정적 \(O(\log K)\)
양쪽 동적 \(O(c_u + c_v)\)

별 그래프 + 중심이 K번 변화 케이스: 중심 외 모든 정점이 정적 → 모든 다리가 Case 2 → 전체 \(O((K + M)\log K) \approx 10^7\). walk 의 \(O(NK)\) 와 비교해서 \(N \log N \approx 20N\) 배 빠름.

양쪽 동적 다리만 모인 worst case 는 여전히 \(\sum_{e \in M_2}(c_u + c_v)\) 이지만, 정점에 변화가 몰리는 가장 흔한 adversarial 입력은 그 정점에서 나가는 다리들의 반대편이 거의 정적이라 Case 2 로 빠진다.

4.7 정수 오버플로 가드

evt_max[i] 누적은 최대 \(5 \times 10^{13}\) 까지 가능 → 제곱은 long long 초과.

constexpr ll SAFE_BND = 1'500'000'000LL;  // SAFE_BND^2 = 2.25e18 < LL_MAX
ll mval = evt_max[mid];
bool broken = (mval > SAFE_BND) || (mval * mval > lb_e);

\(\mathrm{lb}_e \le 10^{18}\) 이므로 \(\mathrm{evt\_max} > \mathrm{SAFE\_BND}\) 면 무조건 \(\mathrm{evt\_max}^2 > \mathrm{lb}_e\), 안전한 short-circuit.

Note

머지 스캔의 오버플로?

Case 3 머지 스캔에서는 살아있는 다리만 검사 한다. 살아있다는 건 직전까지 \(|z_u - z_v| \le \sqrt{\mathrm{lb}_e} \le 10^9\) 였다는 뜻. 한 이벤트의 변화 \(|h_t| \le 10^8\) 이므로 새 \(|z_u - z_v| \le 1.1 \times 10^9\). 제곱 \(\le 1.21 \times 10^{18}\) 으로 long long 안에 들어옴. 추가 가드 불필요.

5. 2단계 — Kruskal Reconstruction Tree

5.1 무엇을 만드는가

원래 그래프의 정점 \(1, \dots, N\) 을 잎 으로 두고, 합쳐지는 사건마다 새 내부 노드 하나씩 만들어 트리를 키운다.

  • 잎: 건물 \(1, \dots, N\)
  • 내부 노드: “이 시점에 두 컴포넌트가 합쳐졌음” 을 의미하는 가상 노드
  • 내부 노드의 value = 합치게 만든 다리의 \(\mathrm{break}\) 시각

이진 트리 형태. 연결 그래프이므로 최종 \(2N - 1\) 노드.

5.2 경로 단조성

다리를 \(\mathrm{break}\) 내림차순 으로 처리하므로:

잎에서 루트로 올라갈 때 만나는 내부 노드들의 value 는 단조감소 한다.

뿌리에 가까울수록 value 가 작다. 이 성질이 LCA 가 답을 주는 근거.

5.3 구축 알고리즘

sort(bridges by broken_time desc)
for i in 1..2N: par_uf[i] = i
tot_nodes = N

for each bridge (u, v, b) in sorted order:
    ru = find_uf(u); rv = find_uf(v)
    if ru == rv: continue
    w = ++tot_nodes
    kru_val[w] = b
    kru_l[w] = ru;  kru_r[w] = rv
    par_uf[ru] = par_uf[rv] = w

5.4 왜 LCA value 가 답인가 — Bottleneck Path

쿼리 \((r, s)\) 에 대해 다음이 정확히 성립:

\[ \text{첫 분리 시각}(r, s) = \max_{P \in \mathcal P(r,s)} \min_{e \in P} \mathrm{break}(e). \]

해석: \(r\) 과 \(s\) 사이의 모든 경로 중에서, 그 경로의 최약 다리 의 끊김 시각이 가장 큰 경로를 찾고, 그 값이 답.

Note

Bottleneck 의 직관

각 경로의 “수명” = 그 경로 최약 다리의 끊김 시각. \(r, s\) 가 살아남으려면 어느 한 경로만 살아있으면 충분하므로, 최약 다리들 중 가장 늦게 끊어지는 경로가 운명을 결정.

KRT 는 \(\mathrm{break}\) 가 큰 다리부터 처리하므로 사실상 Kruskal Max Spanning Tree 알고리즘. MaxST 의 고전 성질:

임의의 두 정점 \(r, s\) 에 대해, MaxST 상 \(r\)-\(s\) 경로의 bottleneck = 원래 그래프 모든 경로의 bottleneck 최댓값.

KRT 는 이 MaxST 의 bottleneck 정보를 LCA value 형태로 압축 저장. 따라서

\[ \mathrm{LCA}(r, s).\mathrm{value} \;=\; \text{첫 분리 시각}(r, s). \]

5.5 미니 예제

건물 3개, 다리 3개:

다리 끝점 \(\mathrm{break}\)
\(e_1\) \((1, 2)\) 5
\(e_2\) \((1, 3)\) 3
\(e_3\) \((2, 3)\) 8

내림차순 처리: \(e_3 (8), e_1 (5), e_2 (3)\)

  • \(e_3\): 새 노드 4, \(\mathrm{val} = 8\), 자식 \(\{2, 3\}\)
  • \(e_1\): \(\mathrm{find}(2) = 4\) → 새 노드 5, \(\mathrm{val} = 5\), 자식 \(\{1, 4\}\)
  • \(e_2\): \(\mathrm{find}(1) = 5 = \mathrm{find}(3)\) → 같은 컴포넌트, 스킵

쿼리 \((1, 3)\) 의 \(\mathrm{LCA} = 5\), \(\mathrm{val} = 5\). 답 = 5.

검증: 직접 다리 \(e_2\) 는 날 3 에 끊어지지만, 우회 경로 \(1{-}2{-}3\) 가 날 5 까지 살아있음. 답이 bottleneck 더 좋은 경로 의 값이 되는 게 정확하다.

Important

\(e_2\) 가 스킵되는 게 정당한 이유: 처리 시점에 1 과 3 이 이미 더 큰 \(\mathrm{break}\) 의 경로로 연결돼 있으니 \(e_2\) 는 bottleneck 을 개선하지 못한다. Kruskal MaxST 가 사이클 만드는 간선을 스킵해도 정답을 내는 이유와 동일.

6. 3단계 — Tarjan Offline LCA

6.1 Binary Lifting 대신 Tarjan 을 쓰는 이유

KRT 노드 수가 \(2N \approx 10^6\) 까지 가는데 binary lifting 의 up[2N][LOG] 는

\[ 10^6 \times 21 \times 4\text{B} = 84\text{ MB} \]

메모리 부담 + 빌드의 21M cache-miss-prone 연산.

Tarjan offline LCA 는 모든 쿼리를 미리 알고 있을 때 한 번의 DFS + UF 로 처리:

  • 시간: \(O((N + Q)\,\alpha(N))\)
  • 메모리: \(O(N + Q)\) — 84MB 통째 절약

6.2 알고리즘 핵심

Tip

DFS 로 트리를 순회하면서 방문 완료된 노드들 에 대한 UF 를 유지. 각 컴포넌트의 “ancestor” 는 현재 DFS 경로상 가장 깊은 공통 조상.

노드 \(u\) 의 DFS 가 끝나는 시점에, \(u\) 와 관련된 쿼리들 중 상대 정점 \(v\) 가 이미 방문 완료 인 것에 대해 \(\mathrm{LCA}(u, v) = \mathrm{anc}[\mathrm{find}(v)]\).

의사코드:

DFS(u):
    par_uf[u] = u
    anc[u] = u
    for each child c:
        DFS(c)
        par_uf[find(c)] = u
        anc[find(u)] = u
    visited[u] = true
    for each query (u, v) registered at u:
        if visited[v]:
            answer with kru_val[ anc[find(v)] ]

6.3 재귀 깊이 회피 — 3-phase 명시적 스택

KRT 가 선형 체인 형태이면 깊이 \(O(N)\) 이라 재귀 DFS 는 stack overflow. 명시적 스택 + 노드별 phase 상태로 반복 구현:

  • Phase 0: 진입, \(\mathrm{par\_uf}/\mathrm{anc}\) 초기화, 왼쪽 자식 push (있으면)
  • Phase 1: 왼쪽 자식 처리 후 union, 오른쪽 자식 push (있으면)
  • Phase 2: 오른쪽 자식 처리 후 union, \(\mathrm{visited}\) 설정 + 쿼리 처리, pop

7. 4단계 — 답 집계

ll total = 0;
for (int i = 0; i < q; ++i) {
    total += (ll)(i + 1) * query[i].ans;
}

출력 합의 상한 \(\sim Q^2 \cdot K \approx 1.25 \times 10^{17}\), long long 안에 충분히 들어옴. 음수 누적 (\(\mathrm{ans} = -1\)) 가능하니 signed long long.

8. 구현 함정 모음

Warning

1-indexed vs 0-indexed
입력 정점 번호가 1-indexed 라면 배열도 1-indexed 로 통일. 한 칸 어긋나면 OOB read 와 미묘한 logic 오류.

z 의 자료형
\(|h_i| \le 10^8\), \(K \le 5 \times 10^5\) → 누적 \(|z| \le 5 \times 10^{13}\). int 로는 오버플로. 반드시 long long.

scanf("%d", &ll_var) 는 UB
long long 변수에 %d 포맷으로 읽으면 상위 4바이트가 스택 garbage. 관계없어 보이는 코드를 건드리면 출력이 사라지거나 나타나는 류의 spooky 버그를 만든다. 반드시 %lld 로.

z_diff^2 의 안전 가드
evt_max 류 누적 최댓값은 long long 범위까지 갈 수 있으니 제곱 전 사전 검사. 살아있는 다리의 머지 스캔에선 1.1e9 로 bounded 라 가드 불필요.

테스트 케이스 간 상태 리셋
tot_nodes, qry_count, 정점별 카운터 등 매 케이스 초기화. BSS zero-init 에만 의존하지 말 것.

KRT DFS 깊이
선형 체인 가능. 재귀 대신 명시적 스택 / BFS 로 반드시 처리.

_qsort 의 worst case
동일 키 (특히 모두 INF) 가 많으면 단순 Lomuto partition 은 \(O(M^2)\). 3-way partition 으로 동치류를 한 번에 처리하면 해결.

9. 복잡도 정리

단계 시간
정점별 이벤트 packing \(O(N + K)\)
다리별 break (한쪽 정적 우세) \(O((M + K) \log K)\)
다리별 break (양쪽 동적 우세) \(O(\sum_e (c_u + c_v))\)
KRT 정렬 \(O(M \log M)\)
KRT 빌드 \(O(M\,\alpha(N))\)
Tarjan LCA \(O((N + Q)\,\alpha(N))\)
답 집계 \(O(Q)\)

대부분의 입력에서 \(O\!\left((N + M + K + Q)\log\right)\) 에 수렴. 메모리도 binary lifting 대신 Tarjan 을 쓰면서 binary lifting 대비 ~80MB 절약.

10. 회고 — 발상의 전환점 정리

Note

이 문제에서 정착시킬 PS 일반론:

  1. 단조성을 찾아라. “한 번 X 되면 영영 X” 패턴 = 시간 역순 UF / KRT 의 전형적 신호.

  2. 단조 술어를 정확히 골라라. 현재 시점의 값 이 아니라 이력 술어 만 단조일 수 있다. PBS 를 적용하기 전, 술어의 단조성과 평가 비용 을 둘 다 검증할 것. 평가가 walk 만큼 든다면 PBS 의 \(\log\) 절약이 실현되지 않는다.

  3. 그래프 알고리즘을 시간축이 아닌 간선축 으로 뒤집어 보라. 시간 순방향 시뮬레이션이 worst case 입력에 막힐 때, 각 간선의 운명을 그 간선 끝점들의 이벤트만 으로 결정할 수 있는지 확인. 됐다면 walk 의 \(\sum_t \deg(v_t)\) 가 다리 단위 \(\sum_e (c_u + c_v)\) 로 바뀐다.

  4. KRT 의 본질은 bottleneck path. “최약 간선이 가장 강한 경로” 정보를 LCA value 에 압축. 우회 경로 가능성까지 자동으로 처리해주는 게 핵심 매력.

  5. Tarjan offline LCA 는 binary lifting 보다 메모리·캐시 측면에서 우월. 모든 쿼리가 미리 주어지면 거의 항상 우월.

  6. scanf 포맷 미스매치는 가장 알아내기 힘든 UB. -Wall -Wformat -fsanitize=address,undefined 켜고 디버깅하면 즉시 잡힘.

  7. TLE 의 진짜 원인은 상수배가 아니라 worst case complexity 일 때가 많다. 코드 마이크로 최적화 (fast I/O, 3-way qsort, 캐시 친화 splice) 를 다 해도 TLE 가 안 풀린다면 알고리즘 자체를 다시 본다. 이 문제도 walk 의 \(O(NK)\) 가 본질적 한계였고, 다리별 독립 계산으로 알고리즘 자체 를 갈아엎어야 했다.

#include <stdio.h>

using ll = long long;

int t, n, m, k, q;
constexpr int MAX_N     = 500'001;
constexpr int MAX_M     = 1'500'001;
constexpr int MAX_K     = 500'001;
constexpr int MAX_Q     = 500'001;
constexpr int MAX_NODES = 2 * MAX_N;
constexpr int INF       = 1'000'000'000;
constexpr ll  SAFE_BND  = 1'500'000'000LL;

struct Building {
    int x, y;
    void init(int _x, int _y) { x = _x; y = _y; }
} building[MAX_N];

struct Bridge {
    int v1, v2;
    int broken_time;
    ll  lb;
} bridge[MAX_M];

struct Winter { int v, h; } winter[MAX_K];
struct Query  { int src, dst; ll ans; } query[MAX_Q];

int v_evt_cnt  [MAX_N];
int v_evt_start[MAX_N + 1];
int evt_day [MAX_K];
ll  evt_z   [MAX_K];
ll  evt_max [MAX_K];
ll  temp_z  [MAX_N];
ll  temp_max[MAX_N];

int par_uf [MAX_NODES];
int kru_l  [MAX_NODES];
int kru_r  [MAX_NODES];
ll  kru_val[MAX_NODES];
int tot_nodes;

int find_uf(int x) {
    while (par_uf[x] != x) {
        par_uf[x] = par_uf[par_uf[x]];
        x = par_uf[x];
    }
    return x;
}

int  tarjan_par    [MAX_NODES];
int  tarjan_anc    [MAX_NODES];
char tarjan_visited[MAX_NODES];

int qry_head [MAX_NODES];
int qry_next [2 * MAX_Q];
int qry_other[2 * MAX_Q];
int qry_idx  [2 * MAX_Q];
int qry_count;

void qry_add(int u, int v, int qid) {
    qry_other[qry_count] = v;
    qry_idx  [qry_count] = qid;
    qry_next [qry_count] = qry_head[u];
    qry_head [u]         = qry_count++;
}

int tarjan_find(int x) {
    while (tarjan_par[x] != x) {
        tarjan_par[x] = tarjan_par[tarjan_par[x]];
        x = tarjan_par[x];
    }
    return x;
}

int dfs_stack[MAX_NODES];
int dfs_phase[MAX_NODES];

void tarjan_lca_all(int root) {
    int sp = 0;
    dfs_stack[sp] = root;
    dfs_phase[sp] = 0;
    ++sp;
    while (sp > 0) {
        int u = dfs_stack[sp - 1];
        int p = dfs_phase[sp - 1];
        if (p == 0) {
            tarjan_par[u] = u;
            tarjan_anc[u] = u;
            dfs_phase[sp - 1] = 1;
            if (kru_l[u]) {
                dfs_stack[sp] = kru_l[u];
                dfs_phase[sp] = 0;
                ++sp;
                continue;
            }
            p = 1;
        }
        if (p == 1) {
            if (kru_l[u]) {
                tarjan_par[tarjan_find(kru_l[u])] = u;
                tarjan_anc[tarjan_find(u)] = u;
            }
            dfs_phase[sp - 1] = 2;
            if (kru_r[u]) {
                dfs_stack[sp] = kru_r[u];
                dfs_phase[sp] = 0;
                ++sp;
                continue;
            }
            p = 2;
        }
        if (p == 2) {
            if (kru_r[u]) {
                tarjan_par[tarjan_find(kru_r[u])] = u;
                tarjan_anc[tarjan_find(u)] = u;
            }
            tarjan_visited[u] = 1;
            for (int qe = qry_head[u]; qe != -1; qe = qry_next[qe]) {
                int v = qry_other[qe];
                if (tarjan_visited[v]) {
                    int qid = qry_idx[qe];
                    int la = tarjan_anc[tarjan_find(v)];
                    ll val = kru_val[la];
                    query[qid].ans = (val >= INF) ? -1LL : val;
                }
            }
            --sp;
        }
    }
}

void _qsort(int p, int r) {
    if (p >= r) return;
    int pivot = bridge[(p + r) >> 1].broken_time;
    int lt = p, gt = r, i = p;
    while (i <= gt) {
        if (bridge[i].broken_time > pivot) {
            auto tmp = bridge[lt];
            bridge[lt] = bridge[i];
            bridge[i] = tmp;
            ++lt; ++i;
        } else if (bridge[i].broken_time < pivot) {
            auto tmp = bridge[gt];
            bridge[gt] = bridge[i];
            bridge[i] = tmp;
            --gt;
        } else {
            ++i;
        }
    }
    _qsort(p, lt - 1);
    _qsort(gt + 1, r);
}

void reset_state() {
    tot_nodes = 0;
    qry_count = 0;
}

int main(void) {
    scanf("%d", &t);
    while (t--) {
        reset_state();

        scanf("%d", &n);
        for (int i = 1; i <= n; ++i) {
            int x, y;
            scanf("%d%d", &x, &y);
            building[i].init(x, y);
        }

        scanf("%d", &m);
        for (int i = 0; i < m; ++i) {
            ll l;
            scanf("%d%d%lld", &bridge[i].v1, &bridge[i].v2, &l);
            ll dx = building[bridge[i].v1].x - building[bridge[i].v2].x;
            ll dy = building[bridge[i].v1].y - building[bridge[i].v2].y;
            bridge[i].lb          = l * l - dx * dx - dy * dy;
            bridge[i].broken_time = INF;
        }

        scanf("%d", &k);
        for (int i = 0; i < k; ++i) {
            scanf("%d%d", &winter[i].v, &winter[i].h);
        }

        scanf("%d", &q);
        for (int i = 0; i < q; ++i) {
            scanf("%d%d", &query[i].src, &query[i].dst);
        }

        for (int v = 1; v <= n; ++v) v_evt_cnt[v] = 0;
        for (int i = 0; i < k; ++i) v_evt_cnt[winter[i].v]++;
        v_evt_start[1] = 0;
        for (int v = 1; v <= n; ++v) v_evt_start[v + 1] = v_evt_start[v] + v_evt_cnt[v];

        for (int v = 1; v <= n; ++v) {
            v_evt_cnt[v] = 0;
            temp_z[v]   = 0;
            temp_max[v] = 0;
        }
        for (int i = 0; i < k; ++i) {
            int v = winter[i].v;
            temp_z[v] += winter[i].h;
            ll abs_z = temp_z[v] < 0 ? -temp_z[v] : temp_z[v];
            if (abs_z > temp_max[v]) temp_max[v] = abs_z;
            int idx = v_evt_start[v] + v_evt_cnt[v];
            evt_day[idx] = i;
            evt_z  [idx] = temp_z[v];
            evt_max[idx] = temp_max[v];
            v_evt_cnt[v]++;
        }

        for (int e = 0; e < m; ++e) {
            int u = bridge[e].v1;
            int v = bridge[e].v2;
            ll lb_e = bridge[e].lb;
            int cu = v_evt_cnt[u];
            int cv = v_evt_cnt[v];
            int su = v_evt_start[u];
            int sv = v_evt_start[v];

            if (cu == 0 && cv == 0) continue;

            if (cv == 0) {
                int lo = su, hi = su + cu;
                while (lo < hi) {
                    int mid = (lo + hi) >> 1;
                    ll mval = evt_max[mid];
                    bool broken = (mval > SAFE_BND) || (mval * mval > lb_e);
                    if (broken) hi = mid;
                    else        lo = mid + 1;
                }
                if (lo < su + cu) bridge[e].broken_time = evt_day[lo] + 1;
            } else if (cu == 0) {
                int lo = sv, hi = sv + cv;
                while (lo < hi) {
                    int mid = (lo + hi) >> 1;
                    ll mval = evt_max[mid];
                    bool broken = (mval > SAFE_BND) || (mval * mval > lb_e);
                    if (broken) hi = mid;
                    else        lo = mid + 1;
                }
                if (lo < sv + cv) bridge[e].broken_time = evt_day[lo] + 1;
            } else {
                ll z_u = 0, z_v = 0;
                int pu = su, pv = sv;
                int eu = su + cu, ev = sv + cv;
                while (pu < eu || pv < ev) {
                    int day;
                    if (pu < eu && (pv == ev || evt_day[pu] <= evt_day[pv])) {
                        z_u = evt_z[pu];
                        day = evt_day[pu];
                        pu++;
                    } else {
                        z_v = evt_z[pv];
                        day = evt_day[pv];
                        pv++;
                    }
                    ll diff = z_u - z_v;
                    if (diff * diff > lb_e) {
                        bridge[e].broken_time = day + 1;
                        break;
                    }
                }
            }
        }

        _qsort(0, m - 1);

        for (int i = 1; i <= 2 * n; ++i) par_uf[i] = i;
        for (int i = 1; i <= n;     ++i) kru_l[i] = kru_r[i] = 0;
        tot_nodes = n;

        for (int i = 0; i < m; ++i) {
            int ru = find_uf(bridge[i].v1);
            int rv = find_uf(bridge[i].v2);
            if (ru == rv) continue;
            int w = ++tot_nodes;
            kru_val[w] = bridge[i].broken_time;
            kru_l[w] = ru;
            kru_r[w] = rv;
            par_uf[ru] = w;
            par_uf[rv] = w;
        }

        for (int i = 1; i <= tot_nodes; ++i) {
            qry_head[i] = -1;
            tarjan_visited[i] = 0;
        }
        for (int i = 0; i < q; ++i) {
            qry_add(query[i].src, query[i].dst, i);
            qry_add(query[i].dst, query[i].src, i);
        }
        tarjan_lca_all(tot_nodes);

        ll total = 0;
        for (int i = 0; i < q; ++i) {
            total += (ll)(i + 1) * query[i].ans;
        }
        printf("%lld\n", total);
    }
    return 0;
}
