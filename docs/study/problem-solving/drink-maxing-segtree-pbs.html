1 문제 요약

마트에 \(n\)개의 액체가 있다. \(i\)번 액체는 맛 \(d_i\), 1리터당 가격 \(p_i\), 최대 사용량 \(l_i\) 리터를 가진다.

\(m\)명의 사람이 음료수 한 병씩을 받는다. \(j\)번 사람의 조건은:

  • 사용한 액체 가격 합 \(\le g_j\)
  • 액체 양의 합 \(\ge L_j\) 리터
  • 음료수의 맛(= 사용한 액체들의 맛 중 최솟값)을 최대화

각 사람의 답을 출력. 불가능하면 \(-1\).

Note제약
  • \(1 \le n, m \le 10^5\)
  • \(1 \le d_i, p_i, l_i \le 10^5\)
  • \(1 \le g_j, L_j \le 10^{18}\)

2 핵심 관찰

2.1 임계값 사고

맛이 사용한 액체들의 최솟값으로 정의되니, 어떤 임계값 \(T\)를 정하고 “\(d_i \ge T\)인 액체만 풀로 사용 가능”이라고 보면, 그 풀에서 만든 음료수의 맛은 \(\ge T\). 답은 실현 가능한 가장 큰 \(T\).

ImportantLemma 1 (답 = 최대 임계값)

\[T^* := \max\{T : \{d_i \ge T\} \text{ 풀에서 } (g_j, L_j) \text{ 조건 실현 가능}\}\]

일 때, 정답은 \(T^*\)이다.

증명. \(T = T^*\)에서 최적 부분집합이 \(d_i = T^*\)인 액체를 하나도 안 쓴다고 가정하면, 그 부분집합의 모든 원소가 \(d_i > T^*\)이므로 \(T = T^* + \epsilon\)에서도 실현 가능. 이는 \(T^*\)의 최댓값성에 모순. 따라서 최적 부분집합은 \(d_i = T^*\)인 액체를 적어도 하나 사용하며, 그 부분집합의 맛 최솟값 \(= T^*\). \(\square\)

2.2 단조성

액체를 \(d_i\) 내림차순으로 정렬한 뒤 prefix 크기 \(k\)를 잡는다 (= 임계값을 그 prefix의 최솟값으로 설정한 것과 동치).

ImportantLemma 2 (단조성)

\(k\)가 증가하면 가용 풀이 단조 확장 → \(L\) 리터를 만드는 최소비용은 단조 비증가 → feasibility는 \(k\)에 대해 단조.

따라서 “feasibility를 만족시키는 가장 작은 \(k^*\)”가 존재하면 답 = (정렬된 액체의 \(k^*\)번째 맛), 없으면 \(-1\).

2.3 분수 배낭 그리디

ImportantLemma 3 (그리디 최적성)

고정된 풀에서 \(L\) 리터를 만드는 최소비용은 가격 \(p\)가 작은 것부터 \(l_i\)까지 채워가며 \(L\)에 도달하는 그리디로 얻어진다.

증명 스케치. Exchange argument. 만약 더 비싼 액체를 부분 사용하면서 더 싼 액체를 부분 미사용한 해가 있다면, 둘을 무한소 교환해 비용을 (엄밀히) 줄일 수 있다. \(\square\)

3 자료구조: 가격축 세그먼트 트리

가격 \(p\)가 \([1, P_{\max}]\)의 작은 정수 (\(\le 10^5\))라는 점을 활용해 가격을 인덱스로 하는 세그트리를 만든다. 각 노드 \(v\)는 해당 가격 구간 \([\ell_v, r_v]\)의 활성 액체 통계를 저장:

\[ \begin{aligned} \text{liters}(v) &= \sum_{p \in [\ell_v, r_v]} (\text{가격이 } p \text{인 활성 액체들의 리터 합}) \\ \text{cost}(v) &= \sum_{p \in [\ell_v, r_v]} p \cdot (\text{같은 합}) \end{aligned} \]

3.1 점 업데이트

액체 \((p, l)\) 추가: 인덱스 \(p\) 잎에 \((+l, +pl)\) 누적 후 루트로 합 갱신. \(O(\log P)\).

3.2 최소비용 쿼리 — Descent

질문. 활성 풀에서 \(L\) 리터를 가장 싸게 채우는 비용은?

루트에서 시작해 다음 규칙으로 내려간다:

  1. liters(현재 노드) < L → 풀 전체로도 부족, \(-1\).
  2. 잎(l == r) → 이 가격 \(p (= l)\)로 \(L\) 리터, 비용 \(L \cdot p\).
  3. 좌측 자식의 liters \(\ge L\) → 답이 좌측 안에 있음, 좌측 재귀.
  4. 그렇지 않으면 → 좌측을 통째로 흡수(cost(좌) 누적)하고 남은 \(L - \text{liters(좌)}\)를 우측에서 마저 찾기.

루트에서 잎까지 한 경로만 타니 \(O(\log P)\).

Tip패턴: 세그먼트 트리 위 이분탐색

이 descent는 “\(k\)번째 원소 찾기”, “prefix sum이 \(X\)를 처음 넘는 위치” 같은 류의 일반화. 누적 가능한 양에 대한 임계값 검색이 필요할 때마다 등장하는 도구.

3.3 노드 인덱스와 의미적 구간의 분리

Warning흔한 헷갈림

세그트리 코드의 매개변수 (node, l, r, idx)에서:

  • node: seg[] 배열 안의 위치. 자식 = \(2v, 2v+1\).
  • [l, r]: 그 노드가 의미적으로 책임지는 가격 범위. 재귀 인자로만 추적되며 배열에 저장되지 않는다.
  • l == r은 잎 도달(구간 폭 1로 수렴) 조건. idx == mid와는 무관. 후자는 임의 깊이에서 우연히 성립할 수 있는 국소적 사건이며, 성립해도 종료하지 않는다.

잎에 도달했을 때만 l = r = idx가 성립한다 (재귀가 항상 idx를 포함하는 자식으로 내려가기 때문).

3.4 트리 크기

배열 크기는 \(4P_{\max}\)로 잡는다. 정확히는 노드 인덱스 최댓값이 \(2 \cdot 2^{\lceil \log_2 P_{\max} \rceil}\)까지 갈 수 있어 \(4P_{\max}\)가 안전 상한. \(P_{\max}\)가 2의 거듭제곱이면 \(2P_{\max}\)도 충분하나, 일반화를 위해 \(4P_{\max}\).

4 통합: 병렬 이분탐색

각 쿼리에 대해 prefix 크기 \(k\)를 이분탐색. 단일 세그트리를 공유하기 위해 모든 쿼리의 이분탐색을 동시에 굴린다.

Note알고리즘 골격

쿼리 \(j\)마다 lo[j] = 0, hi[j] = n (sentinel)로 시작.

라운드 반복 (총 \(O(\log n)\)회):

  1. 각 활성 쿼리(lo[j] < hi[j])의 mid를 계산해 bucket[mid]에 push.
  2. 세그트리를 0으로 초기화.
  3. \(k = 0, 1, \ldots, n-1\)로 액체를 맛 내림차순 추가 (점 업데이트).
  4. 각 \(k\) 직후, bucket[k]의 모든 쿼리에 대해 descent 쿼리 → cost와 \(g_j\) 비교 → lo/hi 갱신.

수렴 후, lo[j] == n이면 \(-1\), 아니면 정렬된 액체의 lo[j]번째 맛이 답.

Warning안티패턴

각 \(k\)마다 \(m\)개 쿼리를 전부 순회하며 “내 mid가 \(k\)인가?”를 검사하면 한 라운드가 \(O(nm) = 10^{10}\). 반드시 mid별 버킷에 미리 그룹핑해야 한다.

5 복잡도

\[O\big((n + m) \cdot \log n \cdot \log P\big) \approx 10^5 \cdot 17 \cdot 17 \approx 3 \times 10^7\]

6 함정 모음

Warning1. 타입 절단 (정답성)

\(L_j \le 10^{18}\)이므로 liters 관련 모든 변수와 함수 매개변수를 long long (또는 unsigned long long)으로 둔다. 특히 query 함수의 litter 매개변수가 int로 선언되어 있으면 호출 시 암묵적 절단되어 큰 \(L\)에서 오답.

Warning2. 이분탐색 경계 (정답성)

hi = n - 1로 초기화하면 모든 \(k\)가 infeasible인 경우에도 수렴 후 lo == n - 1이 되어 liq[n-1].d를 잘못 반환할 수 있다. hi = n을 sentinel로 두는 게 안전. (혹은 hi = n-1을 유지하면서 마지막에 명시적으로 feasibility 검증.)

Warning3. 정렬 알고리즘 (TLE)

피벗을 항상 마지막 원소로 잡는 quicksort는 정렬된 입력에서 \(O(n^2)\). std::sort 또는 랜덤 피벗 사용.

Warning4. 비용 오버플로 (정답성)

비용은 \(\le n \cdot l_{\max} \cdot p_{\max} = 10^5 \cdot 10^5 \cdot 10^5 = 10^{15}\). long long 충분. 다만 liters 측에서 \(L_j\)가 \(10^{18}\)까지 들어오므로 비교는 long long 또는 unsigned long long로.

루트의 liters < L 체크로 $L > $ 풀 총량 케이스를 즉시 infeasible로 거른다.

Warning5. 출력 포맷

“마지막 정수 끝에 공백 금지”. 첫 토큰 앞에 공백을 붙이는 패턴이 안전.

for (int j = 0; j < m; ++j) {
    if (j > 0) putchar(' ');
    printf("%d", ans[j]);
}
putchar('\n');

7 대안: Persistent Segment Tree

병렬 이분탐색은 매 라운드 세그트리를 재구축하므로 업데이트 측이 \(O(n \log n \log P)\). 이를 한 번의 빌드로 줄이려면 영속 세그트리 사용:

  • 액체를 맛 내림차순으로 한 번만 sweep, 매 추가마다 새 버전 생성.
  • 각 버전은 변경되지 않은 노드를 이전 버전과 공유, 새 노드 \(O(\log P)\)개씩만 생성.
  • 빌드 \(O(n \log P)\), 메모리 \(O(n \log P)\).
  • 각 쿼리는 독립적으로 prefix 크기에 대해 이분탐색하며 해당 버전에 descent → \(O(m \log n \log P)\).
측면 병렬 BS Persistent SegTree
빌드 \(O(n \log n \log P)\) \(O(n \log P)\)
쿼리 \(O(m \log n \log P)\) \(O(m \log n \log P)\)
메모리 \(O(P)\) \(O(n \log P)\)
코드 길이 짧음 김
캐시 / 상수 좋음 나쁨

전체 점근은 같지만 메모리와 구현 난이도에서 트레이드오프. 단순함이 보통 우선이라 병렬 BS가 더 자주 채택된다.

8 Codes

#include <bits/stdc++.h>
using namespace std;
typedef long long ll;

const int MAXP = 100001;  // prices in [1, MAXP-1]

struct Node {
    ll liters;
    ll cost;
};
Node seg[4 * MAXP];

void update(int node, int l, int r, int idx, ll dl) {
    if (l == r) {
        seg[node].liters += dl;
        seg[node].cost   += dl * (ll)l;   // l == price at the leaf
        return;
    }
    int mid = (l + r) >> 1;
    if (idx <= mid) {
        update(node << 1, l, mid, idx, dl);
    } else {
        update(node << 1 | 1, mid + 1, r, idx, dl);
    }
    seg[node].liters = seg[node << 1].liters + seg[node << 1 | 1].liters;
    seg[node].cost   = seg[node << 1].cost   + seg[node << 1 | 1].cost;
}

// min cost to obtain exactly L liters from active liquids; -1 if pool insufficient
ll query(int node, int l, int r, ll L) {
    if (seg[node].liters < L) {
        return -1;
    }
    if (l == r) {
        return L * (ll)l;
    }
    int mid = (l + r) >> 1;
    if (seg[node << 1].liters >= L) {
        return query(node << 1, l, mid, L);
    } else {
        return seg[node << 1].cost
             + query(node << 1 | 1, mid + 1, r, L - seg[node << 1].liters);
    }
}

int main() {
    int TC;
    scanf("%d", &TC);
    while (TC--) {
        int n, m;
        scanf("%d %d", &n, &m);

        vector<array<int, 3>> liq(n);  // {d, p, l}
        for (int i = 0; i < n; ++i) {
            scanf("%d %d %d", &liq[i][0], &liq[i][1], &liq[i][2]);
        }
        sort(liq.begin(), liq.end(),
             [](const array<int,3>& a, const array<int,3>& b) {
                 return a[0] > b[0];   // taste descending
             });

        vector<ll> G(m), L(m);
        for (int j = 0; j < m; ++j) {
            scanf("%lld %lld", &G[j], &L[j]);
        }

        // Binary search: smallest k in [0, n-1] s.t. feasible(top-(k+1)).
        // hi = n is the "infeasible" sentinel.
        vector<int> lo(m, 0), hi(m, n);

        while (true) {
            vector<vector<int>> bucket(n + 1);
            bool active = false;
            for (int j = 0; j < m; ++j) {
                if (lo[j] < hi[j]) {
                    int mid = (lo[j] + hi[j]) >> 1;
                    bucket[mid].push_back(j);
                    active = true;
                }
            }
            if (!active) {
                break;
            }

            memset(seg, 0, sizeof(seg));

            for (int k = 0; k < n; ++k) {
                int p   = liq[k][1];
                int lit = liq[k][2];
                update(1, 1, MAXP - 1, p, lit);

                for (int j : bucket[k]) {
                    ll c = query(1, 1, MAXP - 1, L[j]);
                    if (c != -1 && c <= G[j]) {
                        hi[j] = k;
                    } else {
                        lo[j] = k + 1;
                    }
                }
            }
        }

        for (int j = 0; j < m; ++j) {
            if (j > 0) {
                putchar(' ');
            }
            int k = lo[j];
            if (k >= n) {
                printf("-1");
            } else {
                printf("%d", liq[k][0]);
            }
        }
        putchar('\n');
    }
    return 0;
}
