Heap and Heapsort Summary

Published

March 29, 2026

1 Heap as a Complete Binary Tree

1.1 Heap의 구조

Binary heap은 배열로 표현하는 nearly complete binary tree이다. 완전 이진 트리처럼 모든 레벨이 꽉 차되, 마지막 레벨만 비어 있을 수 있고 이때도 왼쪽부터 채워진다.

배열 \(A\)는 다음 두 속성을 가진다.

  • \(A.\mathrm{length}\): 배열 전체 길이
  • \(A.\mathrm{heap\text{-}size}\): 현재 heap에 포함된 원소 수

유효한 heap 원소는 \(A[1..A.\mathrm{heap\text{-}size}]\)에만 들어 있다.

1.2 배열 인덱스와 트리의 대응

1-based indexing을 쓰면,

\[ \mathrm{LEFT}(i)=2i, \qquad \mathrm{RIGHT}(i)=2i+1, \qquad \mathrm{PARENT}(i)=\left\lfloor \frac{i}{2} \right\rfloor. \]

즉, heap은 포인터 없이도 배열만으로 부모/자식 관계를 계산할 수 있다.

1.3 Height의 정의

어떤 노드의 height는 그 노드에서 leaf까지 내려가는 가장 긴 단순 경로의 간선 수이다. 힙 전체의 높이는 루트의 height이다.

heap은 complete binary tree 기반이므로, 원소 수가 \(n\)일 때 전체 높이는

\[ O(\lg n) \]

이다.

1.3.1 직관

높이가 \(h\)인 완전 이진 트리의 노드 수는 대략

\[ 1+2+4+\cdots+2^h = 2^{h+1}-1 \]

이므로,

\[ n \approx 2^{h+1}-1 \quad\Longrightarrow\quad h = \Theta(\lg n). \]

2 Min-Heap and Max-Heap

2.1 Min-Heap

Min-heap에서는 모든 비루트 노드 \(i\)에 대해

\[ A[\mathrm{PARENT}(i)] \le A[i] \]

가 성립한다.

2.2 Max-Heap

Max-heap에서는 모든 비루트 노드 \(i\)에 대해

\[ A[\mathrm{PARENT}(i)] \ge A[i] \]

가 성립한다.

Heapsort는 보통 max-heap을 사용한다. 이유는 최대 원소를 항상 루트 \(A[1]\)에서 즉시 꺼낼 수 있기 때문이다.

3 MAX-HEAPIFY

3.1 함수가 맡는 일

\(\mathrm{MAX\text{-}HEAPIFY}(A,i)\)는 다음 전제에서 동작한다.

  • \(\mathrm{LEFT}(i)\)를 루트로 하는 서브트리는 이미 max-heap
  • \(\mathrm{RIGHT}(i)\)를 루트로 하는 서브트리도 이미 max-heap
  • 단, 현재 \(A[i]\)만 max-heap property를 위반할 수 있음

즉, 두 자식 서브트리는 이미 정상이고 현재 루트만 문제일 수 있을 때, \(A[i]\)의 값을 아래로 내려 보내며 subtree rooted at \(i\) 전체를 다시 max-heap으로 만든다.

3.2 Pseudocode

MAX-HEAPIFY(A, i)
1.  L = LEFT(i)
2.  R = RIGHT(i)
3.  if L <= A.heap-size and A[L] > A[i]
4.      largest = L
5.  else largest = i
6.  if R <= A.heap-size and A[R] > A[largest]
7.      largest = R
8.  if largest != i
9.      exchange A[i] with A[largest]
10.     MAX-HEAPIFY(A, largest)

3.3 핵심 아이디어: float down / sift down

현재 노드와 두 자식을 비교하여 가장 큰 값을 위로 두고, 현재 노드의 값이 더 작다면 더 큰 자식과 swap한다. 그 결과 내려간 값이 다시 아래쪽에서 heap property를 위반할 수 있으므로, 한 단계 아래에서 같은 과정을 반복한다.

3.4 왜 한 경로만 따라 내려가나?

한 번 호출할 때마다 실제 재귀는 두 자식 모두로 내려가는 것이 아니라, 더 큰 자식이 있는 한쪽 경로로만 내려간다. 이 점이 시간복잡도 분석의 핵심이다.

3.5 시간복잡도: \(O(h)\) vs \(O(\lg n)\)

노드 \(i\)의 height를 \(h\)라고 하자. \(\mathrm{MAX\text{-}HEAPIFY}(A,i)\)는 한 번 재귀할 때마다 최대 한 레벨씩 내려가며, 많아야 leaf까지 \(h\)번 이동할 수 있다. 따라서

\[ \mathrm{MAX\text{-}HEAPIFY}(A,i)=O(h). \]

한편, 원소 수가 \(n\)인 heap 전체의 높이는 \(\lfloor \lg n \rfloor\)이므로, 어떤 노드의 height도 이를 넘지 않는다. 즉,

\[ h \le \lfloor \lg n \rfloor. \]

따라서 최악의 경우에는

\[ \mathrm{MAX\text{-}HEAPIFY}(A,i)=O(\lg n) \]

이라고 써도 맞다.

따라서 다음 두 표현은 모두 맞다.

  • 어떤 노드의 height가 \(h\)이면: \(\mathrm{MAX\text{-}HEAPIFY}=O(h)\)
  • heap 원소 수가 \(n\)일 때 worst case: \(\mathrm{MAX\text{-}HEAPIFY}=O(\lg n)\)

3.5.1 자주 헷갈리는 포인트

\(O(h)\)는 더 정밀한 표현이고, \(O(\lg n)\)은 heap 전체 기준의 최악 경우 상한이다. 서로 모순되지 않는다.

3.6 Why does the recurrence use \(2n/3\)?

교안에서는 subtree rooted at \(i\)의 크기를 \(n\)이라고 했을 때,

\[ T(n) \le T(2n/3) + \Theta(1) \]

라고 분석한다.

이 의미는 다음과 같다.

  • \(\mathrm{MAX\text{-}HEAPIFY}\)는 현재 노드와 두 자식의 관계를 고치는 데 \(\Theta(1)\) 시간이 든다.
  • 그 후 많아야 한 자식의 서브트리로만 재귀한다.
  • complete binary tree 구조 때문에, 한 자식 서브트리의 크기는 최대 \(2n/3\) 정도로 상한을 둘 수 있다.

따라서 재귀식은

\[ T(n) \le T(2n/3)+\Theta(1) \]

이 되고, 이는

\[ T(n)=O(\lg n) \]

을 준다.

3.6.1 직관

heap은 complete binary tree라서 한쪽 자식 서브트리가 전체의 거의 전부를 차지할 수 없다. 즉, 재귀할 때마다 문제 크기가 적어도 일정 비율만큼 줄어들므로 깊이는 logarithmic이다.

4 BUILD-MAX-HEAP

4.1 Bottom-up construction

배열 전체를 한 번에 max-heap으로 바꾸는 알고리즘은 다음과 같다.

BUILD-MAX-HEAP(A)
1. A.heap-size = A.length
2. for i = floor(A.length/2) downto 1
3.     MAX-HEAPIFY(A, i)

왜 \(\lfloor n/2 \rfloor\)부터 시작할까?

  • 인덱스 \(\lfloor n/2 \rfloor + 1\)부터 \(n\)까지는 모두 leaf이다.
  • leaf는 이미 trivial max-heap이다.
  • 따라서 마지막 internal node부터 위로 올라가며 heapify하면 된다.

4.2 Correctness via Loop Invariant

교안의 핵심 정당화는 loop invariant이다.

4.2.1 Loop Invariant

for-loop의 각 반복이 시작될 때, 노드

\[ i+1, i+2, \dots, n \]

은 각각 max-heap의 루트이다.

4.2.2 Initialization

첫 반복 직전 \(i = \lfloor n/2 \rfloor\)이다. 이때

\[ \left\lfloor \frac{n}{2} \right\rfloor + 1, \left\lfloor \frac{n}{2} \right\rfloor + 2, \dots, n \]

은 모두 leaf이다. leaf 하나만 있는 트리는 trivial max-heap이므로 invariant가 성립한다.

4.2.3 Maintenance

반복 시작 시점에 \(i+1, i+2, \dots, n\)이 모두 max-heap의 루트라고 가정하자. 그러면 노드 \(i\)의 두 자식이 존재한다면 그 자식들이 루트인 서브트리는 이미 max-heap이다. 따라서 \(\mathrm{MAX\text{-}HEAPIFY}(A,i)\)를 호출하면 \(i\)를 루트로 하는 subtree도 max-heap이 된다. 그리고 그 외의 노드들의 상태는 망가지지 않는다. 따라서 다음 반복에서도 invariant가 유지된다.

4.2.4 Termination

루프가 종료되면 \(i = 0\)이다. 이 시점에서 invariant에 의해 노드 \(1,2,\dots,n\)이 모두 max-heap의 루트이다. 특히 노드 \(1\)을 루트로 하는 전체 트리가 max-heap이다. 즉, \(\mathrm{BUILD\text{-}MAX\text{-}HEAP}\)은 배열 전체를 올바른 max-heap으로 만든다.

5 Running Time of BUILD-MAX-HEAP

5.1 Simple upper bound

아주 느슨하게 보면,

  • \(\mathrm{MAX\text{-}HEAPIFY}\)를 \(O(n)\)번 호출하고
  • 각 호출이 \(O(\lg n)\)

이라서

\[ O(n \lg n) \]

이라는 상한을 얻을 수 있다.

하지만 이건 tight upper bound가 아니다.

5.2 Why the tighter bound is \(O(n)\)

핵심은 모든 노드에서 heapify 비용이 같지 않다는 점이다.

  • 아래쪽 노드는 height가 작아서 heapify가 거의 안 걸린다.
  • 위쪽 노드는 heapify 비용이 크지만, 그런 노드 수가 매우 적다.

따라서 전체 비용은 단순히 \(n\)개의 노드에 \(\lg n\)을 곱하는 식으로 세면 너무 느슨하다.

5.3 높이별로 비용 세기

height가 \(h\)인 노드 하나에 대해 \(\mathrm{MAX\text{-}HEAPIFY}\) 비용은 \(O(h)\)이다. 그리고 \(n\)-element heap에서 height가 \(h\)인 노드 수는 많아야

\[ \left\lceil \frac{n}{2^{h+1}} \right\rceil \]

개이다.

따라서 전체 비용은

\[ \sum_{h=0}^{\lfloor \lg n \rfloor} \left\lceil \frac{n}{2^{h+1}} \right\rceil O(h) \]

로 쓸 수 있다.

이제

\[ \left\lceil x \right\rceil \le x+1 \]

을 이용하면

\[ \sum_{h=0}^{\lfloor \lg n \rfloor} \left\lceil \frac{n}{2^{h+1}} \right\rceil O(h) \le \sum_{h=0}^{\lfloor \lg n \rfloor} \left(\frac{n}{2^{h+1}}+1\right)O(h). \]

이를 나누어 보면

\[ O\left(n \sum_{h=0}^{\lfloor \lg n \rfloor} \frac{h}{2^h}\right) + O\left(\sum_{h=0}^{\lfloor \lg n \rfloor} h\right). \]

둘째 항은

\[ O((\lg n)^2) \]

이다.

첫째 항에서는 급수

\[ \sum_{h=0}^{\infty} \frac{h}{2^h} \]

가 상수로 수렴한다는 사실이 중요하다. 실제로

\[ \sum_{h=0}^{\infty} \frac{h}{2^h} = 2. \]

따라서 첫째 항은

\[ O(n) \]

이다.

또한

\[ (\lg n)^2 = o(n) \]

이므로,

\[ O(n)+O((\lg n)^2)=O(n). \]

결론적으로

\[ \mathrm{BUILD\text{-}MAX\text{-}HEAP}(A)=O(n). \]

5.4 Another intuitive analysis (complete tree case)

교안에는 \(n = 2^H - 1\)인 complete tree를 가정한 또 다른 분석도 있다.

  • height \(H\)에 노드 1개, 비용 \(H\)
  • height \(H-1\)에 노드 2개, 각 비용 \(H-1\)
  • height \(H-2\)에 노드 4개, 각 비용 \(H-2\)
  • \(\cdots\)

따라서 총 비용은

\[ S = H + 2(H-1) + 2^2(H-2) + \cdots + 2^{H-1}\cdot 1. \]

이 식을 정리하면 교안처럼 최종적으로 \(2n\) 정도의 상한으로 묶을 수 있어, 역시 선형시간이 나온다. 이 분석의 핵심 직관도 동일하다.

비싼 노드는 적고, 싼 노드는 많다.

6 Heapsort

6.1 알고리즘 개요

Heapsort는 두 단계로 이해하면 쉽다.

  1. \(\mathrm{BUILD\text{-}MAX\text{-}HEAP}(A)\)로 배열을 max-heap으로 만든다.
  2. 루트의 최대값을 맨 뒤로 보내고, 줄어든 heap에 대해 다시 \(\mathrm{MAX\text{-}HEAPIFY}(A,1)\)를 수행한다.

이를 heap size가 2가 될 때까지 반복한다.

6.2 Pseudocode

HEAPSORT(A)
1. BUILD-MAX-HEAP(A)
2. for i = A.length downto 2
3.     exchange A[1] with A[i]
4.     A.heap-size = A.heap-size - 1
5.     MAX-HEAPIFY(A, 1)

6.3 왜 정렬이 되나?

각 반복에서 루트 \(A[1]\)는 현재 heap 구간에서 최대값이다. 이를 \(A[i]\)와 교환하면 해당 최대값이 정렬된 최종 위치로 간다. 그 뒤 heap size를 1 줄이면, 앞으로의 heap 연산은 아직 정렬되지 않은 앞부분에 대해서만 수행된다. 이 과정을 반복하면 뒤에서부터 큰 값들이 차례대로 확정되어 전체 배열이 오름차순으로 정렬된다.

6.4 시간복잡도

Heapsort 전체 시간은

  • \(\mathrm{BUILD\text{-}MAX\text{-}HEAP}\): \(O(n)\)
  • \(n-1\)번의 \(\mathrm{MAX\text{-}HEAPIFY}(A,1)\): 각 \(O(\lg n)\)

이므로,

\[ O(n) + (n-1)O(\lg n) = O(n\lg n). \]

6.4.1 자주 하는 오해

\(\mathrm{BUILD\text{-}MAX\text{-}HEAP}\)이 \(O(n)\)이라고 해서 heapsort 전체가 \(O(n)\)인 것은 아니다. 정렬 단계에서 최대값 추출과 heapify를 거의 \(n\)번 반복하므로 전체는 여전히

\[ O(n\lg n) \]

이다.

7 In-memory / In-place 관점

Heapsort는 보통 in-memory sorting으로 분류한다. 즉, 배열이 RAM 안에 있다고 보고 그 배열 내부에서 직접 정렬한다. 또한 추가 배열을 거의 쓰지 않으므로 in-place sorting이기도 하다.

Merge sort와 비교하면,

  • 둘 다 시간복잡도는 \(O(n\lg n)\)
  • 하지만 heapsort는 보통 \(O(1)\) extra space로 구현 가능
  • merge sort는 전형적으로 \(O(n)\) 추가 공간이 필요

8 Priority Queue Operations on a Max-Heap

Heap은 정렬뿐 아니라 priority queue 구현에도 매우 중요하다.

8.1 HEAP-MAXIMUM

HEAP-MAXIMUM(A)
1. return A[1]

최대값은 루트에 있으므로 \(O(1)\)이다.

8.2 HEAP-EXTRACT-MAX

HEAP-EXTRACT-MAX(A)
1. if A.heap-size < 1
2.     error "heap underflow"
3. max = A[1]
4. A[1] = A[A.heap-size]
5. A.heap-size = A.heap-size - 1
6. MAX-HEAPIFY(A, 1)
7. return max

루트의 최대값을 제거하고 마지막 원소를 루트로 올린 뒤, \(\mathrm{MAX\text{-}HEAPIFY}\)로 max-heap property를 복구한다. 시간복잡도는 \(O(\lg n)\)이다.

8.3 HEAP-INCREASE-KEY

HEAP-INCREASE-KEY(A, i, key)
1. if key < A[i]
2.     error "new key is smaller than current key"
3. A[i] = key
4. while i > 1 and A[PARENT(i)] < A[i]
5.     exchange A[i] with A[PARENT(i)]
6.     i = PARENT(i)

키 값을 증가시키면 부모보다 커질 수 있으므로, 이번에는 아래가 아니라 위로 올라가며 heap property를 회복한다. 즉, \(\mathrm{MAX\text{-}HEAPIFY}\)가 sift-down이라면, 이 연산은 sift-up이라고 볼 수 있다. 시간복잡도는 \(O(\lg n)\)이다.

8.4 MAX-HEAP-INSERT

MAX-HEAP-INSERT(A, key)
1. A.heap-size = A.heap-size + 1
2. A[A.heap-size] = -infinity
3. HEAP-INCREASE-KEY(A, A.heap-size, key)

맨 뒤에 아주 작은 값을 임시로 넣고, \(\mathrm{HEAP\text{-}INCREASE\text{-}KEY}\)로 적절한 위치까지 위로 올린다. 역시 \(O(\lg n)\)이다.

9 핵심 개념 한 번에 정리

9.1 꼭 기억할 것들

  • Heap은 complete binary tree를 배열로 표현한 자료구조이다.
  • \(\mathrm{LEFT}(i)=2i\), \(\mathrm{RIGHT}(i)=2i+1\), \(\mathrm{PARENT}(i)=\lfloor i/2 \rfloor\).
  • Max-heap에서는 부모가 자식보다 크거나 같다.
  • \(\mathrm{MAX\text{-}HEAPIFY}\)는 두 자식 서브트리가 이미 max-heap이라는 가정 아래, 현재 루트만 어긋난 상황을 복구한다.
  • \(\mathrm{MAX\text{-}HEAPIFY}(A,i)\)의 시간은 노드 height가 \(h\)이면 \(O(h)\)이고, worst case로는 \(O(\lg n)\)이다.
  • \(\mathrm{BUILD\text{-}MAX\text{-}HEAP}\)은 bottom-up으로 진행하며 loop invariant로 correctness를 증명할 수 있다.
  • \(\mathrm{BUILD\text{-}MAX\text{-}HEAP}\)의 tight upper bound는 \(O(n)\)이다.
  • 그러나 Heapsort 전체는 \(O(n\lg n)\)이다.
  • Heapsort는 in-memory, in-place sorting algorithm이다.
  • Max-heap은 priority queue 연산도 효율적으로 지원한다.

9.2 자주 혼동하는 문장들

9.2.1 “MAX-HEAPIFY with a node of height h takes O(h) time”

이 말은 특정 노드 \(i\)의 높이가 \(h\)일 때, 그 노드에서 시작한 heapify 비용이 \(O(h)\)라는 뜻이다.

9.2.2 “MAX-HEAPIFY takes O(lg n) time”

이 말은 heap 전체 크기가 \(n\)일 때, 최악의 경우 루트에서 시작하면 heap 높이만큼 내려갈 수 있으므로 \(O(\lg n)\)이라는 뜻이다.

9.2.3 “BUILD-MAX-HEAP is O(n)”

높이별 노드 수와 각 높이의 heapify 비용을 가중합하면 선형시간이 된다.

9.2.4 “Heapsort is O(n)”

아니다. Build 단계만 \(O(n)\)이고, 정렬 단계의 반복 heapify 때문에 전체는 \(O(n\lg n)\)이다.

10 시험 답안용 표현 모음

10.1 BUILD-MAX-HEAP correctness

Loop invariant: At the start of each iteration, each node \(i+1, i+2, \dots, n\) is the root of a max-heap. Initialization holds because all such nodes are leaves initially. Maintenance follows since the children of node \(i\) are already roots of max-heaps, so \(\mathrm{MAX\text{-}HEAPIFY}(A,i)\) makes the subtree rooted at \(i\) a max-heap. At termination, node \(1\) becomes the root of a max-heap, so the entire array represents a max-heap.

10.2 BUILD-MAX-HEAP running time

A node of height \(h\) costs \(O(h)\) under \(\mathrm{MAX\text{-}HEAPIFY}\), and the number of nodes of height \(h\) is at most \(\lceil n/2^{h+1} \rceil\). Hence,

\[ \sum_{h=0}^{\lfloor \lg n \rfloor} \left\lceil \frac{n}{2^{h+1}} \right\rceil O(h) = O(n). \]

10.3 absorbing the lower-order term

Also, \((\lg n)^2 = o(n)\), so \(O((\lg n)^2)\) is absorbed into \(O(n)\).

11 마무리

Chapter 6의 핵심은 단순히 heapsort 절차를 외우는 것이 아니라,

  • heap의 구조를 배열 인덱스와 연결해서 이해하고,
  • \(\mathrm{MAX\text{-}HEAPIFY}\)의 전제와 작동 방식을 정확히 이해하며,
  • \(\mathrm{BUILD\text{-}MAX\text{-}HEAP}\)의 정당성과 tight running time을 증명할 수 있고,
  • heapsort와 priority queue 응용까지 연결하는 것

에 있다.

이 축이 정리되면, heap 관련 문제에서 거의 모든 질문을 같은 원리로 설명할 수 있다.
