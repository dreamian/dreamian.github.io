Four Problem-Solving Paradigms: Divide-and-Conquer, Incremental, Dynamic Programming, and Greedy

알고리즘 문제 해결에서 divide-and-conquer, incremental approach, dynamic programming, greedy의 핵심 property와 차이를 간단히 비교 정리한 노트
Published

March 31, 2026

1 Overview

알고리즘 문제를 풀 때 자주 등장하는 대표적인 접근 방식으로는 다음 네 가지가 있다.

  • Divide-and-Conquer
  • Incremental Approach
  • Dynamic Programming
  • Greedy

이 네 가지는 모두 “큰 문제를 어떻게 구조화해서 풀 것인가”라는 공통 관심사를 가지지만, 문제를 바라보는 방식과 요구하는 성질은 다르다.

이 노트에서는 각 패러다임이 잘 적용되기 위해 기대되는 핵심 property를 간단히 정리한다.

2 Divide-and-Conquer

2.1 핵심 아이디어

문제를 더 작은 subproblem으로 나누고, 각 subproblem을 푼 뒤, 그 결과를 합쳐서 원래 문제의 답을 구한다.

2.2 잘 맞는 property

  • Self-similarity: 부분문제가 원래 문제와 같은 형태여야 한다.
  • Efficient combine: 부분문제의 해를 이용해 원래 문제의 해를 효율적으로 구성할 수 있어야 한다.
  • Relative independence of subproblems: 부분문제들이 서로 강하게 얽혀 있지 않아야 한다.

2.3 직관

핵심 질문은 다음과 같다.

문제를 쪼갰을 때, 각 조각이 여전히 같은 종류의 문제인가?

2.4 examples

  • Merge Sort
  • Quick Sort
  • Binary Search
  • Closest Pair of Points

3 Incremental Approach

3.1 핵심 아이디어

작은 입력에서 시작해서, 원소를 하나씩 추가하면서 기존 해를 갱신한다.

3.2 잘 맞는 property

  • Extendability: 크기 (n)의 해로부터 크기 (n+1)의 해를 확장할 수 있어야 한다.
  • Local updateability: 전체를 다시 풀지 않고 국소 수정만으로 해를 갱신할 수 있어야 한다.
  • Invariant maintainability: 각 단계에서 유지해야 하는 invariant가 있어야 한다.

3.3 직관

핵심 질문은 다음과 같다.

원소 하나가 추가되었을 때, 기존 답을 조금만 고쳐서 새 답을 만들 수 있는가?

3.4 examples

  • Insertion Sort
  • Incremental Convex Hull
  • BST insertion
  • 일부 자료구조 유지 문제

4 Dynamic Programming

4.1 핵심 아이디어

문제를 더 작은 subproblem들로 나누되, 같은 subproblem이 반복해서 등장하면 그 답을 저장하여 재사용한다.

4.2 잘 맞는 property

  • Optimal substructure: 원문제의 최적해가 부분문제의 최적해로부터 구성되어야 한다.
  • Overlapping subproblems: 같은 부분문제가 여러 번 반복해서 등장해야 한다.
  • Compact state representation: 과거의 핵심 정보를 작은 state로 요약할 수 있어야 한다.

4.3 직관

핵심 질문은 다음과 같다.

부분문제가 반복해서 나오고, 그 답을 저장해 두면 큰 이득이 있는가?

4.4 examples

  • Fibonacci
  • Longest Common Subsequence (LCS)
  • Edit Distance
  • Knapsack
  • Matrix Chain Multiplication

5 Greedy

5.1 핵심 아이디어

각 단계에서 현재 시점에 가장 좋아 보이는 선택을 하고, 그 선택들을 쌓아 전체 해를 만든다.

5.2 잘 맞는 property

  • Greedy-choice property: 현재의 locally optimal choice가 전체 최적해의 일부가 될 수 있어야 한다.
  • Optimal substructure: 한 번 좋은 선택을 한 뒤, 남은 부분문제도 같은 의미의 최적화 문제로 남아야 한다.
  • Irrevocability tolerance: 한 번 내린 선택을 되돌리지 않아도 전체 최적성이 유지되어야 한다.

5.3 직관

핵심 질문은 다음과 같다.

지금 가장 좋아 보이는 선택을 해도, 나중에 후회하지 않는가?

5.4 examples

  • Activity Selection
  • Huffman Coding
  • Kruskal’s Algorithm
  • Prim’s Algorithm
  • Dijkstra’s Algorithm (nonnegative edge weights)

6 Four-way comparison

Paradigm 핵심 관점 중요한 property 대표 질문
Divide-and-Conquer 나누고 푼 뒤 합친다 self-similarity, efficient combine 쪼개면 같은 문제인가?
Incremental 하나씩 추가하며 갱신한다 extendability, local updateability, invariant maintainability 하나 추가해도 조금만 고치면 되나?
Dynamic Programming 겹치는 subproblem을 저장해 재사용한다 optimal substructure, overlapping subproblems, compact state 반복되는 부분문제가 있나?
Greedy 매 단계 최선처럼 보이는 선택을 한다 greedy-choice property, optimal substructure 지금 최선의 선택이 전체에도 좋은가?

7 Common confusion points

7.1 Divide-and-Conquer vs Dynamic Programming

둘 다 subproblem을 만든다는 점은 비슷하지만, 가장 큰 차이는 overlap이다.

  • Divide-and-Conquer: 부분문제가 보통 겹치지 않는다.
  • Dynamic Programming: 부분문제가 많이 겹친다.

예를 들어 Merge Sort는 Divide-and-Conquer이고, LCS는 Dynamic Programming이다.

7.2 Incremental vs Dynamic Programming

둘 다 작은 것으로부터 큰 것으로 간다는 느낌이 있지만, 관점이 다르다.

  • Incremental: 실제 입력 원소를 하나씩 추가하면서 구조를 유지한다.
  • Dynamic Programming: 상태 공간에서 작은 state부터 큰 state로 값을 계산한다.

Insertion Sort는 Incremental이고, Knapsack은 Dynamic Programming이다.

7.3 Greedy vs Dynamic Programming

둘 다 최적화 문제에 많이 등장하지만, 차이는 선택을 되돌릴 수 있느냐에 있다.

  • Greedy: 현재 선택이 항상 안전해야 한다.
  • Dynamic Programming: 여러 가능성을 상태로 보존하면서 비교할 수 있다.

Greedy는 빠르고 간단하지만, greedy-choice property가 성립하지 않으면 틀릴 수 있다.

8 How to recognize which paradigm fits

문제를 처음 봤을 때는 아래 질문들을 차례로 던져 보면 도움이 된다.

  1. 문제를 같은 형태의 작은 문제들로 자연스럽게 쪼갤 수 있는가?
    • 그렇다면 Divide-and-Conquer를 고려할 수 있다.
  2. 입력을 하나씩 추가하면서 기존 답을 조금만 수정해 유지할 수 있는가?
    • 그렇다면 Incremental approach를 고려할 수 있다.
  3. 부분문제가 반복해서 등장하고, 그 답을 저장하면 큰 이득이 있는가?
    • 그렇다면 Dynamic Programming을 고려할 수 있다.
  4. 매 단계의 locally optimal choice가 전체 최적해로 이어진다는 근거가 있는가?
    • 그렇다면 Greedy를 고려할 수 있다.

9 Final summary

각 패러다임을 한 줄로 요약하면 다음과 같다.

  • Divide-and-Conquer: 같은 형태의 작은 문제로 나누고, 푼 뒤 합친다.
  • Incremental: 기존 해를 유지한 채 입력을 하나씩 확장한다.
  • Dynamic Programming: 겹치는 부분문제를 저장하며 최적해를 축적한다.
  • Greedy: 각 단계에서 안전한 최선의 선택을 즉시 확정한다.

문제를 잘 분류하는 가장 좋은 방법은, 정답을 구하는 과정에서

  • “쪼개는 구조”가 중요한지,
  • “점진적 갱신”이 중요한지,
  • “부분문제 재사용”이 중요한지,
  • “현재 선택의 안전성”이 중요한지

를 먼저 보는 것이다.
