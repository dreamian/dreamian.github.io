Note큰 그림

알고리즘 분석에서는 한 컴퓨터에서의 정확한 실행시간보다, 입력 크기 n이 커질 때 실행시간이 어떻게 증가하는지를 더 중요하게 본다.

2 왜 점근적으로 알고리즘을 분석하는가?

알고리즘의 실행시간은 하드웨어 성능, 컴파일러 품질, 구현 방식 같은 여러 요소에 영향을 받는다. 하지만 입력 크기 n이 충분히 커지면, 보통 가장 중요한 것은 알고리즘 자체의 구조다.

그래서 명령어를 하나하나 세어 정확한 시간을 구하기보다는, 실행시간을 함수 T(n)으로 모델링하고 그 증가율을 본다.

Important핵심 직관

n이 커질수록 상수배나 낮은 차수 항보다 지배항(dominant term) 이 훨씬 더 중요해진다.

예를 들어

\frac{1}{2}n^2 - 3n = \Theta(n^2)

라고 쓰는 이유는, 큰 n에서는 n^2 항이 전체 성질을 지배하기 때문이다.

3 점근 표기

3.1 \Theta-표기

다음과 같이 쓴다.

f(n) = \Theta(g(n))

이 뜻은 f(n)이 충분히 큰 n에서 g(n)와 같은 차수로 증가한다는 것이다.

정의는 다음과 같다.

\Theta(g(n)) = \left\{f(n) : \exists c_1,c_2,n_0>0 \text{ such that } 0 \le c_1 g(n) \le f(n) \le c_2 g(n) \text{ for all } n \ge n_0 \right\}

즉, 충분히 큰 n에 대해 f(n)이 g(n)의 두 상수배 사이에 끼워진다는 뜻이다.

3.1.1 예시

3n + 2 = \Theta(n), \qquad 10n^2 + 4n + 2 = \Theta(n^2)

3.2 O-표기

다음과 같이 쓴다.

f(n) = O(g(n))

이 뜻은 g(n)이 f(n)의 점근적 상한이라는 것이다.

정의는 다음과 같다.

O(g(n)) = \left\{f(n) : \exists c,n_0>0 \text{ such that } 0 \le f(n) \le c g(n) \text{ for all } n \ge n_0 \right\}

3.2.1 예시

3n+3 = O(n), \qquad 3n+3 = O(n^2)

둘 다 맞지만, 더 타이트한 상한은 O(n)이다.

3.3 \Omega-표기

다음과 같이 쓴다.

f(n) = \Omega(g(n))

이 뜻은 g(n)이 f(n)의 점근적 하한이라는 것이다.

정의는 다음과 같다.

\Omega(g(n)) = \left\{f(n) : \exists c,n_0>0 \text{ such that } 0 \le c g(n) \le f(n) \text{ for all } n \ge n_0 \right\}

3.3.1 예시

3n+2 = \Omega(n), \qquad 10n^2+4n+2 = \Omega(n^2)

3.4 \Theta, O, \Omega의 관계

아주 중요한 정리는 다음이다.

f(n) = \Theta(g(n)) \iff f(n) = O(g(n)) \text{ and } f(n)=\Omega(g(n))

Tip해석
  • O(g(n)): 위에서 누르는 상한
  • \Omega(g(n)): 아래에서 받쳐주는 하한
  • \Theta(g(n)): 양쪽에서 끼워 정확한 차수를 말함

4 수식 안에서 점근 표기가 어떻게 쓰이는가

점근 표기는 정확한 하위 항을 굳이 밝힐 필요가 없을 때, 어떤 “이름 없는 함수”를 대신 나타내는 기호처럼 쓰일 수 있다.

예를 들어

2n^2 + 3n + 1 = 2n^2 + \Theta(n)

은 3n+1을 \Theta(n)에 속하는 어떤 함수로 묶어 쓴 것이라고 보면 된다.

이건 점화식에서 특히 유용하다.

T(n) = 2T(n/2) + \Theta(n)

에서는 결합 비용의 정확한 상수보다, 그것이 선형이라는 사실이 더 중요하다.

5 Big-Oh의 유용한 성질

다음이 성립한다고 하자.

T_1(n)=O(f(n)), \qquad T_2(n)=O(g(n))

그럼 아래 규칙들을 자주 쓴다.

5.1 합 규칙

T_1(n)+T_2(n)=O(\max(f(n),g(n)))

즉, 더 빨리 증가하는 항이 전체를 지배한다.

예를 들어

n^2+n = O(n^2)

이다.

5.2 곱 규칙

T_1(n)T_2(n)=O(f(n)g(n))

5.3 상수배는 점근적으로 무시한다

O(cf(n)) = O(f(n)) \qquad \text{for } c>0

Warning주의

상수배를 무시하는 것은 점근적 관점에서는 맞지만, 실제로 입력이 작을 때는 상수항 차이가 꽤 크게 작용할 수 있다.

6 대표적인 증가율

자주 보는 증가율은 다음과 같다.

\log n, \quad n, \quad n\log n, \quad n^2, \quad n^3, \quad 2^n

대략적인 크기 비교는

\log n < n < n\log n < n^2 < n^3 < 2^n

이다.

입력이 커질수록 지수시간 알고리즘보다 다항시간 알고리즘이 훨씬 실용적이다.

7 반복문 기반 시간복잡도 분석

7.1 단일 반복문

반복이 n번 일어나고, 각 반복에서 O(1) 작업을 하면 전체는 보통

\Theta(n)

이다.

7.2 이중 반복문

예를 들어

for i = 1 to n
    for j = 1 to n
        constant work

같은 코드는

\Theta(n^2)

시간이 든다.

7.3 순차 실행

앞 블록이 T_1(n), 뒤 블록이 T_2(n) 시간이라면

T(n)=T_1(n)+T_2(n)

이고, 최종 점근 결과는 지배항이 결정한다.

7.4 조건문

if-then-else는 한 경로만 실행되므로 보통

T(n)=\max(T_1(n),T_2(n))

처럼 본다.

8 분할정복

분할정복 알고리즘은 보통 세 단계로 구성된다.

  1. 문제를 더 작은 부분문제로 분할한다.
  2. 부분문제를 재귀적으로 해결한다.
  3. 부분문제의 답을 결합한다.

이 구조는 자연스럽게 점화식(recurrence) 으로 이어진다.

9 점화식이란 무엇인가?

점화식은 어떤 함수를 더 작은 입력에서의 함수값으로 표현한 식 또는 부등식이다.

Note왜 중요한가?

점화식은 재귀 알고리즘과 분할정복 알고리즘의 실행시간을 기술하는 가장 자연스러운 언어다.

9.1 Merge Sort의 점화식

merge sort의 경우

T(1)=1

그리고 n>1일 때

T(n)=2T(n/2)+n

이다.

의미는 다음과 같다.

  • 크기 n/2인 부분문제 두 개를 재귀적으로 풂
  • 두 결과를 합치는 데 선형 시간 n이 듦

9.2 불균등 분할 점화식

크기 2n/3와 n/3으로 나누고 결합 비용이 선형이면

T(n)=T(2n/3)+T(n/3)+\Theta(n)

이다.

9.3 선형 탐색형 점화식

매번 문제 크기를 정확히 1만큼 줄이고 상수 시간만 추가되면

T(n)=T(n-1)+\Theta(1)

이다.

10 점화식을 푸는 방법

점화식을 푸는 방법은 여러 가지가 있다.

  1. brute-force method
  2. substitution method
  3. recursion-tree method
  4. master method

이 노트에서는 특히 앞의 세 가지를 중심으로 설명한다.

11 점화식에서 자주 하는 단순화

실제로는 바닥 함수, 천장 함수, 경계 조건이 더 정확히 들어가야 하는 경우가 많다.

예를 들어 merge sort를 아주 정확히 쓰면 \lfloor n/2 \rfloor, \lceil n/2 \rceil 같은 항이 나오지만, 점근 분석에서는 보통

T(n)=2T(n/2)+n

처럼 단순화한다.

이런 단순화는 보통 최종적인 점근 결과를 바꾸지 않는다.

12 Merge Sort를 brute-force로 풀기

다음을 생각하자.

T(1)=1, \qquad T(n)=2T(n/2)+n

편의를 위해

n=2^k

라고 가정하자.

이제 계속 전개하면

T(n)=2T(n/2)+n

한 번 더 대입하면

T(n)=2\left(2T(n/4)+n/2\right)+n = 4T(n/4)+2n

다시 전개하면

T(n)=4\left(2T(n/8)+n/4\right)+2n = 8T(n/8)+3n

k번 전개하면

T(n)=2^kT\left(\frac{n}{2^k}\right)+kn

이제 n/2^k=1이 되면 2^k=n이고 k=\lg n이므로

T(n)=nT(1)+n\lg n = n+n\lg n

따라서

T(n)=\Theta(n\log n)

이다.

Tip구조적 해석

recursion tree의 각 레벨 비용이 \Theta(n)이고, 그런 레벨이 \Theta(\log n)개 있으므로 전체는 \Theta(n\log n)이 된다.

13 Merge Sort에 대한 또 다른 brute-force 관점

어떤 때는 양변을 n으로 나눠서 망원경 합처럼 보는 것도 유용하다.

\frac{T(n)}{n} = \frac{T(n/2)}{n/2} + 1

이 식을 반복 대입하면 약 \lg n개의 1이 더해지는 구조가 나오고, 결국 다시

T(n)=\Theta(n\log n)

을 얻는다.

14 Substitution Method

substitution method는 두 단계로 생각하면 된다.

  1. 해의 형태를 추측한다.
  2. 그 추측이 맞는지 귀납법으로 증명한다.

14.1 예시: Merge Sort upper bound

다음처럼 추측해보자.

T(n)=O(n\log n)

즉 어떤 상수 c>0에 대해

T(n)\le c n\lg n

을 보이고 싶다.

귀납 가정으로 모든 더 작은 m<n에 대해

T(m)\le c m\lg m

라고 두면,

T(n)=2T(n/2)+n

으로부터

T(n) \le 2\left(c\frac{n}{2}\lg\frac{n}{2}\right)+n

이다.

따라서

T(n) \le c n \lg\frac{n}{2}+n

이고

\lg\frac{n}{2}=\lg n -1

이므로

T(n) \le c n(\lg n -1)+n = c n\lg n - cn + n

이제 c\ge 1이면

-cn+n\le 0

이므로

T(n)\le c n\lg n

이 성립한다. 따라서

T(n)=O(n\log n)

이다.

14.2 Base case의 미묘한 문제

기저를 n=1로 바로 넣으면

T(1) \le c\cdot 1 \cdot \lg 1 = 0

이 되어 말이 안 된다.

14.2.1 어떻게 해결할까?

점근 분석은 충분히 큰 n에 대해서만 관심이 있으므로, 귀납의 시작점을 n=2나 n=3처럼 더 큰 값으로 옮기면 된다.

Warning중요한 교훈

경계 조건 때문에 귀납 증명이 까다로워질 수는 있지만, 보통 최종 점근 결과 자체는 달라지지 않는다.

15 T(n)=T(n-1)+\Theta(1)를 brute-force로 풀기

다음처럼 두자.

T(n)=T(n-1)+c

계속 전개하면

T(n)=T(n-2)+2c

T(n)=T(n-3)+3c

k번 전개하면

T(n)=T(n-k)+kc

이제 k=n-1로 두고, T(1)=d라고 하면

T(n)=T(1)+(n-1)c = d+(n-1)c

따라서

T(n)=\Theta(n)

이다.

Tip왜 선형인가?

매 단계마다 문제 크기가 정확히 1만 줄어드므로 재귀 깊이가 \Theta(n)이다. 따라서 로그가 아니라 선형이 된다.

16 불균등 분할 점화식: 직관과 recursion tree

이제 다음을 생각하자.

T(n)=T(2n/3)+T(n/3)+\Theta(n)

각 노드의 non-recursive cost가 그 노드 크기의 c배라고 생각하자.

16.1 ASCII recursion tree

Level 0
n                               cost = c·n

Level 1
├── 2n/3                        cost = c·(2n/3)
└── n/3                         cost = c·(n/3)

Level 2
├── from 2n/3
│   ├── 4n/9                    cost = c·(4n/9)
│   └── 2n/9                    cost = c·(2n/9)
│
└── from n/3
    ├── 2n/9                    cost = c·(2n/9)
    └── n/9                     cost = c·(n/9)

16.2 왜 각 레벨 비용이 \Theta(n)인가?

Level 1에서는

\frac{2n}{3}+\frac{n}{3}=n

이고, Level 2에서는

\frac{4n}{9}+\frac{2n}{9}+\frac{2n}{9}+\frac{n}{9}=n

이다.

일반적으로 각 부모 노드 크기 m은 2m/3와 m/3으로 나뉘고, 두 자식의 합은 다시 m이다. 따라서 매 레벨에서 부분문제 크기의 총합은 항상 n으로 유지된다.

그래서 각 레벨의 non-recursive cost 총합은

\Theta(n)

이 된다.

16.3 왜 깊이가 여전히 로그인가?

이 부분이 핵심 질문이었다.

트리에서 가장 오래 살아남는 경로는 항상 더 큰 자식을 따라가는 경로다.

n,\ \frac{2n}{3},\ \left(\frac{2}{3}\right)^2n,\ \left(\frac{2}{3}\right)^3n,\ \dots

깊이 h에서 가장 큰 부분문제 크기는

n\left(\frac{2}{3}\right)^h

이다.

재귀는 이 값이 1 정도가 되면 멈추므로

n\left(\frac{2}{3}\right)^h \approx 1

을 푼다.

그러면

\left(\frac{2}{3}\right)^h \approx \frac{1}{n}

이고, 로그를 취하면

h \approx \frac{\log n}{\log(3/2)}

이므로

h=\Theta(\log n)

이다.

Important핵심 직관

가장 큰 부분문제가 매 단계마다 1보다 작은 어떤 고정 비율로 줄어들기만 하면, 재귀 깊이는 로그가 된다.

  • n \to n/2 \to n/4 \to \cdots 는 로그 깊이
  • n \to (2/3)n \to (2/3)^2 n \to \cdots 도 로그 깊이
  • n \to n-1 \to n-2 \to \cdots 는 선형 깊이

16.4 recursion tree로 본 전체 비용

  • 각 레벨 비용은 \Theta(n)
  • 레벨 수는 \Theta(\log n)

따라서

T(n)=\Theta(n\log n)

이다.

17 불균등 분할 점화식의 조금 더 엄밀한 증명

이제 다음 점화식을 조금 더 수학적으로 보자.

T(n)=T(2n/3)+T(n/3)+\Theta(n)

이 해가

T(n)=\Theta(n\log n)

임을 upper bound와 lower bound로 나누어 보인다.

\Theta(n) 항에 대해 어떤 상수 c_1,c_2>0가 존재해서 충분히 큰 n에 대해

T(2n/3)+T(n/3)+c_1 n \le T(n) \le T(2n/3)+T(n/3)+c_2 n

이라고 하자.

작은 n에 대해서는 상수로 처리할 수 있다고 보고 진행한다.

17.1 Upper bound: T(n)=O(n\log n)

다음을 귀납적으로 증명하자.

T(n)\le A n\log n + Bn

적절한 상수 A,B>0를 잡고 점화식을 대입하면

T(n)\le A\frac{2n}{3}\log\frac{2n}{3}+B\frac{2n}{3} + A\frac{n}{3}\log\frac{n}{3}+B\frac{n}{3}+c_2 n

이다.

항들을 정리하면

T(n)\le A n\log n + A n\left(\frac{2}{3}\log\frac{2}{3}+\frac{1}{3}\log\frac{1}{3}\right)+Bn+c_2 n

여기서

\delta = -\left(\frac{2}{3}\log\frac{2}{3}+\frac{1}{3}\log\frac{1}{3}\right) > 0

라고 두면,

T(n)\le A n\log n -A\delta n +Bn+c_2 n

이제 A를 충분히 크게 잡아

A\delta \ge c_2

가 되게 하면

-A\delta n + c_2 n \le 0

이므로

T(n)\le A n\log n + Bn

이 성립한다. 따라서

T(n)=O(n\log n)

이다.

17.2 Lower bound: T(n)=\Omega(n\log n)

이번에는 다음을 귀납적으로 보이자.

T(n)\ge A' n\log n - B'n

점화식의 하한을 대입하면

T(n)\ge A'\frac{2n}{3}\log\frac{2n}{3}-B'\frac{2n}{3} + A'\frac{n}{3}\log\frac{n}{3}-B'\frac{n}{3}+c_1 n

이고, 정리하면

T(n)\ge A' n\log n -A'\delta n - B'n + c_1 n

이다.

이 식은 적절한 상수 B''에 대해

T(n)\ge A' n\log n - B''n

꼴로 쓸 수 있다. 따라서

T(n)=\Omega(n\log n)

이다.

17.3 결론

upper bound와 lower bound를 모두 얻었으므로

T(n)=\Theta(n\log n)

이다.

18 부등식 형태의 점화식

어떤 경우에는 점화식이 정확한 등식이 아니라 상한 또는 하한만 줄 수도 있다.

예를 들어

T(n) \le 2T(n/2)+\Theta(n)

은 O(\cdot) 결론을 뒷받침하고,

T(n) \ge 2T(n/2)+\Theta(n)

은 \Omega(\cdot) 결론을 뒷받침한다.

즉, 점화식의 부호와 형태를 잘 봐야 한다.

20 최종 정리

Tip꼭 기억할 것
  1. 점근 분석은 정확한 시간이 아니라 증가율에 초점을 맞춘다.
  2. \Theta는 tight bound, O와 \Omega는 각각 상한과 하한이다.
  3. 재귀 알고리즘을 분석할 때는 점화식이 가장 자연스러운 도구다.
  4. merge sort의 점화식은 T(n)=2T(n/2)+n이고 결과는 \Theta(n\log n)이다.
  5. 불균등 분할 점화식 T(n)=T(2n/3)+T(n/3)+\Theta(n) 역시 \Theta(n\log n)이다.
  6. 이유는 단순하지만 강력하다.
    • 각 레벨 비용은 \Theta(n)
    • 가장 큰 부분문제가 고정 비율로 줄어들므로 깊이는 \Theta(\log n)
