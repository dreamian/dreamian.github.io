Dive into Divide-and-Conquer: Merge Sort

Divide-and-Conquer는 큰 문제를 작은 문제로 나누어 해결하는 알고리즘 설계 패러다임이다. Merge Sort는 이 방식을 대표하는 정렬 알고리즘으로, 배열을 절반으로 나누고 각 부분을 재귀적으로 정렬한 뒤, 정렬된 두 부분을 병합하여 최종 정렬 결과를 만든다. 이 글에서는 Merge Sort의 의사코드, 핵심 아이디어, loop invariant 증명, 시간 복잡도 분석 등을 자세히 설명한다.

1 1. Divide-and-Conquer란?

노트핵심 아이디어

Divide-and-Conquer(분할 정복) 는 큰 문제를 더 작은 같은 형태의 문제들로 나눈 뒤, 각 부분 문제를 해결하고, 그 결과를 다시 합쳐서 원래 문제를 푸는 방식이다.

이 방법은 재귀(recursion)와 매우 잘 어울리며, 각 재귀 단계에서 다음 세 가지를 수행한다.

힌트Divide

문제를 더 작은 여러 개의 부분 문제로 나눈다.

힌트Conquer

각 부분 문제를 재귀적으로 해결한다. 문제 크기가 충분히 작아지면(base case) 직접 간단히 해결한다.

힌트Combine

부분 문제들의 해를 합쳐서 원래 문제의 해를 만든다.

2 2. Merge Sort 개요

중요Merge Sort의 큰 흐름

Merge Sort 는 divide-and-conquer 방식을 대표적으로 사용하는 정렬 알고리즘이다.

  • Divide: 길이 \(n\)인 배열을 두 부분으로 나눈다.
  • Conquer: 나누어진 두 부분 배열을 각각 재귀적으로 정렬한다.
  • Combine: 정렬된 두 부분 배열을 하나의 정렬된 배열로 합친다.

재귀는 배열의 길이가 1이 되면 종료된다. 길이가 1인 배열은 이미 정렬되어 있기 때문이다.

3 3. Merge Sort 의사코드

3.1 MERGE-SORT

\[ \begin{aligned} &\text{MERGE-SORT}(A,p,r) \\ &1\ \textbf{if}\ p < r \\ &2\ \quad q = \lfloor (p+r)/2 \rfloor \\ &3\ \quad \text{MERGE-SORT}(A,p,q) \\ &4\ \quad \text{MERGE-SORT}(A,q+1,r) \\ &5\ \quad \text{MERGE}(A,p,q,r) \end{aligned} \]

여기서:

  • \(A\): 정렬할 배열
  • \(p\): 시작 인덱스
  • \(r\): 끝 인덱스
  • \(q\): 중간 인덱스

즉, \(\text{MERGE-SORT}(A,p,r)\) 는 부분배열 \(A[p \dots r]\) 를 정렬한다.

4 4. MERGE 과정

노트왜 MERGE가 핵심인가?

Merge Sort의 진짜 핵심은 MERGE 과정이다. 이미 정렬된 두 부분 배열을 하나의 정렬된 배열로 합치는 단계가 알고리즘의 정확성과 성능을 결정한다.

4.1 MERGE 의사코드

\[ \begin{aligned} &\text{MERGE}(A,p,q,r) \\ &1\ \ n_1 = q-p+1 \\ &2\ \ n_2 = r-q \\ &3\ \ \text{let } L[1\dots n_1+1] \text{ and } R[1\dots n_2+1] \text{ be new arrays} \\ &4\ \ \textbf{for } i = 1 \textbf{ to } n_1 \\ &5\ \quad L[i] = A[p+i-1] \\ &6\ \ \textbf{for } j = 1 \textbf{ to } n_2 \\ &7\ \quad R[j] = A[q+j] \\ &8\ \ L[n_1+1] = \infty \\ &9\ \ R[n_2+1] = \infty \\ &10\ i = 1 \\ &11\ j = 1 \\ &12\ \textbf{for } k = p \textbf{ to } r \\ &13\ \quad \textbf{if } L[i] \le R[j] \\ &14\ \qquad A[k] = L[i] \\ &15\ \qquad i = i + 1 \\ &16\ \quad \textbf{else } A[k] = R[j] \\ &17\ \qquad j = j + 1 \end{aligned} \]

5 5. 왜 \(\infty\) 를 넣을까?

경고Sentinel의 역할

위 의사코드에서

  • \(L[n_1+1] = \infty\)
  • \(R[n_2+1] = \infty\)

는 sentinel(감시값) 이다.

이 값의 목적은 다음과 같다.

  • 왼쪽 배열이나 오른쪽 배열의 원소를 모두 사용했는지 매 반복마다 검사하지 않게 해준다.
  • 반복문 내부의 경계 조건 처리를 단순화한다.
  • 한쪽 배열이 먼저 소진되면, 다른 쪽 배열의 남은 원소가 자동으로 선택되도록 만든다.

예를 들어 왼쪽 배열의 실제 원소를 모두 사용했다면, 이후 비교에서 왼쪽 현재 값은 \(\infty\) 가 된다. 그러면 오른쪽 배열의 남은 실제 값들이 계속 선택되어 \(A\)에 복사된다.

즉, sentinel은 코드를 더 간단하게 만들기 위한 장치이다.

6 6. MERGE의 Loop Invariant

중요Loop Invariant

for-loop (12–17번 줄)의 각 반복이 시작될 때마다,

  • 부분배열 \(A[p \dots k-1]\) 는 \(L[1 \dots n_1+1]\) 와 \(R[1 \dots n_2+1]\) 에 있는 원소들 중 가장 작은 \((k-p)\)개의 원소를 오름차순으로 담고 있다.
  • 또한 \(L[i]\) 와 \(R[j]\) 는 각각 아직 \(A\)로 복사되지 않은 원소들 중 가장 작은 원소이다.

이 불변식이 유지되면, 반복이 끝났을 때 전체 병합 결과가 정확하게 정렬되어 있음을 보일 수 있다.

7 7. Loop Invariant 증명

7.1 Initialization

반복문이 시작되기 전, \(k=p\) 이므로 부분배열 \(A[p \dots k-1]\) 는 비어 있다.

비어 있는 배열은 “가장 작은 0개의 원소를 정렬된 상태로 담고 있다”라고 볼 수 있으므로 초기 조건은 성립한다. 또한 \(i=1\), \(j=1\) 이므로 \(L[i]\), \(R[j]\) 는 각 배열에서 아직 복사되지 않은 가장 작은 후보이다.

7.2 Maintenance

반복 시작 시 loop invariant가 참이라고 가정하자.

힌트경우 1: \(L[i] \le R[j]\)

이때 \(L[i]\) 는 아직 복사되지 않은 원소들 중 가장 작은 값이다. 따라서 \(A[k]\) 에 \(L[i]\) 를 넣으면,

  • \(A[p \dots k]\) 는 가장 작은 \((k-p+1)\)개의 원소를 담게 되고
  • 오름차순 정렬 상태도 유지된다.

그 후 \(i\) 를 1 증가시키면 다음 반복에서도 불변식이 다시 성립한다.

힌트경우 2: \(L[i] > R[j]\)

이 경우에는 \(R[j]\) 가 가장 작은 미복사 원소이므로 \(A[k]\) 에 \(R[j]\) 를 넣고 \(j\) 를 증가시키면 된다. 같은 논리로 loop invariant는 유지된다.

7.3 Termination

반복문이 끝나면 \(k=r+1\) 이다.

따라서 loop invariant에 의해 \(A[p \dots k-1] = A[p \dots r]\) 는 \(L\) 과 \(R\) 의 원소들 중 가장 작은 \((r-p+1)\)개를 오름차순으로 담고 있다.

원래 우리가 병합하려던 실제 원소 개수는 정확히 \((r-p+1)\)개이므로, 결국 \(A[p \dots r]\) 는 정렬된 상태가 된다. 마지막에 남는 두 개의 가장 큰 값은 sentinel인 \(\infty\) 이므로 실제 정렬 결과에는 포함되지 않는다.

8 8. Merge Sort의 시간 복잡도

Merge Sort의 실행 시간을 divide, conquer, combine 관점에서 분석해보자.

노트Divide

중간 인덱스 \(q\) 를 계산하는 데 걸리는 시간은 \(\Theta(1)\) 이다.

노트Conquer

크기가 \(n/2\) 인 두 부분 문제를 재귀적으로 해결하므로 비용은

\[ 2T(n/2) \]

이다.

노트Combine

정렬된 두 부분 배열을 합치는 MERGE 과정은 전체 원소를 한 번씩 보므로

\[ \Theta(n) \]

시간이 걸린다.

따라서 전체 점화식은 다음과 같다.

\[ T(1) = 1 \]

\[ T(n) = 2T(n/2) + n \]

이 점화식을 풀면 Merge Sort의 시간 복잡도는

\[ T(n) = \Theta(n \log n) \]

이 된다.

9 9. Merge Sort의 특징 정리

중요요약

Merge Sort는 다음과 같은 특징을 가진다.

  • divide-and-conquer의 전형적인 예시이다.
  • 최악의 경우에도 \(\Theta(n \log n)\) 시간에 동작한다.
  • stable sort 이다.
  • 추가 배열 \(L\), \(R\) 이 필요하므로 추가 메모리가 필요하다.

즉, Merge Sort는 성능이 매우 예측 가능하고 이론적으로도 중요한 정렬 알고리즘이지만, in-place sorting은 아니라는 점도 함께 기억해야 한다.

10 10. 핵심 요약

11 Final Takeaway

Merge Sort는 배열을 절반으로 계속 나누고, 각 부분을 재귀적으로 정렬한 뒤, 정렬된 두 배열을 merge하여 최종 정렬 결과를 만든다.

정확성은 MERGE 과정의 loop invariant로 설명할 수 있고, 시간 복잡도는

\[ T(n) = 2T(n/2) + n \]

으로 표현된다. 따라서 전체 시간 복잡도는

\[ \Theta(n \log n) \]

이다.
