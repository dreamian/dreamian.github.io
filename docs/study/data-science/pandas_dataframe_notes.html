1 결측치 탐지와 불리언 인덱싱

1.1 notna() / isna()

notna()는 각 원소가 결측(NaN)이 아니면 True, isna()는 그 반대인 불리언 Series를 반환한다. 불리언 Series는 그 자체가 하나의 “행 필터”로 기능한다.

df_titanic['Embarked'].isna().sum()   # True의 합 = 결측 개수
np.int64(2)

1.2 Series에서의 .loc — 인자 1개

Series는 1차원이므로 .loc에 행 선택자 하나만 들어간다.

x = df_titanic['Embarked']
x.loc[x.notna()].unique()             # 결측 제거 후 유일값
<StringArray>
['S', 'C', 'Q']
Length: 3, dtype: str

1.3 DataFrame에서의 .loc[행, 열] — 인자 2개

DataFrame은 2차원이므로 콤마로 행 선택자와 열 선택자를 동시에 지정한다.

df_titanic.loc[df_titanic['Cabin'].notna(), 'Cabin'].head()
1      C85
3     C123
6      E46
10      G6
11    C103
Name: Cabin, dtype: str

열 선택자의 형태에 따라 반환 타입이 달라진다.

열 선택자 예 반환
문자열 하나 .loc[cond, 'Cabin'] Series
리스트 .loc[cond, ['Name', 'Sex']] DataFrame
라벨 슬라이스 .loc[cond, 'Pclass':'Cabin'] DataFrame (양 끝 포함)
생략 또는 : .loc[cond] 모든 열
Important값 대입은 반드시 .loc[행, 열] = 값

df['col'][cond] = 값 형태의 연쇄 인덱싱(chained indexing) 은 대입이 복사본에 적용될 수 있어 원본이 바뀌지 않는 버그의 흔한 원인이다. 한 번의 .loc 호출로 좌표를 지정하는 것이 표준 패턴이다.

df2 = df_titanic.copy()
df2.loc[df2['Embarked'].isna(), 'Embarked'] = df2['Embarked'].mode()[0]
df2['Embarked'].isna().sum()
np.int64(0)

복합 조건은 &, |로 결합하되 각 조건을 괄호로 감싼다 (비교 연산자보다 &의 우선순위가 높기 때문).

df_titanic.loc[
    (df_titanic['Sex'] == 'female') & (df_titanic['Pclass'] == 1),
    'Survived'
].mean()
np.float64(0.9680851063829787)

2 apply — 열 단위 반복 연산

DataFrame에 apply(func)를 쓰면 기본값 axis=0으로 각 열이 Series로서 함수에 차례로 전달된다. for 루프로 열을 순회하는 것과 논리적으로 같지만, 결과를 자동으로 하나의 객체로 모아 준다.

df_titanic[['Survived', 'Pclass', 'Sex', 'Embarked']].apply(
    lambda x: x.loc[x.notna()].unique().tolist()
)
Survived            [0, 1]
Pclass           [3, 1, 2]
Sex         [male, female]
Embarked         [S, C, Q]
dtype: object

함수가 스칼라를 반환하면 결과는 Series, 리스트 같은 객체를 반환하면 “값이 리스트인 Series”가 된다.

Tipapply + pd.Series = 한 열을 여러 열로

Series에 apply를 적용할 때 람다가 pd.Series를 반환하면, pandas가 그 인덱스를 열 이름으로 삼아 결과를 DataFrame으로 조립해 준다.

df_titanic.loc[df_titanic['Cabin'].notna(), 'Cabin'].str.split(' ')\
    .explode()\
    .apply(
        lambda x: pd.Series((x[:1], x[1:]), index=['Cabin_Type', 'Cabin_No'])
    ).head()
Cabin_Type Cabin_No
1 C 85
3 C 123
6 E 46
10 G 6
11 C 103

x[0] 대신 x[:1]을 쓰면 빈 문자열에서 IndexError 없이 빈 문자열을 반환하므로 슬라이싱이 더 방어적이다.

벡터화된 대안이 있으면 그쪽이 간결하고 빠르다는 점도 기억해 둔다.

# apply 버전:  .apply(lambda x: x.isna().sum())
df_titanic[['Age', 'Cabin', 'Embarked']].isna().sum()   # 벡터화 버전
Age         177
Cabin       687
Embarked      2
dtype: int64

3 .str 접근자 — 문자열 일괄 처리

.str은 Series의 각 문자열 원소에 문자열 메서드를 벡터화하여 적용한다. split 결과(리스트의 Series)에서 원소를 꺼낼 때는 .str[i]를 이어 쓴다.

# "성, 호칭. 이름" 형식에서 호칭만 추출
title = df_titanic['Name'].str.split(', ').str[1].str.split('.').str[0]
title.value_counts().head()
Name
Mr        517
Miss      182
Mrs       125
Master     40
Dr          7
Name: count, dtype: int64
Warning.str.split / .str.rsplit의 n은 키워드 전용 인자

순수 파이썬 문자열은 'A/5 21171'.rsplit(' ', 1)처럼 위치 인자를 허용하지만, pandas .str 접근자의 시그니처는 rsplit(pat=None, *, n=-1, expand=False)로 * 뒤의 인자를 키워드로만 받는다.

s.str.rsplit(' ', 1)     # TypeError!
s.str.rsplit(' ', n=1)   # OK

에러 메시지의 “3 were given”은 self가 첫 위치 인자로 자동 전달되기 때문이다. apply(lambda x: x.rsplit(' ', 1))이 동작하는 이유는 람다 안의 x가 Series가 아닌 개별 파이썬 문자열이기 때문이다.

rsplit(' ', n=1)은 오른쪽에서 한 번만 나누므로, 접두사에 공백이 있는 'STON/O 2. 3101282' 같은 값에서도 마지막 조각(번호)이 보존된다.

4 explode — 관측 단위 재구성

한 셀에 값 여러 개가 뭉쳐 있으면(“C23 C25 C27”) 표준 집계 연산을 쓸 수 없다. explode는 리스트의 각 원소를 독립된 행으로 펼쳐 “한 셀 = 한 값”을 만든다.

cabin_exploded = df_titanic.loc[df_titanic['Cabin'].notna(), 'Cabin']\
    .str.split(' ')\
    .explode()
cabin_exploded.loc[[27]]    # 인덱스 27: 객실 3개 → 행 3개
27    C23
27    C25
27    C27
Name: Cabin, dtype: str

핵심 성질 두 가지:

  1. 인덱스가 복제된다 — 펼쳐진 각 값이 어느 원래 행에서 나왔는지가 보존된다.
  2. 길이가 늘어난다 — 관측 단위가 “승객”에서 “객실”로 바뀐다.

5 groupby 심화

5.1 level=0 — 인덱스로 그룹화

groupby의 기준이 열이 아니라 인덱스에 있을 때 level 인자를 쓴다. level=0은 인덱스의 첫 번째 층을 뜻하며, 단일 인덱스라면 “인덱스 그 자체로 묶어라”가 된다. explode가 보존해 준 인덱스를 그룹 키로 되살리는 전형적 조합이다.

cabins_per_passenger = cabin_exploded.groupby(level=0).size()
cabins_per_passenger.value_counts()   # 객실 개수별 승객 수
Cabin
1    180
2     16
3      6
4      2
Name: count, dtype: int64

size()는 그룹의 행 개수, count()는 결측이 아닌 값의 개수를 센다.

5.2 agg vs transform

같은 그룹 연산이지만 결과를 돌려주는 방식이 다르다.

계산 반환 형태 관측 단위
agg (median() 등) 그룹별 통계량 그룹 개수만큼의 행 그룹
transform 그룹별 통계량 원본과 같은 길이·인덱스 원래 행

transform은 split → 그룹별 계산 → broadcast(각 행에 자기 그룹의 값을 되돌려 뿌리기)의 3단계로 동작한다. 개념적으로는 조건부 통계량 \(E[Y \mid \text{그룹}]\)을 각 관측치에 매핑하는 연산이다.

df3 = df_titanic.copy()

# 호칭별 나이 중앙값을 각 승객에게 대응시킨 891행 Series
age_median_by_title = df3.groupby(title)['Age'].transform('median')

# .loc 대입은 인덱스 정렬 기반 → 원본과 인덱스가 같아야 결측 위치에 정확히 들어간다
df3.loc[df3['Age'].isna(), 'Age'] = age_median_by_title

print(df3['Age'].isna().sum())
print(round(df_titanic['Age'].mean(), 3), '→', round(df3['Age'].mean(), 3))
0
29.699 → 29.39

agg 결과(인덱스가 호칭인 짧은 Series)를 우변에 넣으면 인덱스가 맞지 않아 전부 NaN이 대입된다. transform이 필요한 이유는 이 정렬 호환성이다.

전형적 용례: 그룹별 결측 대체, 그룹 내 표준화 (x - x.mean()) / x.std(), 그룹 합 대비 비중 x / x.sum().
