1 RLHF — Reinforcement Learning from Human Feedback

1.1 동기: 왜 instruction finetuning만으로는 부족한가

직답. Instruction finetuning은 언어 모델링 목적함수를 최적화하지만, 우리가 실제로 원하는 것은 인간 선호(human preference)를 만족시키는 것이다. 이 둘 사이에는 목적 불일치(objective mismatch) 가 존재한다.

노트Recap — Instruction Finetuning

다양한 task를 “instruction–answer” 쌍의 형태로 묶어 사전학습된 LLM을 추가 미세조정하면, 학습에 직접 쓰이지 않은(unseen) task에서도 zero-shot 성능이 향상된다 (Wei et al., Finetuned Language Models Are Zero-Shot Learners, ICLR 2022). 형식상 “fine-tuning”이지만, 실질은 광범위한 task로 모델을 추가 사전학습하여 일반화된 응답 능력을 끌어올리는 절차에 가깝다.

Instruction finetuning의 두 가지 본질적 한계:

# 한계 설명 예시
1 정답이 없는 task open-ended 생성은 단일 정답·단일 metric이 없음 → instruction–answer 쌍 자체를 만들 수 없음 “강아지와 그 애완 메뚜기에 대한 이야기를 써줘”
2 토큰 오류의 균등 처벌 언어 모델링 손실은 모든 토큰 오류를 동일하게 처벌하지만, 어떤 오류는 더 치명적임 “현재 미국 대통령은 ___” 에서 이름 토큰의 오류는 조사·접속사 오류보다 훨씬 치명적

핵심 통찰: 언어 모델링 목적(\(\max \log p(\text{next token})\))은 “사용자의 만족도”를 직접 신경 쓰지 않는다. 다음 토큰을 높은 확률로 뱉을 뿐, 그 응답이 인간을 얼마나 만족시키는지는 목적함수에 들어 있지 않다. → “인간 선호를 명시적 목적으로 넣을 수 없을까?” 가 RLHF의 출발점이다.

1.2 RLHF의 3단계 구조

직답. RLHF = SFT로 시작점 마련 → 선호 데이터로 보상 모델 학습 → 그 보상으로 LLM을 RL 미세조정.

  • Step 1 — SFT 시작점: instruction finetuning으로 그럴듯한 응답을 내는 기반 모델을 만든다.
  • Step 2 — 피드백 수집: 하나의 prompt에 대해 LLM이 두 개의 응답을 생성하면, 사람이 어느 쪽이 더 선호되는지 Likert 척도(강하게 더 좋음 ↔︎ 약간 더 좋음)나 랭킹으로 평가한다. (OpenAI는 공학 전공자가 아닌 언어학·인문 전공자를 다수 고용해 고임금으로 라벨링을 수행했다는 일화가 있다.)
  • Step 3 — 보상 모델 + RL: 선호 데이터로 보상 모델을 학습하고, 그 보상을 신호로 LLM을 강화학습으로 미세조정한다.
힌트역사적 맥락 — Learning to summarize (NeurIPS 2020)

초기 실험(Stiennon et al.)에서, 동일 prompt에 대해 바닐라 LM 출력은 같은 말을 반복하는 등 기계적이었으나, 경량 인간 피드백을 주입한 모델의 출력은 사람이 쓴 것처럼 자연스러워졌다. 이 효과를 확인한 뒤 GPT-3 계열을 InstructGPT → ChatGPT로 발전시키는 3단계 파이프라인이 정립되었다.

1.3 보상 모델과 Bradley–Terry 손실

직답. 보상 모델은 선택된(chosen) 응답의 보상이 거절된(rejected) 응답의 보상보다 커지도록, 두 보상의 차이를 키우는 손실로 학습한다.

base 모델 위에 새 final layer(선호 헤드)를 얹고, 다음 손실을 최소화한다:

\[ L_{\text{RM}} \;=\; \log\!\Big(1 + e^{\,r_{\text{rejected}} - r_{\text{chosen}}}\Big). \]

이는 Bradley–Terry / 로지스틱 선호 모형과 동일하다. \(\sigma(z)=\frac{1}{1+e^{-z}}\) 로 두면

\[ L_{\text{RM}} = -\log \sigma\!\big(r_{\text{chosen}} - r_{\text{rejected}}\big), \]

즉 “chosen이 rejected를 이길 확률”의 음의 로그우도(이진 교차엔트로피)다. (부록 섹션 8 에서 두 형태의 수치적 등가성을 SymPy로 검증한다.)

노트실무 디테일
  • 단 1 epoch 학습(의도적 overfitting).
  • 인간 평가 상호 동의율(agreement) 은 보통 65–75% 수준 — 보상 신호는 본질적으로 noisy하다. 이 점이 뒤의 KL 정규화(섹션 1.5) 필요성으로 이어진다.
  • 손실에 margin(선택지 간 강도 차이)을 추가하는 변형이 흔하다.

1.4 RL 관점에서 본 RLHF + PPO-Clip

직답. LLM = 정책(policy), 출력 토큰열 = 행동(action), 보상 모델 = 환경의 보상. 이를 PPO-Clip으로 최적화한다.

RL 개념 RLHF에서의 대응
Agent / Policy \(\pi_\theta\) 학습 중인 LLM
Action LLM이 생성한 응답(토큰열)
Environment reward 인간 선호로 학습된 보상 모델 출력
Episode 하나의 prompt → completion

참고. RLHF의 “deep” 여부는 프레임워크가 아니라 정책/가치 함수에 신경망을 쓰는지에 달려 있다. 동일한 RL 프레임으로 deep/shallow 모두 가능하다.

1.5 보상이 불안정하므로: base 정책으로의 KL 정규화

직답. 보상 신호가 noisy하므로, 학습된 정책이 원래 LM에서 너무 멀어지지 않도록 KL 발산으로 보수적으로 제약한다.

\[ \max_\theta \;\; \mathbb{E}\big[\, r(x) \,\big] \;-\; \beta\, D_{\mathrm{KL}}\!\big(\pi_{\text{RLHF}} \,\|\, \pi_{\text{base}}\big). \]

중요두 KL을 혼동하지 말 것 (시험 빈출 포인트)
비교 대상 역할
RLHF의 KL \(D_{\mathrm{KL}}(\pi_{\text{RLHF}} \,\|\, \pi_{\text{base}})\) 학습 정책을 원래 base LM에 앵커링 — 모델이 망가지지 않도록
PPO-Clip의 KL \(D_{\mathrm{KL}}(\pi_{\text{old}} \,\|\, \pi_{\text{new}})\) 연속한 두 정책 반복(iterate) 사이의 신뢰영역(trust region) — 업데이트 폭 제한

즉 RLHF-KL은 절대 기준(base) 에 묶는 정규화 항이고, PPO-KL은 상대 기준(직전 정책) 에 대한 스텝 크기 제약이다. 또한 PPO-Clip은 매 gradient step마다 작은 신뢰영역을 강제하지만, RLHF의 KL 항은 여러 step을 모아 한 번 크게 갱신할 때 base로부터의 거리를 직접 벌점화한다.

1.6 “Alignment”라는 이름

선호 데이터로 모델을 사용자 취향에 맞추는 절차는 여전히 파라미터를 갱신하는 학습이지만, “fine-tuning/learning”이라는 표현이 식상하다는 이유로 alignment(정렬) 이라는 새 이름으로 부른다. 본질은 같다(일종의 마케팅적 재명명).

노트무선통신 비유 — 제한된 피드백 기반 적응

RLHF는 수신단의 제한된 피드백(limited feedback)으로 송신 정책을 적응시키는 폐루프 제어와 닮았다. - 보상 모델 = 채널 품질을 대신하는 학습된 품질 지표(soft CSI). 인간 선호는 정확한 CSI가 아니라 양자화된 선호 피드백(어느 쪽이 더 좋은지)에 해당한다 → 그래서 noisy(동의율 65–75%). - Bradley–Terry 로지스틱 = soft-decision의 LLR(log-likelihood ratio) 와 같은 로지스틱 링크. - KL 정규화(→base) = 근접(proximal)·신뢰영역 갱신. 적응형 전력제어에서 한 번에 큰 스텝을 밟지 않고 직전(또는 기준) 동작점 근처로 업데이트를 제한해 발산을 막는 것과 동형(同型)이다.

힌트보조 참고 (math4ml / d2l)
  • KL 발산·엔트로피의 정의와 성질: math4ml의 Probability 절(엔트로피·상대엔트로피)을 함께 보면 KL 정규화의 직관이 단단해진다.
  • 정책경사·PPO의 RL 기초: d2l.ai의 강화학습/정책최적화 관련 장을 보조 자료로 활용.

2 PEFT — Parameter-Efficient Fine-Tuning

2.1 왜 PEFT인가

직답. 거대 모델 전체를 갱신하지 않고 소수의 파라미터만 갱신하여 적응시키는 기법.

이점 메커니즘
효율 증가 / 빠른 time-to-value 갱신 파라미터가 적어 학습·배포가 빠름
Catastrophic forgetting 감소 기존 가중치를 대부분 동결 → 사전학습 지식 보존
Overfitting 위험 감소 갱신 자유도가 작음
데이터 요구량 감소 적은 파라미터 → 적은 데이터로 충분
접근성 향상 적은 자원으로 거대 모델 적응 가능

대표 기법: Adapters, LoRA, QLoRA, Prefix-/Prompt-/P-tuning. 본 노트는 앞의 세 가지를 다룬다.

2.2 Adapter

직답. Transformer 블록 사이에 작은 추가 레이어(adapter) 를 끼워 넣고, 기존 가중치는 동결한 채 adapter와 LayerNorm만 학습한다 (Houlsby et al., Google Research, ICML 2019).

  • feed-forward·multi-head attention 가중치는 고정.
  • 새로 삽입한 adapter는 보통 down-projection → 비선형 → up-projection 구조(병목, bottleneck).
  • 출력 분포가 달라지므로 LayerNorm을 추가/재학습.

결과적으로 소수의 레이어만 갱신하면서, 이전에 학습한 지식과 새 데이터 지식을 LayerNorm 재조정으로 섞어 양쪽 정확도를 모두 유지한다.

2.3 LoRA — Low-Rank Adaptation

직답. 가중치 갱신량 \(\Delta W\) 를 저랭크(low-rank) 분해 \(BA\) 로 근사하여, 원래 가중치 \(W\) 는 동결하고 \(A,B\) 만 학습한다 (Hu et al., Microsoft, ICLR 2022).

선형층 \(W \in \mathbb{R}^{d\times d}\) 에 대해:

\[ h \;=\; W x \;+\; \underbrace{B A}_{\Delta W}\, x, \qquad A \in \mathbb{R}^{r \times d},\; B \in \mathbb{R}^{d \times r},\; r \ll d. \]

  • 파라미터 수: \(W\) 는 \(d^2\), \(BA\) 는 \(2dr\). 절감비

\[ \frac{2dr}{d^2} = \frac{2r}{d}. \]

예: \(d=4096,\ r=8\) 이면 \(2dr/d^2 = 1/256\). 실제 LoRA는 종종 원본의 0.1% 이하 파라미터만 학습한다.

노트왜 저랭크로 충분한가 — 직관

어떤 task의 적응에 필요한 정보가 full-rank 만큼 복잡하지 않다면(내재 차원이 낮다면), 갱신 방향은 저차원 부분공간에 거의 놓인다. 그 부분공간만 \(BA\) 로 학습하면 된다. 이는 행렬의 저랭크 근사(SVD의 상위 특이값만 취하기) 와 같은 정신이다.

추론 시 \(BA\) 를 \(W\) 에 병합(\(W' = W + BA\))할 수 있어, 추론 지연 0으로 만들 수 있다(다만 어댑터를 분리 유지하면 약간의 overhead가 있다).

2.4 QLoRA — Quantized LoRA

직답. 동결된 base 가중치를 저정밀도(예: 4-bit)로 양자화한 상태에서 LoRA 어댑터를 학습한다 (Dettmers et al., UW, NeurIPS 2023 Oral).

  • LoRA의 \(BA\) 가 base의 0.1% 미만이라도 절대 크기가 클 수 있다. base를 양자화하면 메모리·overhead를 더 줄이면서 정확도를 거의 유지한다.
  • 요지: “동결된 무거운 부분은 낮은 비트로, 학습하는 가벼운 부분(어댑터)은 그대로” → 매우 컴팩트한 적응.
노트무선통신 비유 — 저랭크 부분공간 적응 & 양자화 피드백
  • LoRA = reduced-rank / 부분공간 적응. MIMO에서 채널이 저랭크일 때 상위 특이모드(빔)만으로 프리코딩하는 것, 혹은 적응 필터에서 부분공간 추적(subspace tracking) 으로 소수 좌표만 갱신하는 것과 동형이다. 전체 \(W\) 가 아닌 저차원 방향 \(BA\) 만 학습 = 제한된 피드백 코드북으로 핵심 방향만 보정.
  • QLoRA = 적응 정보를 양자화해 전송·저장 비용을 줄이는 limited-feedback 정밀도 절감과 같다(핵심 빔은 동결·양자화, 보정만 정밀하게).
힌트보조 참고 (math4ml / d2l)
  • 저랭크 근사·SVD·고유분해의 엄밀한 배경: math4ml의 Linear Algebra 절(eigendecomposition, singular values)을 LoRA 직관의 토대로 삼을 것.
  • Adapter/LoRA가 끼어드는 Transformer 블록 구조: d2l.ai의 Attention Mechanisms / Transformer 장으로 위치 감각을 보강.

3 RAG — Retrieval-Augmented Generation

3.1 동기와 핵심 아이디어

직답. LLM은 거짓말을 하려는 게 아니라 확률적으로 그럴듯한 토큰을 뱉다가 환각(hallucination) 을 낸다. 관련 외부 문서를 조건으로 주어 환각을 줄인다 (Piktus et al., Facebook, NeurIPS 2020).

3.2 MIPS와 RAG-Sequence vs RAG-Token

Maximum Inner Product Search (MIPS). 쿼리 임베딩 \(q\) 와 문서 임베딩 \(\{d_i\}\) 의 내적(코사인 유사도와 같은 정렬도) 을 계산해 최대값 문서를 찾는다:

\[ i^\star = \arg\max_i \; \langle q, d_i \rangle . \]

상위 \(K\) 개 문서에 대해 seq-to-seq 예측을 주변화(marginalize) 한다:

변형 동작 비용/특성
RAG-Sequence 문장 전체를 한 번에 보고 가장 관련된 문서를 골라 생성 한 시퀀스에 하나의 문서 사용 — 더 저렴
RAG-Token 토큰마다 관련 문서를 다시 찾아 생성 후 결합 토큰마다 다른 문서 가능 — 더 비쌈, 더 유연

어느 쪽이 우월한지는 application에 따라 다르다. 2020년 이후 수많은 고급 변형이 나왔으나, 최소한 MIPS는 확실히 이해하고 거기서 출발해 문헌을 따라가는 것이 권장된다.

노트무선통신 비유 — 정합 필터 / 상관 수신기

MIPS의 “내적 최대화” = 정합 필터(matched filter)·상관 수신기. 수신 신호와 후보 파형(코드)의 상관을 최대화해 가장 잘 맞는 경로/심볼을 고르는 것(예: RAKE 수신기의 강한 상관 경로 선택)과 정확히 같은 연산이다. 검색된 문서로 응답을 그라운딩하는 것은 파일럿 기반 채널추정으로 디코딩을 정합시키는 것에 대응한다.

힌트보조 참고 (d2l)

임베딩·attention 기반 유사도와 seq-to-seq 디코딩의 기초는 d2l.ai의 Attention / Encoder–Decoder 장에서 보강할 수 있다.

4 AI Agents (Agentic AI)

4.1 정의와 Toolformer

직답. 에이전트 = 외부 도구를 호출하거나 계획을 세워 작업을 끝내는 (대개 LLM 기반) 모델. 출력이 단어 토큰이 아니라 행동(action) 토큰이라는 점이 핵심.

  • 이름(“AI Agents” vs “Agentic AI”)은 중요치 않다 — 본질은 도구 호출·계획으로 고정밀 작업 수행.
  • 행동은 물리적 동작일 수도, 컴퓨터 조작(마우스 이동·클릭·타이핑하는 web agent)일 수도 있다. 작업 = 행동의 시퀀스.

Toolformer (Schick et al., UW, NeurIPS 2023) — 초기 대표 사례:

즉 “API 호출 결과가 다음 토큰의 손실을 줄여주면 그 호출을 학습 데이터로 채택” 하는 자기지도 방식. 오늘날에는 이런 도구 제어를 더 정교하게 다뤄 web agent·로봇 등으로 확장한다.

노트무선통신 비유 — 폐루프 제어와 제어 시그널링

에이전트는 외부 센싱(도구·웹)으로 상태를 관측하고 행동을 출력하는 폐루프 제어기다. 행동 토큰은 물리계층의 제어 시그널링에 대응하며, 관측→평가(손실)→행동 채택의 루프는 채널 상태를 보고 변조·전력을 조정하는 적응 루프와 같은 구조다.

5 World Models

5.1 초기 정의 (Ha & Schmidhuber, 2018)

직답. 세계의 대리(proxy) 모델. RL에서 model-based 방법의 “model”(환경 시뮬레이터)이 곧 world model이다.

  • 개념적 뿌리는 1993년 Scott McCloud — “인간은 뇌 속에서 상상하고, 그 상상의 결과로 행동한다”는 직관. 자전거를 머릿속으로 그려보며 타듯, 상상의 출력으로 행동한다.
  • Ha & Schmidhuber(NeurIPS 2018)는 이를 시각 입력 + 메모리 + 컨트롤러 구조로 구체화: 지각(perception)에서 압축된 표현을 얻고, 메모리(순환 구조)로 동역학을 예측하며, 컨트롤러가 행동 시퀀스를 산출한다.

5.2 현대적 world model

직답. 지각 정보(시각·언어·오디오 등)로부터 상호작용 가능한 세계를 학습 → 사실상 무한히 영상을 생성하는 모델로 진화. 그 위에서 로봇·정책 모델을 학습한다.

대표 사례:

모델 핵심
UniSim (2023) Universal Simulator — 다양한 현실 장면(내비게이션·조작 등)을 생성해 정책 학습용 입력을 만든다 (Yang et al., Learning Interactive Real-World Simulators)
LWM (2025) Large World Model — 멀티모달 토큰 시퀀스 위의 autoregressive transformer
NVIDIA Cosmos (2025–2026) 사전학습 멀티모달 생성 모델 스위트

LWM (Liu, Yan, Zaharia, Abbeel, ICLR 2025) 구조:

  • 각 비디오 프레임 → VQGAN으로 256개 토큰으로 토큰화.
  • 텍스트 → BPE(Byte-Pair Encoding) 토크나이저로 처리.
    • BPE/바이트 수준 인코딩을 쓰면, 단어 수준 인코딩의 방대한 vocabulary 대신 소수의 문자 단위만으로 다양한 언어 변형을 표현할 수 있다.
  • 이미지·텍스트 토큰을 합쳐 transformer에 넣고 autoregressive하게 다음 토큰 예측.

NVIDIA Cosmos 3종 모듈:

  • Cosmos Predict: 주어진 프레임 시퀀스로 다음 프레임을 예측하는 world model → 영상 형태의 세계 거동 생성.
  • Cosmos Reason: Predict 위에서 학습하는 추론/행동 모델(VLA 예시).
  • Cosmos Transfer: sim-to-real 도메인 전이로 실세계 적용을 개선.
  • Cosmos 2.5(2025년 10월) → Cosmos 3(2026년 6월): mixture-of-transformers 기반, 공개 합성 비디오 데이터를 활용해 비전·추론을 강화하고 더 나은 정책 모델·세계 시뮬레이션을 지향.
노트무선통신 비유 — 채널 예측 / 디지털 트윈

World model은 채널 예측기(channel predictor)·디지털 트윈과 같다. “다음 프레임 예측”은 “다음 채널 상태 예측”에 대응하며, 예측된 미래 위에서 정책을 학습·계획하는 것은 예측적 자원할당(predictive scheduling) — 미래 채널을 내다보고 미리 자원을 배치하는 것과 동형이다. 실제 환경을 직접 두드리지 않고 내부 모델 안에서 시뮬레이션해 학습하는 점이 model-based의 핵심 이득이다.

7 보론: 연구 방법론 노트

본 회차 후반부의 연구 조언을 핵심만 정리한다(시험 범위와 별개로 가치가 높음).

7.1 연구와 출판의 정의

  • Research = re-search: 해를 못 찾았기에 다시, 또다시 탐색하는 일. 실패가 평상(ordinary)이고, 해를 찾는 날이 비범(extra-ordinary) 하다. 매일 새것을 못 찾는 게 정상이며, 찾으면 오히려 놀라야 한다.
  • Publication ≠ “내가 한 일의 보고”: 무엇을 시도했는지가 아니라, 문제에 대한 새로운·놀라운 발견을 보고하는 것. 단, 무엇을 시도했고 무엇을 배웠는지는 스스로 기록하라(같은 실수 반복 방지). 다만 논문 본문에 시도 나열을 쓰지는 말 것.
  • 좋은 논문의 메시지: “이 문제를 풀려면 이렇게 해야 한다” (예: “객체 검출을 효율적·정확하게 하려면 X를 해야 한다”). “이걸 해봤더니 5% 올랐으니 받아달라” 는 약한 논문.

7.2 절차와 원칙

  1. 흥미로운 주제 선정 — 많은 사람에게 흥미로운 문제일수록 가치가 크다.
  2. 선행연구 위에서 시작 — 바퀴를 다시 발명하지 말 것. SOTA를 읽고, 무엇이 잘못됐는지 찾아 고친다. 그래서 남의 논문을 읽는다.
  3. 협업 — 거대 모델 시대엔 (예: 100명 이상 저자의 기술 리포트) 다수와 협업해야 큰 임팩트가 난다. 함께 일하고 싶은 사람이 되라.

7.3 큰 아이디어 vs 점진적 아이디어

  • 점진적(safe) 아이디어: 결과가 예측 가능, 거의 항상 출판 가능하지만 커리어 임팩트는 작다(예: 성능 +몇 %).
  • 큰(risky) 아이디어: 고위험·고수익. 구현이 길고 고통스러우며 결과 보장이 없지만, 성공하면 임팩트가 수십~수백 배. (CNN처럼 오랜 잠복 끝에 빛을 본 사례, GPU 컴퓨팅의 장기 투자 사례 등.)
  • 박사 초기엔 작은 아이디어로 연습하되, 진짜 연구는 4–5년을 걸 만한 큰 아이디어인지로 판단하라. “창의적·독창적이며(때로 과감할 만큼) 큰 문제”를 노릴 것.

7.4 리뷰·리버탈의 현실

  • 리뷰어는 시간이 없고 거절할 이유를 찾는다(피상적으로 수치·그림·결론만 본다). 그러니 “거절할 이유를 만들 수 없게” 쓰는 것이 곧 좋은 논문/리버탈 작성이다.
  • 명명(naming)도 영향력의 일부: 좋은 아이디어엔 기억에 남는 이름을 붙여라(예: LSTM 계열의 게이팅 변형들).
노트회차 말미의 기술적 여담 — 게이팅(gating)

“과거를 기억”하기 위해 도입된 핵심 아이디어가 게이팅이다. 현재 입력과 과거 메모리를 게이트 값으로 가중합: \[ f \;=\; g(x)\odot x \;+\;\big(1-g(x)\big)\odot m, \qquad g(x)\in(0,1), \] 여기서 \(m\) 은 메모리(과거의 이동평균적 누적). 대표 변형으로 LSTM과, 더 적은 파라미터로 유사 성능을 내는 GRU가 있다. 시간에 걸친 기억(long-range memory) 은 여전히 완전히 풀리지 않은 난제다.

import sympy as sp

# (1) 보상모델 손실의 등가성:
#     -log sigma(r_c - r_r)  ==  log(1 + e^{r_r - r_c})
r_c, r_r = sp.symbols('r_c r_r', real=True)
bt    = -sp.log(1/(1 + sp.exp(-(r_c - r_r))))   # Bradley-Terry 형태
slide =  sp.log(1 + sp.exp(r_r - r_c))          # 본문 손실 형태
print("등가성 확인 (0이어야 함):",
      sp.simplify(sp.expand_log(bt - slide, force=True)))

# (2) LoRA 파라미터 절감비 2r/d
def lora_ratio(d, r):
    full = d * d          # 원본 W 의 파라미터 수
    lora = 2 * d * r      # A(r x d) + B(d x r)
    return full, lora, lora / full

for d, r in [(4096, 8), (4096, 16), (1024, 4)]:

          f"비율={ratio:.5f} (≈ 1/{round(1/ratio)})")

import numpy as np
# (3) sigmoid(x) == 2-class softmax([x, 0])_0  (선호 모형의 로지스틱 링크)
def sigmoid(x): return 1.0 / (1.0 + np.exp(-x))
def softmax2_first(x):
    z = np.array([x, 0.0]); e = np.exp(z - z.max())
    return (e / e.sum())[0]

xs = np.linspace(-4, 4, 9)
diff = np.max(np.abs([sigmoid(x) - softmax2_first(x) for x in xs]))
print("max |sigmoid - 2class softmax| =", diff)   # ~1e-16

# RLHF — Reinforcement Learning from Human Feedback

## 동기: 왜 instruction finetuning만으로는 부족한가 {#sec-rlhf-motiv}

**직답.** Instruction finetuning은 *언어 모델링 목적함수*를 최적화하지만, 우리가 실제로 원하는 것은 *인간 선호(human preference)를 만족*시키는 것이다. 이 둘 사이에는 **목적 불일치(objective mismatch)** 가 존재한다.

::: {.callout-note title="Recap — Instruction Finetuning"}
다양한 task를 "instruction–answer" 쌍의 형태로 묶어 사전학습된 LLM을 추가 미세조정하면, **학습에 직접 쓰이지 않은(unseen) task에서도 zero-shot 성능이 향상**된다 (Wei et al., *Finetuned Language Models Are Zero-Shot Learners*, ICLR 2022). 형식상 "fine-tuning"이지만, 실질은 광범위한 task로 모델을 추가 *사전학습*하여 일반화된 응답 능력을 끌어올리는 절차에 가깝다.
:::

Instruction finetuning의 두 가지 본질적 한계:

| # | 한계 | 설명 | 예시 |
|---|------|------|------|
| 1 | **정답이 없는 task** | open-ended 생성은 단일 정답·단일 metric이 없음 → instruction–answer 쌍 자체를 만들 수 없음 | "강아지와 그 애완 메뚜기에 대한 이야기를 써줘" |
| 2 | **토큰 오류의 균등 처벌** | 언어 모델링 손실은 모든 토큰 오류를 *동일하게* 처벌하지만, 어떤 오류는 더 치명적임 | "현재 미국 대통령은 ___" 에서 *이름* 토큰의 오류는 조사·접속사 오류보다 훨씬 치명적 |

핵심 통찰: **언어 모델링 목적($\max \log p(\text{next token})$)은 "사용자의 만족도"를 직접 신경 쓰지 않는다.** 다음 토큰을 높은 확률로 뱉을 뿐, 그 응답이 인간을 *얼마나 만족시키는지*는 목적함수에 들어 있지 않다. → **"인간 선호를 명시적 목적으로 넣을 수 없을까?"** 가 RLHF의 출발점이다.

## RLHF의 3단계 구조 {#sec-rlhf-3step}

**직답.** RLHF = SFT로 시작점 마련 → 선호 데이터로 보상 모델 학습 → 그 보상으로 LLM을 RL 미세조정.

```{mermaid}
flowchart LR
    A["Step 1<br/>Instruction-tuned LM<br/>(SFT 시작점)"] --> B["Step 2<br/>인간 피드백 수집<br/>(선호 쌍, Likert/랭킹)"]
    B --> C["Step 3<br/>보상 모델(RM) 학습<br/>+ PPO로 LLM 미세조정"]
    C -. "정책이 base에서<br/>너무 벗어나지 않게 KL 제약" .-> C
```

- **Step 1 — SFT 시작점**: instruction finetuning으로 그럴듯한 응답을 내는 기반 모델을 만든다.
- **Step 2 — 피드백 수집**: 하나의 prompt에 대해 LLM이 **두 개의 응답**을 생성하면, 사람이 **어느 쪽이 더 선호되는지** Likert 척도(강하게 더 좋음 ↔ 약간 더 좋음)나 랭킹으로 평가한다. (OpenAI는 공학 전공자가 아닌 언어학·인문 전공자를 다수 고용해 고임금으로 라벨링을 수행했다는 일화가 있다.)
- **Step 3 — 보상 모델 + RL**: 선호 데이터로 *보상 모델*을 학습하고, 그 보상을 신호로 LLM을 강화학습으로 미세조정한다.

::: {.callout-tip title="역사적 맥락 — Learning to summarize (NeurIPS 2020)"}
초기 실험(Stiennon et al.)에서, 동일 prompt에 대해 *바닐라 LM* 출력은 같은 말을 반복하는 등 기계적이었으나, **경량 인간 피드백을 주입한 모델**의 출력은 사람이 쓴 것처럼 자연스러워졌다. 이 효과를 확인한 뒤 GPT-3 계열을 InstructGPT → ChatGPT로 발전시키는 3단계 파이프라인이 정립되었다.
:::

## 보상 모델과 Bradley–Terry 손실 {#sec-rlhf-rm}

**직답.** 보상 모델은 *선택된(chosen) 응답*의 보상이 *거절된(rejected) 응답*의 보상보다 커지도록, 두 보상의 차이를 키우는 손실로 학습한다.

base 모델 위에 새 final layer(선호 헤드)를 얹고, 다음 손실을 최소화한다:

$$
L_{\text{RM}} \;=\; \log\!\Big(1 + e^{\,r_{\text{rejected}} - r_{\text{chosen}}}\Big).
$$

이는 **Bradley–Terry / 로지스틱 선호 모형**과 동일하다. $\sigma(z)=\frac{1}{1+e^{-z}}$ 로 두면

$$
L_{\text{RM}} = -\log \sigma\!\big(r_{\text{chosen}} - r_{\text{rejected}}\big),
$$

즉 "chosen이 rejected를 이길 확률"의 음의 로그우도(이진 교차엔트로피)다. (부록 @sec-appendix 에서 두 형태의 *수치적 등가성*을 SymPy로 검증한다.)

::: {.callout-note title="실무 디테일"}
- **단 1 epoch** 학습(의도적 overfitting).
- 인간 평가 *상호 동의율(agreement)* 은 보통 **65–75%** 수준 — 보상 신호는 본질적으로 noisy하다. 이 점이 뒤의 KL 정규화(@sec-rlhf-kl) 필요성으로 이어진다.
- 손실에 *margin*(선택지 간 강도 차이)을 추가하는 변형이 흔하다.
:::

## RL 관점에서 본 RLHF + PPO-Clip {#sec-rlhf-ppo}

**직답.** LLM = *정책(policy)*, 출력 토큰열 = *행동(action)*, 보상 모델 = *환경의 보상*. 이를 PPO-Clip으로 최적화한다.

| RL 개념 | RLHF에서의 대응 |
|---------|----------------|
| Agent / Policy $\pi_\theta$ | 학습 중인 LLM |
| Action | LLM이 생성한 응답(토큰열) |
| Environment reward | 인간 선호로 학습된 **보상 모델** 출력 |
| Episode | 하나의 prompt → completion |

> **참고.** RLHF의 "deep" 여부는 *프레임워크*가 아니라 *정책/가치 함수에 신경망을 쓰는지*에 달려 있다. 동일한 RL 프레임으로 deep/shallow 모두 가능하다.

PPO-Clip 의사코드(반복 루프):

```text
for each iteration:
    1. 현재 정책 π_θ 로 completion 집합 수집  (← LLM 생성, "episode")
    2. 보상 모델로 각 completion 의 reward 계산
    3. advantage  Â  추정 (가치함수 V_φ 이용)
    4. PPO-Clip 목적함수로 정책 파라미터 θ 갱신
    5. 가치함수 φ 를 gradient descent 로 갱신
    repeat
```

PPO에 국한될 필요는 없다 — DPO 등 다른 정렬 기법으로도 LLM을 미세조정할 수 있다.

## 보상이 불안정하므로: base 정책으로의 KL 정규화 {#sec-rlhf-kl}

**직답.** 보상 신호가 noisy하므로, 학습된 정책이 *원래 LM에서 너무 멀어지지 않도록* KL 발산으로 보수적으로 제약한다.

$$
\max_\theta \;\; \mathbb{E}\big[\, r(x) \,\big] \;-\; \beta\, D_{\mathrm{KL}}\!\big(\pi_{\text{RLHF}} \,\|\, \pi_{\text{base}}\big).
$$

::: {.callout-important title="두 KL을 혼동하지 말 것 (시험 빈출 포인트)"}
| | 비교 대상 | 역할 |
|---|---|---|
| **RLHF의 KL** | $D_{\mathrm{KL}}(\pi_{\text{RLHF}} \,\|\, \pi_{\text{base}})$ | 학습 정책을 **원래 base LM**에 *앵커링* — 모델이 망가지지 않도록 |
| **PPO-Clip의 KL** | $D_{\mathrm{KL}}(\pi_{\text{old}} \,\|\, \pi_{\text{new}})$ | **연속한 두 정책 반복(iterate)** 사이의 신뢰영역(trust region) — 업데이트 폭 제한 |

즉 RLHF-KL은 *절대 기준(base)* 에 묶는 정규화 항이고, PPO-KL은 *상대 기준(직전 정책)* 에 대한 스텝 크기 제약이다. 또한 PPO-Clip은 매 gradient step마다 작은 신뢰영역을 강제하지만, RLHF의 KL 항은 여러 step을 모아 한 번 크게 갱신할 때 base로부터의 거리를 직접 벌점화한다.
:::

## "Alignment"라는 이름 {#sec-rlhf-align}

선호 데이터로 모델을 사용자 취향에 맞추는 절차는 *여전히 파라미터를 갱신하는 학습*이지만, "fine-tuning/learning"이라는 표현이 식상하다는 이유로 **alignment(정렬)** 이라는 새 이름으로 부른다. 본질은 같다(일종의 마케팅적 재명명).

::: {.callout-note title="무선통신 비유 — 제한된 피드백 기반 적응"}
RLHF는 **수신단의 제한된 피드백(limited feedback)으로 송신 정책을 적응**시키는 폐루프 제어와 닮았다.
- *보상 모델* = 채널 품질을 대신하는 **학습된 품질 지표(soft CSI)**. 인간 선호는 정확한 CSI가 아니라 *양자화된 선호 피드백*(어느 쪽이 더 좋은지)에 해당한다 → 그래서 noisy(동의율 65–75%).
- *Bradley–Terry 로지스틱* = soft-decision의 **LLR(log-likelihood ratio)** 와 같은 로지스틱 링크.
- *KL 정규화(→base)* = **근접(proximal)·신뢰영역 갱신**. 적응형 전력제어에서 한 번에 큰 스텝을 밟지 않고 직전(또는 기준) 동작점 근처로 업데이트를 제한해 발산을 막는 것과 동형(同型)이다.
:::

::: {.callout-tip title="보조 참고 (math4ml / d2l)"}
- KL 발산·엔트로피의 정의와 성질: math4ml의 *Probability* 절(엔트로피·상대엔트로피)을 함께 보면 KL 정규화의 직관이 단단해진다.
- 정책경사·PPO의 RL 기초: d2l.ai의 강화학습/정책최적화 관련 장을 보조 자료로 활용.
:::

# PEFT — Parameter-Efficient Fine-Tuning

## 왜 PEFT인가 {#sec-peft-why}

**직답.** 거대 모델 전체를 갱신하지 않고 *소수의 파라미터만* 갱신하여 적응시키는 기법.

| 이점 | 메커니즘 |
|------|----------|
| **효율 증가 / 빠른 time-to-value** | 갱신 파라미터가 적어 학습·배포가 빠름 |
| **Catastrophic forgetting 감소** | 기존 가중치를 대부분 동결 → 사전학습 지식 보존 |
| **Overfitting 위험 감소** | 갱신 자유도가 작음 |
| **데이터 요구량 감소** | 적은 파라미터 → 적은 데이터로 충분 |
| **접근성 향상** | 적은 자원으로 거대 모델 적응 가능 |

대표 기법: **Adapters, LoRA, QLoRA**, Prefix-/Prompt-/P-tuning. 본 노트는 앞의 세 가지를 다룬다.

## Adapter {#sec-peft-adapter}

**직답.** Transformer 블록 사이에 *작은 추가 레이어(adapter)* 를 끼워 넣고, 기존 가중치는 동결한 채 **adapter와 LayerNorm만** 학습한다 (Houlsby et al., Google Research, ICML 2019).

- feed-forward·multi-head attention 가중치는 **고정**.
- 새로 삽입한 adapter는 보통 **down-projection → 비선형 → up-projection** 구조(병목, bottleneck).
- 출력 분포가 달라지므로 **LayerNorm을 추가/재학습**.

결과적으로 *소수의 레이어만 갱신*하면서, 이전에 학습한 지식과 새 데이터 지식을 LayerNorm 재조정으로 섞어 양쪽 정확도를 모두 유지한다.

## LoRA — Low-Rank Adaptation {#sec-peft-lora}

**직답.** 가중치 갱신량 $\Delta W$ 를 **저랭크(low-rank) 분해 $BA$** 로 근사하여, 원래 가중치 $W$ 는 동결하고 $A,B$ 만 학습한다 (Hu et al., Microsoft, ICLR 2022).

선형층 $W \in \mathbb{R}^{d\times d}$ 에 대해:

$$
h \;=\; W x \;+\; \underbrace{B A}_{\Delta W}\, x,
\qquad A \in \mathbb{R}^{r \times d},\; B \in \mathbb{R}^{d \times r},\; r \ll d.
$$

- **파라미터 수**: $W$ 는 $d^2$, $BA$ 는 $2dr$. 절감비

$$
\frac{2dr}{d^2} = \frac{2r}{d}.
$$

예: $d=4096,\ r=8$ 이면 $2dr/d^2 = 1/256$. 실제 LoRA는 종종 **원본의 0.1% 이하** 파라미터만 학습한다.

::: {.callout-note title="왜 저랭크로 충분한가 — 직관"}
어떤 task의 적응에 필요한 정보가 *full-rank* 만큼 복잡하지 않다면(내재 차원이 낮다면), 갱신 방향은 저차원 부분공간에 거의 놓인다. 그 부분공간만 $BA$ 로 학습하면 된다. 이는 행렬의 **저랭크 근사(SVD의 상위 특이값만 취하기)** 와 같은 정신이다.
:::

추론 시 $BA$ 를 $W$ 에 병합($W' = W + BA$)할 수 있어, **추론 지연 0**으로 만들 수 있다(다만 어댑터를 분리 유지하면 약간의 overhead가 있다).

## QLoRA — Quantized LoRA {#sec-peft-qlora}

**직답.** 동결된 base 가중치를 **저정밀도(예: 4-bit)로 양자화**한 상태에서 LoRA 어댑터를 학습한다 (Dettmers et al., UW, NeurIPS 2023 Oral).

- LoRA의 $BA$ 가 base의 0.1% 미만이라도 *절대 크기*가 클 수 있다. base를 양자화하면 **메모리·overhead를 더 줄이면서** 정확도를 거의 유지한다.
- 요지: "동결된 무거운 부분은 낮은 비트로, 학습하는 가벼운 부분(어댑터)은 그대로" → 매우 컴팩트한 적응.

::: {.callout-note title="무선통신 비유 — 저랭크 부분공간 적응 & 양자화 피드백"}
- **LoRA** = **reduced-rank / 부분공간 적응**. MIMO에서 채널이 저랭크일 때 상위 특이모드(빔)만으로 프리코딩하는 것, 혹은 적응 필터에서 *부분공간 추적(subspace tracking)* 으로 소수 좌표만 갱신하는 것과 동형이다. 전체 $W$ 가 아닌 저차원 방향 $BA$ 만 학습 = *제한된 피드백 코드북*으로 핵심 방향만 보정.
- **QLoRA** = 적응 정보를 **양자화**해 전송·저장 비용을 줄이는 limited-feedback 정밀도 절감과 같다(핵심 빔은 동결·양자화, 보정만 정밀하게).
:::

::: {.callout-tip title="보조 참고 (math4ml / d2l)"}
- 저랭크 근사·SVD·고유분해의 엄밀한 배경: math4ml의 *Linear Algebra* 절(eigendecomposition, singular values)을 LoRA 직관의 토대로 삼을 것.
- Adapter/LoRA가 끼어드는 Transformer 블록 구조: d2l.ai의 *Attention Mechanisms / Transformer* 장으로 위치 감각을 보강.
:::

# RAG — Retrieval-Augmented Generation

## 동기와 핵심 아이디어 {#sec-rag-idea}

**직답.** LLM은 *거짓말을 하려는 게 아니라* 확률적으로 그럴듯한 토큰을 뱉다가 **환각(hallucination)** 을 낸다. 관련 외부 문서를 *조건*으로 주어 환각을 줄인다 (Piktus et al., Facebook, NeurIPS 2020).

흐름:

```{mermaid}
flowchart LR
    Q["쿼리<br/>(예: 한국 문화)"] --> E["쿼리 임베딩"]
    E --> S["MIPS<br/>최대 내적 검색"]
    DB["문서 임베딩 DB / 웹"] --> S
    S --> R["가장 관련 높은<br/>문서 선택"]
    R --> G["문서 + 쿼리로<br/>응답 생성(조건부)"]
    G --> O["환각 줄어든 출력"]
```

## MIPS와 RAG-Sequence vs RAG-Token {#sec-rag-mips}

**Maximum Inner Product Search (MIPS).** 쿼리 임베딩 $q$ 와 문서 임베딩 $\{d_i\}$ 의 **내적(코사인 유사도와 같은 정렬도)** 을 계산해 최대값 문서를 찾는다:

$$
i^\star = \arg\max_i \; \langle q, d_i \rangle .
$$

상위 $K$ 개 문서에 대해 seq-to-seq 예측을 **주변화(marginalize)** 한다:

| 변형 | 동작 | 비용/특성 |
|------|------|----------|
| **RAG-Sequence** | *문장 전체*를 한 번에 보고 가장 관련된 문서를 골라 생성 | 한 시퀀스에 **하나의 문서** 사용 — 더 저렴 |
| **RAG-Token** | *토큰마다* 관련 문서를 다시 찾아 생성 후 결합 | 토큰마다 **다른 문서** 가능 — 더 비쌈, 더 유연 |

어느 쪽이 우월한지는 application에 따라 다르다. 2020년 이후 수많은 고급 변형이 나왔으나, **최소한 MIPS는 확실히 이해**하고 거기서 출발해 문헌을 따라가는 것이 권장된다.

::: {.callout-note title="무선통신 비유 — 정합 필터 / 상관 수신기"}
**MIPS의 "내적 최대화" = 정합 필터(matched filter)·상관 수신기**. 수신 신호와 후보 파형(코드)의 상관을 최대화해 가장 잘 맞는 경로/심볼을 고르는 것(예: RAKE 수신기의 강한 상관 경로 선택)과 정확히 같은 연산이다. 검색된 문서로 응답을 *그라운딩*하는 것은 **파일럿 기반 채널추정으로 디코딩을 정합**시키는 것에 대응한다.
:::

::: {.callout-tip title="보조 참고 (d2l)"}
임베딩·attention 기반 유사도와 seq-to-seq 디코딩의 기초는 d2l.ai의 *Attention / Encoder–Decoder* 장에서 보강할 수 있다.
:::

# AI Agents (Agentic AI)

## 정의와 Toolformer {#sec-agents-def}

**직답.** 에이전트 = *외부 도구를 호출*하거나 *계획을 세워* 작업을 끝내는 (대개 LLM 기반) 모델. 출력이 단어 토큰이 아니라 **행동(action) 토큰**이라는 점이 핵심.

- 이름("AI Agents" vs "Agentic AI")은 중요치 않다 — 본질은 *도구 호출·계획으로 고정밀 작업 수행*.
- 행동은 물리적 동작일 수도, 컴퓨터 조작(마우스 이동·클릭·타이핑하는 web agent)일 수도 있다. 작업 = **행동의 시퀀스**.

**Toolformer (Schick et al., UW, NeurIPS 2023)** — 초기 대표 사례:

```{mermaid}
flowchart LR
    T["LLM 토큰 생성 중"] --> A["API 호출 토큰 삽입"]
    A --> X["API 실행 → 결과 수신"]
    X --> L["손실로 평가:<br/>다음 토큰 예측이<br/>개선되는가?"]
    L -->|"개선됨"| K["API 결과 채택"]
    L -->|"개선 안 됨"| D["폐기, 원래 출력 사용"]
```

즉 **"API 호출 결과가 다음 토큰의 손실을 줄여주면 그 호출을 학습 데이터로 채택"** 하는 자기지도 방식. 오늘날에는 이런 도구 제어를 더 정교하게 다뤄 web agent·로봇 등으로 확장한다.

::: {.callout-note title="무선통신 비유 — 폐루프 제어와 제어 시그널링"}
에이전트는 **외부 센싱(도구·웹)으로 상태를 관측하고 행동을 출력하는 폐루프 제어기**다. 행동 토큰은 물리계층의 *제어 시그널링*에 대응하며, 관측→평가(손실)→행동 채택의 루프는 채널 상태를 보고 변조·전력을 조정하는 적응 루프와 같은 구조다.
:::

# World Models

## 초기 정의 (Ha & Schmidhuber, 2018) {#sec-wm-early}

**직답.** *세계의 대리(proxy) 모델*. RL에서 model-based 방법의 "model"(환경 시뮬레이터)이 곧 world model이다.

- 개념적 뿌리는 1993년 Scott McCloud — "인간은 뇌 속에서 *상상*하고, 그 상상의 결과로 행동한다"는 직관. 자전거를 머릿속으로 그려보며 타듯, **상상의 출력으로 행동**한다.
- Ha & Schmidhuber(NeurIPS 2018)는 이를 **시각 입력 + 메모리 + 컨트롤러** 구조로 구체화: 지각(perception)에서 압축된 표현을 얻고, 메모리(순환 구조)로 동역학을 예측하며, 컨트롤러가 행동 시퀀스를 산출한다.

## 현대적 world model {#sec-wm-modern}

**직답.** 지각 정보(시각·언어·오디오 등)로부터 *상호작용 가능한 세계*를 학습 → 사실상 **무한히 영상을 생성하는 모델**로 진화. 그 위에서 로봇·정책 모델을 학습한다.

대표 사례:

| 모델 | 핵심 |
|------|------|
| **UniSim (2023)** | *Universal Simulator* — 다양한 현실 장면(내비게이션·조작 등)을 생성해 정책 학습용 입력을 만든다 (Yang et al., *Learning Interactive Real-World Simulators*) |
| **LWM (2025)** | *Large World Model* — 멀티모달 토큰 시퀀스 위의 autoregressive transformer |
| **NVIDIA Cosmos (2025–2026)** | 사전학습 멀티모달 생성 모델 스위트 |

**LWM (Liu, Yan, Zaharia, Abbeel, ICLR 2025)** 구조:

- 각 **비디오 프레임 → VQGAN으로 256개 토큰**으로 토큰화.
- **텍스트 → BPE(Byte-Pair Encoding)** 토크나이저로 처리.
  - BPE/바이트 수준 인코딩을 쓰면, 단어 수준 인코딩의 방대한 vocabulary 대신 *소수의 문자 단위*만으로 다양한 언어 변형을 표현할 수 있다.
- 이미지·텍스트 토큰을 합쳐 transformer에 넣고 **autoregressive하게 다음 토큰 예측**.

**NVIDIA Cosmos** 3종 모듈:

```{mermaid}
flowchart LR
    P["Cosmos Predict<br/>(world model)<br/>다음 프레임 예측 → 세계 생성"] --> R["Cosmos Reason<br/>(VLA/추론 모델)<br/>Predict 위에서 학습"]
    P --> T["Cosmos Transfer<br/>(sim→real 도메인 전이)<br/>실세계 적용"]
```

- **Cosmos Predict**: 주어진 프레임 시퀀스로 *다음 프레임*을 예측하는 world model → 영상 형태의 세계 거동 생성.
- **Cosmos Reason**: Predict 위에서 학습하는 추론/행동 모델(VLA 예시).
- **Cosmos Transfer**: sim-to-real 도메인 전이로 실세계 적용을 개선.
- *Cosmos 2.5*(2025년 10월) → *Cosmos 3*(2026년 6월): mixture-of-transformers 기반, 공개 합성 비디오 데이터를 활용해 비전·추론을 강화하고 더 나은 정책 모델·세계 시뮬레이션을 지향.

::: {.callout-note title="무선통신 비유 — 채널 예측 / 디지털 트윈"}
World model은 **채널 예측기(channel predictor)·디지털 트윈**과 같다. "다음 프레임 예측"은 "다음 채널 상태 예측"에 대응하며, 예측된 미래 위에서 정책을 학습·계획하는 것은 **예측적 자원할당(predictive scheduling)** — 미래 채널을 내다보고 미리 자원을 배치하는 것과 동형이다. 실제 환경을 직접 두드리지 않고 *내부 모델 안에서 시뮬레이션*해 학습하는 점이 model-based의 핵심 이득이다.
:::

|----|------|------|-------------------|
| **RLHF** | LM 목적 ≠ 인간 선호 | 선호 보상 + RL 미세조정 | $L_{\text{RM}}=-\log\sigma(r_c-r_r)$, base로의 KL 정규화 |

# 보론: 연구 방법론 노트 {#sec-research}

본 회차 후반부의 연구 조언을 핵심만 정리한다(시험 범위와 별개로 가치가 높음).

## 연구와 출판의 정의 {#sec-research-def}

- **Research = re-search**: 해를 못 찾았기에 *다시, 또다시* 탐색하는 일. 실패가 평상(ordinary)이고, *해를 찾는 날이 비범(extra-ordinary)* 하다. 매일 새것을 못 찾는 게 정상이며, 찾으면 오히려 놀라야 한다.
- **Publication ≠ "내가 한 일의 보고"**: 무엇을 시도했는지가 아니라, **문제에 대한 새로운·놀라운 발견**을 보고하는 것. 단, *무엇을 시도했고 무엇을 배웠는지는 스스로 기록*하라(같은 실수 반복 방지). 다만 논문 본문에 시도 나열을 쓰지는 말 것.
- 좋은 논문의 메시지: *"이 문제를 풀려면 이렇게 해야 한다"* (예: "객체 검출을 효율적·정확하게 하려면 X를 해야 한다"). *"이걸 해봤더니 5% 올랐으니 받아달라"* 는 약한 논문.

## 절차와 원칙 {#sec-research-proc}

1. **흥미로운 주제 선정** — 많은 사람에게 흥미로운 문제일수록 가치가 크다.
2. **선행연구 위에서 시작** — 바퀴를 다시 발명하지 말 것. SOTA를 읽고, 무엇이 잘못됐는지 찾아 고친다. 그래서 남의 논문을 읽는다.
3. **협업** — 거대 모델 시대엔 (예: 100명 이상 저자의 기술 리포트) 다수와 협업해야 큰 임팩트가 난다. *함께 일하고 싶은 사람*이 되라.

## 큰 아이디어 vs 점진적 아이디어 {#sec-research-bigidea}

- **점진적(safe) 아이디어**: 결과가 예측 가능, 거의 항상 출판 가능하지만 커리어 임팩트는 작다(예: 성능 +몇 %).
- **큰(risky) 아이디어**: 고위험·고수익. 구현이 길고 고통스러우며 결과 보장이 없지만, 성공하면 임팩트가 *수십~수백 배*. (CNN처럼 오랜 잠복 끝에 빛을 본 사례, GPU 컴퓨팅의 장기 투자 사례 등.)
- 박사 초기엔 작은 아이디어로 *연습*하되, 진짜 연구는 **4–5년을 걸 만한 큰 아이디어인지**로 판단하라. "창의적·독창적이며(때로 과감할 만큼) 큰 문제"를 노릴 것.

## 리뷰·리버탈의 현실 {#sec-research-rebuttal}

- 리뷰어는 시간이 없고 *거절할 이유*를 찾는다(피상적으로 수치·그림·결론만 본다). 그러니 **"거절할 이유를 만들 수 없게"** 쓰는 것이 곧 좋은 논문/리버탈 작성이다.
- 명명(naming)도 영향력의 일부: 좋은 아이디어엔 기억에 남는 이름을 붙여라(예: LSTM 계열의 게이팅 변형들).

::: {.callout-note title="회차 말미의 기술적 여담 — 게이팅(gating)"}
"과거를 기억"하기 위해 도입된 핵심 아이디어가 **게이팅**이다. 현재 입력과 과거 메모리를 게이트 값으로 가중합:
$$
f \;=\; g(x)\odot x \;+\;\big(1-g(x)\big)\odot m, \qquad g(x)\in(0,1),
$$
여기서 $m$ 은 메모리(과거의 이동평균적 누적). 대표 변형으로 **LSTM**과, 더 적은 파라미터로 유사 성능을 내는 **GRU**가 있다. *시간에 걸친 기억(long-range memory)* 은 여전히 완전히 풀리지 않은 난제다.
:::

# 부록: 수식 검증 (Python/SymPy·NumPy) {#sec-appendix}

아래 코드는 본문의 세 가지 수치 주장을 재현·검증한다.

```{python}
#| label: verify-rm-loss
#| code-fold: show
import sympy as sp

# (1) 보상모델 손실의 등가성:
#     -log sigma(r_c - r_r)  ==  log(1 + e^{r_r - r_c})
r_c, r_r = sp.symbols('r_c r_r', real=True)
bt    = -sp.log(1/(1 + sp.exp(-(r_c - r_r))))   # Bradley-Terry 형태
slide =  sp.log(1 + sp.exp(r_r - r_c))          # 본문 손실 형태
print("등가성 확인 (0이어야 함):",
      sp.simplify(sp.expand_log(bt - slide, force=True)))
```

```{python}
#| label: verify-lora-params
#| code-fold: show
# (2) LoRA 파라미터 절감비 2r/d
def lora_ratio(d, r):
    full = d * d          # 원본 W 의 파라미터 수
    lora = 2 * d * r      # A(r x d) + B(d x r)
    return full, lora, lora / full

for d, r in [(4096, 8), (4096, 16), (1024, 4)]:
    full, lora, ratio = lora_ratio(d, r)
    print(f"d={d:5d}, r={r:2d} -> 원본={full:>9d}, LoRA={lora:>7d}, "
          f"비율={ratio:.5f} (≈ 1/{round(1/ratio)})")
```

```{python}
#| label: verify-sigmoid-softmax
#| code-fold: show
import numpy as np
# (3) sigmoid(x) == 2-class softmax([x, 0])_0  (선호 모형의 로지스틱 링크)
def sigmoid(x): return 1.0 / (1.0 + np.exp(-x))
def softmax2_first(x):
    z = np.array([x, 0.0]); e = np.exp(z - z.max())
    return (e / e.sum())[0]

xs = np.linspace(-4, 4, 9)
diff = np.max(np.abs([sigmoid(x) - softmax2_first(x) for x in xs]))
print("max |sigmoid - 2class softmax| =", diff)   # ~1e-16
```

::: {.callout-note title="검증 결과 요약"}
- (1) 보상모델 손실 두 형태는 *기호적으로 정확히 0* (완전 등가).
- (2) LoRA 절감비는 $2r/d$: 예) $d=4096,\,r=8 \Rightarrow 1/256$.
- (3) Bradley–Terry 로지스틱은 2-클래스 softmax와 동일 — 선호 학습이 이진 교차엔트로피임을 재확인.
:::
