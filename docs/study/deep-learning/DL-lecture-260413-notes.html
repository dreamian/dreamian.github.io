1 전체 개요

2 Part I. 최적화를 돕는 현대적 기법

2.1 Batch Normalization — 핵심 복습과 한계

Batch normalization(BN)은 엄밀히 말하면 최적화 알고리즘이 아니라 학습 중인 파라미터의 적응적 재매개변수화(adaptive reparameterization) 기법이다. 미니배치 \(H\)의 활성값을 평균 \(\mu\), 표준편차 \(\sigma\)로 정규화하여 학습/테스트 데이터를 유사한 통계적 범위 안에 묶어준다:

\[ H' = \frac{H - \mu}{\sigma}, \qquad \text{테스트 시에는 학습 중 누적한 running } \mu, \sigma \text{ 사용} \]

WarningBN의 부작용: 표현력 손실

평균과 분산을 강제로 정규화하면 활성값의 크기(magnitude)에 담긴 정보가 소실될 수 있다. 이는 일반화에 유용할 수도 있는 정보를 죽이는 부정적 효과다. 이를 보상하기 위해 학습 가능한 스케일/시프트 파라미터를 도입한다:

\[ H \;\leftarrow\; \gamma H' + \beta \]

\(\gamma, \beta\)는 데이터로부터 학습되므로, 네트워크가 필요하다면 정규화를 “되돌릴” 수 있는 자유도를 확보한다.

Note시대적 흐름: 왜 요즘은 BN을 덜 쓰는가

BN은 MLP·CNN 시대에는 매우 효과적이었지만, Transformer가 주류가 된 이후로는 사용 빈도가 크게 줄었다. Transformer는 query–key 유사도에 기반해 가중치를 학습하는 구조라 배치 단위 통계 정규화의 이득이 작고, 대신 layer normalization이 표준이 되었다. 기법의 유효성은 아키텍처 패러다임에 종속된다는 좋은 사례다.

무선통신 관점: BN은 수신 신호의 AGC(Automatic Gain Control) + DC offset 제거와 유사하다. 신호를 일정한 동적 범위로 정규화하면 후단 처리(양자화, 검출)가 안정되지만, 수신 전력 자체가 정보(예: RSSI 기반 거리 추정)인 경우 그 정보를 잃는다 — \(\gamma, \beta\)는 이 손실을 보상하는 학습형 게인 스테이지에 해당한다.

2.2 Pretraining: 고전적 동기와 현대적 반전

2.2.1 고전적 pretraining — 작은 것에서 큰 것으로

전통적 동기는 다음과 같다. 모델이 크고 복잡하면 처음부터 직접 최적화하기 어렵다. 따라서:

  1. 작은(단순한) 모델을 단순한 task에 먼저 학습시킨다.
  2. 점진적으로 복잡도를 더해가며 관심 있는 복잡한 task로 확장한다.

이를 task 단위로 탐욕적으로(greedy) 쪼개어 하나씩 학습하는 방식이 greedy supervised pretraining이다. 예컨대 깊은 네트워크를 학습할 때 먼저 얕은 서브네트워크를 손실값으로 학습시키고, 그 위에 새 레이어를 추가한 뒤 fine-tuning한다. 먼저 학습된 하위 레이어들이 여러 의미(semantics)에 공통적인 정보를 이미 담고 있으므로, 새 레이어 학습의 좋은 출발점이 되어 전체를 처음부터(from scratch) 학습하는 것보다 수렴이 빠르다.

이 접근의 배경에는 학습 데이터가 극히 부족했던 시절의 제약이 있다. 적은 샘플로 좋은 local minimum에 도달하려면 이런 단계적 최적화가 필요했다.

2.2.2 현대적 pretraining — 정반대의 철학

Important패러다임 역전

현대의 pretraining은 고전적 동기와 정확히 반대다:

\[ \text{거대 데이터} \;\Rightarrow\; \text{거대 모델을 먼저 학습} \;\Rightarrow\; \text{downstream task의 좋은 초기점으로 사용} \]

작은 모델에서 키워가는 것이 아니라, 처음부터 거대 모델을 거대 데이터로 학습한 뒤 이를 다양한 downstream task의 출발점으로 가져온다. 이렇게 여러 downstream task의 기반(foundation) 역할을 하는 사전학습 모델을 foundation model이라 부른다.

구분 고전적 pretraining 현대적 pretraining
데이터 규모 매우 작음 매우 큼 (거대 데이터 풀)
모델 성장 방향 작은 모델 → 복잡도 추가 처음부터 거대 모델
목적 어려운 최적화를 단계적으로 완화 downstream task의 좋은 초기점 제공
대표 방식 Greedy supervised pretraining Foundation model + fine-tuning

2.2.3 MAML: Model-Agnostic Meta-Learning

대표적인 현대적 pretraining 기법으로 MAML(Finn, Abbeel, Levine, ICML 2017)이 있다. 이름에 핵심 키워드 두 개가 들어 있다:

  • Model-agnostic: 특정 아키텍처에 종속되지 않고, gradient 기반 최적화를 쓰는 모든 모델에 적용 가능하다.
  • Fast adaptation: 사전학습된 모델을 downstream task에 아주 적은 반복(예: 1–2 epoch의 fine-tuning) 만으로 적응시킬 수 있다.

아이디어는 단순하다 — 매우 다양한 작은 task들로 동시에 pretraining하라는 것. 영상 분류, 분할, next-token 예측, 행동 예측 등 서로 다른 목적의 task들로 사전학습하면, 모델이 어떤 downstream task가 와도 소수의 gradient update만으로 높은 성능에 도달할 준비가 된다. 기술적으로는 여러 task에 대한 gradient update를 동시에 반영하는 형태로 구현되며, instruction fine-tuning과 유사한 정신을 공유한다. 실제로 이 기법은 로보틱스에서 foundation model을 다양한 조작 task에 범용적으로 적응시키는 데 활발히 쓰이고 있다.

무선통신 관점: MAML은 다양한 채널 환경(도심/교외/실내)에서 동시에 학습한 범용 채널 추정기에 비유할 수 있다. 특정 채널 통계에 과적합된 추정기는 환경이 바뀌면 처음부터 재학습해야 하지만, 다양한 채널 분포로 메타학습된 추정기는 새 환경에서 소량의 파일럿(소수의 adaptation step)만으로 빠르게 수렴한다.

2.3 Knowledge Distillation

2.3.1 핵심 아이디어

큰 teacher network의 출력(soft label, logit)을 supervision으로 사용해 작은 student network를 학습시키는 기법이다 (Hinton, Vinyals, Dean, 2015). 절차는:

  1. 먼저 큰 teacher network를 학습한다.
  2. Student network를 학습할 때, 원래의 one-hot 정답에 대한 cross-entropy 손실과 함께 teacher의 soft label을 추가 supervision으로 사용한다.

흥미롭게도 이 논문은 학회에 제출되지 않고 arXiv에만 공개되었다 — 아이디어가 “너무 단순해서” 학회 심사를 통과하기 어려운 형태였지만, 실제로는 매우 잘 작동하여 지금까지도 광범위하게 쓰인다(최근의 DeepSeek 계열 모델 학습에도 활용). 단순함과 유용함은 별개의 축이라는 교훈이기도 하다.

2.3.2 왜 soft label이 도움이 되는가

이유 1 — 범주들은 서로 연관되어 있다. 오렌지와 자몽을 생각해 보자. 두 과일은 모양, 질감을 공유하고 본질적 차이는 속 색깔 정도다. 그런데 one-hot encoding은 어떤 이미지에 대해 “자몽 100%, 오렌지 0%”라는 과도하게 단정적인 supervision을 강제한다. 사람조차 외형만으로 확신할 수 없는 구분이다. 사람들에게 확률을 물어 soft label을 만드는 것도 주관적이라 신뢰하기 어렵다. 반면 teacher network는 “자몽 75%, 오렌지 20%, 기타 5%” 같은 출력을 주는데, 이 분포가 hard one-hot보다 이미지의 의미 구조에 대해 더 많은 것을 말해준다. 즉 soft label은 모호한 클래스 간 경계를 완화(relax)해 준다.

이유 2 — 단일 hard label 자체가 주관적이고 noisy하다. ImageNet의 라벨은 같은 이미지에 대해 3명에게 물어 다수결로 정해졌다. 한 이미지에 여인·선글라스·손·립스틱이 모두 있는데 라벨은 “립스틱”이고, 차 안의 커플 사진에서 몇 픽셀 안 되는 안전벨트가 라벨이 되기도 한다. 이렇게 hard label은 많은 경우 어떤 의미에서 “틀려” 있다. Soft label은 이 노이즈를 완충한다.

이유 3 — 앙상블 효과. 복수의 teacher를 쓰면 teacher 출력의 앙상블이 더 안정적이고 유용한 supervision을 제공한다.

무선통신 관점: 이것은 채널 디코딩에서 hard decision vs. soft decision의 차이와 정확히 같은 구조다. 복조기가 비트를 0/1로 잘라 전달(hard)하면 신뢰도 정보가 소실되지만, LLR(log-likelihood ratio) 형태의 soft 정보를 전달하면 후단 디코더(LDPC/Turbo)의 성능이 크게 향상된다. Teacher의 logit은 정확히 이 LLR에 해당하고, one-hot label은 hard decision에 해당한다.

2.4 더 나은 아키텍처 — 최적화를 “돕는” 설계

엄밀히 최적화 기법은 아니지만, 아키텍처 자체가 더 나은 최적해로의 수렴을 가능하게 한다. MLP → CNN → Transformer로의 진화, 그 사이의 수많은 CNN 변형(ResNet, DenseNet, U-Net 등)이 그 예다.

대표적으로 ResNet은 skip(highway) connection을 통해 gradient가 깊은 레이어를 거치며 소실(vanish)되지 않도록 gradient의 고속도로를 제공한다.

Tip인과 메커니즘 사슬로 이해하기

“ResNet이 학습을 돕는다”를 한 줄로 외우지 말고 메커니즘으로 연결하자: skip connection \(y = F(x) + x\) → Jacobian에 항등 성분 \(\frac{\partial y}{\partial x} = \frac{\partial F}{\partial x} + I\) 추가 → 역전파 시 gradient에 곱해지는 항이 0 근처로 붕괴하지 않음 → 깊은 망에서도 하위 레이어까지 유의미한 gradient 전달 → 더 깊은 모델의 안정적 최적화 가능.

2.5 Continuation Methods와 Curriculum Learning

2.5.1 Continuation methods

비용함수 \(J(\theta)\)를 직접 최적화하는 대신, 점점 어려워지는 비용함수 열 \(\{J^{(0)}, J^{(1)}, \dots, J^{(n)}\}\) 을 순차적으로 최적화한다. \(J^{(0)}\)는 가장 매끄럽고 쉬운 함수, \(J^{(n)}\)은 국소 굴곡이 많은 실제 목표 함수다. 쉬운 함수에서 얻은 해를 다음 단계의 초기점으로 삼으면, 국소 최적화가 well-behaved한 영역에서 대부분의 시간을 보내도록 초기점/가중치를 유도할 수 있어, 최종적으로 더 좋은 local minimum에 도달할 확률이 올라간다.

2.5.2 Curriculum learning (shaping)

Continuation method의 한 구현이 curriculum learning이다. 사람의 학습처럼 쉬운 task를 먼저, 어려운 task를 나중에 학습시킨다.

Note직관 vs. 실증, 그리고 현재적 중요성

직관적으로 매우 그럴듯하지만, 일반적인 지도학습에서는 성능 이득이 크지 않은 경우가 많다. 그러나 강화학습이나 weakly supervised learning처럼 학습이 어려운 영역에서는 매우 중요하다. 특히 foundation model 시대에는 “어떤 데이터를 어떤 순서로 먹일 것인가”라는 커리큘럼 설계가 거대 모델 학습에 필요한 GPU 비용 자체를 좌우하는 핵심 문제가 되었다.

무선통신 관점: HARQ의 incremental redundancy를 떠올리면 좋다. 처음부터 최저 부호율(가장 어려운 조건 대비)로 보내는 대신, 쉬운 조건(높은 부호율)부터 시작해 필요할 때 점진적으로 redundancy를 추가한다 — 문제의 난이도를 점층적으로 올리며 자원을 효율적으로 쓰는 구조가 닮았다.

MAML 메타학습 다양한 task로 사전학습 → 소수 step으로 fast adaptation
Knowledge distillation supervision 개선 teacher의 soft label로 student 학습
아키텍처 개선 (ResNet 등) 구조적 설계 \(+I\) Jacobian으로 gradient 보존
Continuation / curriculum 학습 스케줄 쉬운 목적함수 → 어려운 목적함수 순차 최적화

전체 최적화 단원의 큰 그림: ① 1차 미분 기반 기법(SGD, momentum, Adam 계열), ② 2차 미분 기반 기법(계산 비용 때문에 실전에서는 드묾), ③ 기타 기법(block coordinate descent — 파라미터를 그룹으로 나눠 하나씩 최적화, Polyak averaging 등), ④ 위의 현대적 기법들. 이들은 MLP뿐 아니라 CNN, Transformer 학습에도 공통으로 유효하다.

3 Part II. CNN 입문 — 왜 convolution인가

3.1 출발점: Universal Approximation Theorem의 역설

복습하면, UAT(Universal Approximation Theorem) 는 단일 은닉층, 유한 개 뉴런의 feed-forward 네트워크가 활성함수에 대한 약한 가정 하에 \(\mathbb{R}^n\)의 compact subset 위 연속함수를 임의 정밀도로 근사할 수 있음을 말한다(Cybenko, 1989, sigmoid에 대해 최초 증명).

CNN과 Transformer에 대한 동일한 형태의 엄밀한 증명은 표준적으로 제시되지 않지만, 이들은 MLP에 서로 다른 inductive bias(구조적 제약)를 부여한 변형으로 볼 수 있다 — 같은 최적화 절차, 같은 학습 패러다임 위에서 아키텍처만 다르다. 그렇다면 역설이 생긴다:

Important핵심 질문

UAT에 따르면 MLP는 거의 모든 함수를 근사할 수 있다. 그런데 왜 CNN, Transformer 같은 다른 아키텍처가 필요한가?

답의 핵심: UAT는 표현 가능성(존재성)을 말할 뿐, 유한한 데이터와 계산으로 그 해를 학습 가능한지는 말하지 않는다. 아키텍처의 inductive bias는 학습의 통계적·계산적 효율을 결정한다.

3.2 MLP로 이미지를 본다는 것 — permutation invariance의 저주

스포츠 세단 이미지를 MLP로 분류한다고 하자. MLP는 각 픽셀마다 독립적인 가중치를 할당하고, 은닉층을 쌓아 의미 수준까지 올라간 뒤 역전파로 학습한다. 여기서 결정적인 사고 실험:

이미지의 픽셀 위치를 전부 뒤섞으면(shuffle) MLP는 다른 것을 학습하는가? — 아니다. 가중치의 순서만 똑같이 뒤섞일 뿐, 정확히 같은 것을 학습한다. 즉 MLP 관점에서 원본 이미지와 픽셀이 뒤섞인 이미지는 완전히 동일한 문제다.

사람에게는 원본에서 차를 알아보는 것이 쉽고 뒤섞인 이미지에서는 불가능하다. MLP에게는 둘 다 후자만큼 어렵다 — 공간 구조라는 강력한 단서를 전혀 활용하지 못하기 때문이다. 그 결과, 이미지를 라벨 공간으로 매핑하려면 엄청난 수의 학습 샘플이 필요해진다.

Tip픽셀은 혼자서는 의미가 없다

수십 년의 컴퓨터 비전 연구가 도달한 한 가지 핵심 교훈: 픽셀을 개별적으로 인코딩하지 말라. 김춘수의 「꽃」처럼 — 이름을 불러주기 전에는 하나의 몸짓에 지나지 않았다 — 개별 픽셀은 의미가 없고, 이웃 픽셀들과 함께 묶일 때 비로소 의미를 갖는다. 따라서 이미지는 patch(작은 부분 영역) 단위로 인코딩해야 한다. 이것이 MLP에서 CNN으로 넘어가는 가장 큰 동기이며, “patch가 2D 정보 이해의 기본 단위”라는 inductive bias를 네트워크에 심는 것이다.

3.3 필터라는 발상 — 두 가지 근본 질문

숫자 “5” 이미지를 인식하고 싶다고 하자. 이미지와 완벽히 일치하는 가중치 창(필터) 이 있다면 정규화된 상관 점수가 1이 되고, 필터의 의미를 알고 있으므로 “이 이미지는 5”라고 확신할 수 있다. 다른 필터를 대면 상관 점수가 낮게 나와 기각할 수 있다.

그러나 이미지 전체를 통째로 매칭하는 필터를 쓰려면 세상의 이미지 수만큼 필터가 필요하다 — 명백히 비효율적이다. 그래서 발상을 전환한다: 이미지를 patch들로 쪼개고, patch 수준의 “조각 필터”들을 일종의 기저(basis)처럼 학습하여 임의의 입력을 표현하자. 그러면 두 가지 질문이 남는다.

  1. 어떤 필터 집합이 필요한가?
  2. 그 필터를 이미지의 어디에 적용해야 하는가?

3.3.1 질문 1의 역사 — 손으로 설계한 필터에서 학습된 필터로

초기 컴퓨터 비전은 필터를 사람이 설계했다: Gaussian 필터, 비등방성(anisotropic) Gaussian을 여러 각도로 회전시킨 필터(방향별 정보 포착 + 노이즈 평활), 이후에는 edge 성분을 각도별 히스토그램으로 집계하는 HOG(Histogram of Oriented Gradients), 유사 계열의 SIFT(Scale-Invariant Feature Transform) 등. 일부 응용에서는 잘 작동했지만 모든 응용에 통하지는 않았다 — 응용마다 특징 집합을 새로 설계해야 한다면 일반화가 안 된다는, No Free Lunch 정리적 상황에 부딪힌 것이다. CNN의 약속은 여기서 나온다: 필터를 손으로 설계하지 말고 데이터로부터 학습하자.

3.3.2 질문 2의 역사 — interest point에서 전수 스캔으로

초기에는 필터를 적용할 distinctive한 위치(interest point) 를 먼저 찾고, 그 주변에서 히스토그램을 뽑아 집계했다. 그러나 다양한 이미지 변형에 대해 안정적으로 interest point를 추출하는 것 자체가 어려운 문제였다. 그래서 실용적 해법으로 전환한다: 모든 위치를 필터로 전수 스캔(sweep)하고, 필터가 가장 강하게 반응하는 위치의 응답을 취하자. 이것이 CNN 내부의 max pooling 연산의 동기다 — “이 필터가 반응해야 할 곳이 어디든, 최대 응답만 보면 된다.”

3.4 Convolution 연산 — 정의와 세 가지 상관 연산

3.4.1 정의

Convolution(기호 \(*\))은 두 함수로부터 제3의 함수를 만드는 연산이다. 신호 및 시스템에서 익숙한 그 연산이다. 1차원에서:

\[ (f * g)(t) = \int_{-\infty}^{\infty} f(\tau)\, g(t - \tau)\, d\tau \]

한 함수를 (세로축 기준으로) 뒤집고(flip), \(-\infty\)에서 \(+\infty\)까지 슬라이딩하며 두 함수가 겹치는 영역의 적분값을 제3 함수의 값으로 할당한다. 어느 함수를 뒤집어도 결과는 같다(교환법칙). 본질적으로 이것은 두 함수 사이의 (이동에 따른) 상관을 계산하는 것이며, 2D convolution은 같은 연산을 두 축에 대해 수행한다 — 즉 2D 공간 정보를 전수 스캔하며 유사도를 계산하는, 우리가 원하던 바로 그 sweep 연산이다.

3.4.2 Convolution vs. Cross-correlation vs. Autocorrelation

연산 flip 여부 대상 정의(1D 연속)
Convolution 한 함수를 flip 서로 다른 두 함수 \(\int f(\tau)g(t-\tau)d\tau\)
Cross-correlation flip 없음 서로 다른 두 함수 \(\int f(\tau)g(t+\tau)d\tau\)
Autocorrelation flip 없음 자기 자신 \(\int f(\tau)f(t+\tau)d\tau\)
Note“CNN”은 사실 cross-correlation 네트워크다

실제 CNN 구현은 convolution이 아니라 cross-correlation이다. 이유는 단순하다: 필터를 학습하는 상황에서는 “저장 시 flip → 적용 시 flip back”의 왕복 flip이 아무 의미 없는 군더더기가 된다. flip을 생략해도 네트워크는 (뒤집힌 형태의) 정확히 같은 필터를 학습한다. 다만 “cross-correlation neural network”는 부르기 번거롭고 convolution이 더 멋있게 들려서 이름이 그렇게 굳었을 뿐이다. d2l.ai 7.2절도 같은 점을 명시한다.

무선통신 관점: 이 구분은 matched filter와 정확히 같은 그림이다. AWGN에서 SNR을 최대화하는 matched filter의 임펄스 응답은 \(h(t) = s^\ast(T-t)\) — 송신 펄스의 시간 반전(= flip) 이다. 그래서 matched filtering(convolution)의 출력은 결국 수신 신호와 템플릿의 상관기(correlator) 출력과 동일하다. CNN 필터는 데이터로부터 학습되는 2D matched filter bank이고, feature map은 각 템플릿에 대한 상관 출력으로 읽으면 된다.

3.5 CNN의 핵심 가정: Stationarity

CNN은 2D 정보를 이해하기 위한 하나의 큰 가정 위에 서 있다 (LeCun, 1998):

ImportantStationarity 가정

이미지 patch의 통계는 위치에 무관하게 동일하다. 생성 모형의 언어로: patch에 대한 단 하나의 data-generating distribution이 있고, 이미지는 그 분포에서 patch들을 샘플링해 이어붙인 것으로 볼 수 있다. (실제로 최신 이미지/비디오 생성 모델은 방대한 이미지로부터 이런 거대 분포를 학습한다.)

왜 이것이 자연스러운가? 같은 산을 두 사람이 찍는다고 하자. 한 사람의 사진에서 왼쪽 위에 있던 patch가 다른 사람의 사진에서는 중앙에 올 수 있다 — 같은 3D 세계가 2D로 투영될 때 동일한 patch가 임의의 위치에 나타날 수 있으므로, “사람이 찍을 수 있는 이미지들의 집합”을 생각하면 patch는 위치와 무관하게 단일 분포에서 나온다고 보는 것이 합리적이다.

이 가정의 보상은 막대하다:

  • 가중치 공유(weight sharing): 각 은닉 유닛을 작은 입력 patch에 연결하되, 같은 필터를 모든 공간 위치에 재사용할 수 있다. 이것이 convolution layer이고, 이를 포함한 네트워크가 CNN이다.
  • 위치마다 별도의 필터를 학습할 필요가 없으므로 파라미터 수와 필요 데이터량이 극적으로 감소한다. 모든 위치의 patch가 하나의 분포 학습에 기여하므로 데이터 효율도 좋아진다.

무선통신 관점: 이것은 확률과정의 WSS(wide-sense stationarity) 가정과 같은 역할이다. 채널이 WSS(-US)라고 가정하면 상관함수가 절대 시점이 아닌 시간차에만 의존하므로, 서로 다른 시점의 관측을 하나의 통계 모형 추정에 모두 활용할 수 있다(예: Jakes 모델 기반 도플러 스펙트럼 추정). Stationarity가 깨지면 시점마다 통계를 따로 추정해야 해서 필요한 관측량이 폭증한다 — CNN에서 위치별 필터를 따로 학습해야 하는 상황과 정확히 대응된다.

3.5.1 대안: Locally connected layer — stationarity를 의도적으로 깨기

각 위치가 작은 patch에만 연결되되 가중치를 공유하지 않는 locally connected layer도 있다. 위치마다 다른 필터를 배우므로 데이터가 많이 필요하지만, 이미지가 정합(registered)되어 있는 도메인에서는 유용할 수 있다. 예: 여권 사진(눈·코·입의 위치가 고정), MRI/CT 스캔(신체 형태에 맞춰 정합) — 특정 위치의 분포가 “눈의 모양”, “간의 모양”처럼 위치 특이적 의미를 가지므로, stationarity를 깨고 위치별 필터를 두는 것이 더 특화된 정보를 포착한다. 그러나 일반적인 비정합 이미지에서는 위치별 통계가 뒤섞여 있으므로 stationarity를 가정하는 편이 데이터 활용 면에서 거의 항상 낫다.

3.6 Convolution layer의 연산

\(32 \times 32 \times 3\) (RGB) 이미지에 \(5 \times 5 \times 3\) 필터를 적용한다고 하자. 필터를 이미지 위에서 공간적으로 슬라이드하며, 각 위치에서 필터 값과 이미지 값의 element-wise 곱의 합(= dot product) 으로 숫자 하나를 만든다. 이 출력값들의 2D 배열을 activation map(feature map)이라 부른다 — 각 값이 필터와 입력의 상관(유사도) 점수이므로, 필터가 인코딩하는 의미 정보에 대한 응답 지도다.

핵심 규칙들:

  • 필터의 채널 수는 입력 채널 수를 자동으로 따른다. “\(5\times5\) 필터”라고 말해도 입력이 3채널이면 실제 필터는 \(5\times5\times3\)이다.
  • 필터 하나당 feature map 하나가 나온다. 필터가 \(K\)개면 출력은 \(K\)채널.
  • 출력 한 값은 필터의 중심 픽셀 위치에 할당된다. 이 때문에 필터 크기는 관례적으로 홀수(\(3\times3, 5\times5, 7\times7\))다 — 짝수면 중심이 픽셀 사이에 떨어진다.
  • 따라서 padding 없이 \(5\times5\) 필터를 적용하면 상하·좌우 각각 2픽셀씩 경계가 잘려 \(32\times32 \to 28\times28\)이 된다.

3.6.1 Stride

매 픽셀마다 convolution하는 대신 몇 픽셀씩 건너뛰며 적용할 수 있다(stride \(S\)). 인접 위치의 응답은 서로 매우 유사한 경우가 많으므로, 중복 정보를 줄이고 계산량을 절감한다. 고해상도(4K 등) 입력에서 특히 유용하다.

  • 예: \(7\times7\) 입력, \(3\times3\) 필터, stride 2 → 출력 \(3\times3\) (stride 1이면 \(5\times5\)).
  • 예: 같은 설정에서 stride 3 → 필터가 끝까지 맞아떨어지지 않아 일부 영역이 인코딩에서 누락된다. stride는 입력·필터 크기와 정합되게 골라야 한다.

3.6.2 Padding

경계 정보를 잃지 않고 (혹은 출력 크기를 입력과 같게 유지하고) 싶다면, 경계 밖에 가상의 값을 채워 필터가 경계를 넘어 연산할 수 있게 한다.

Padding 종류 방식 비고
Zero padding 0으로 채움 가장 보편적. 경계에서 가중치를 사실상 0과 곱해 노이즈 정보를 주입하지 않음
Repeat(replicate) padding 경계값을 반복 픽셀값이 0.5면 패딩도 0.5, 0.5, …
Mirror(reflect) padding 경계 기준 거울 반사 […, 0.5, 1.0] 끝을 2픽셀 패딩하면 […, 0.5, 1.0, 0.5, …]처럼 반사

(픽셀값 범위가 0–255라면 255 padding은 흰 테두리, 0 padding은 검은 테두리에 해당한다.)

3.6.3 출력 크기 공식

입력 한 변의 크기 \(N\), 필터 크기 \(F\), stride \(S\), padding \(P\)일 때:

\[ O = \frac{N - F + 2P}{S} + 1 \]

(마지막 \(+1\)은 첫 번째 필터 적용 위치에 해당한다.) 라이브러리가 자동으로 계산해 주지만, 시험과 설계 감각을 위해 손으로 확인할 수 있어야 한다.

Tip연습 문제 1 — 출력 volume 크기

입력 \(32\times32\times3\), 필터 \(5\times5\) 10개, stride 1, padding 2일 때 출력 volume은?

\[ O = \frac{32 - 5 + 2\cdot 2}{1} + 1 = 32 \;\Rightarrow\; \textbf{32} \times \textbf{32} \times \textbf{10} \]

공간 크기는 입력과 동일(이른바 “same” padding)하고, 채널 수는 필터 개수 = 10이 결정한다.

Tip연습 문제 2 — 파라미터 수 (단골 함정)

같은 설정(\(5\times5\) 필터 10개, 입력 3채널)에서 이 layer의 파라미터 수는?

흔한 오답: \(5\times5\times10 = 250\).

올바른 계산: 필터는 입력 채널을 자동으로 포함하므로 \(5\times5\times\mathbf{3}\)이고, 각 필터마다 bias 1개(\(wx + b\)의 \(b\), 스칼라)가 있다:

\[ (5 \times 5 \times 3 + 1) \times 10 = 76 \times 10 = \textbf{760} \]

3.6.4 MLP 대비 효율 — 정량 비교

같은 \(32\times32\times3\) 입력을 fully-connected layer로 받으면 뉴런 하나당 \(32\times32\times3 = 3072\)개의 가중치가 필요하다. 반면 위 convolution layer는 필터 10개를 쓰고도 전체 760개다. 이 inductive bias(patch 단위 인코딩 + 가중치 공유)가 주는 이득을 메커니즘 사슬로 정리하면:

파라미터 수 감소 → 채워야 할 자유도가 줄어 필요 학습 데이터량 감소(데이터 효율) → 동시에 “픽셀–edge 관계”를 데이터로 일일이 배우는 대신 patch 구조로 모듈화 → 모든 공간 위치의 관측이 단일 필터 학습에 기여 → 계산 효율과 통계 효율을 동시에 확보. 또한 한 layer의 다채널 출력(예: 10채널)은 다음 convolution layer의 입력 채널이 되어, 다음 필터는 자동으로 \(F\times F\times 10\) 형태가 된다 — 이렇게 계층적으로 쌓인다.

3.7 Pooling

3.7.1 왜 “pooling”인가

숫자들의 풀(pool)에서 하나를 고르는 연산이라 pooling이다(명사 pool의 동사화 — bottle→bottling처럼). 필터를 여러 위치에 적용해 얻은 응답값들의 풀에서, 어떤 규칙으로 하나를 선택하느냐가 pooling의 종류를 결정한다.

Pooling 선택 규칙 언제 자연스러운가
Max pooling 최댓값 연산이 유사도(상관/내적) 일 때 — 가장 강한 응답 = 가장 잘 맞는 위치
Min pooling 최솟값 연산이 거리(예: Euclidean) 일 때 — 최소 거리 = 가장 잘 맞는 위치
Mean(average) pooling 평균 영역 전체의 평균적 응답을 요약하고 싶을 때
Warningmean vs. min — 용어 함정

min(최소)과 mean(평균)을 혼동하지 말 것. min pooling은 최솟값, mean pooling은 평균이다.

Max pooling의 의미를 다시 동기와 연결하면: 필터를 전 위치에 sweep할 때, 그 필터가 반응해야 할 위치의 최대 응답만 취하고, 반응하지 않아야 할 위치들에서 발생하는 노이즈성 응답을 버리는 연산이다. 즉 “이 필터에 해당하는 패턴이 이미지 어딘가에 (얼마나 강하게) 존재하는가”만 남긴다.

3.7.2 왜 max가 “유사도”에 맞는가 — 내적의 기하

Convolution의 각 위치 연산은 두 벡터(필터, patch)의 내적이다. 내적의 기하학적 의미는 한 벡터를 다른 벡터 방향으로 사영(projection) 한 길이와 크기의 곱:

\[ \langle \mathbf{a}, \mathbf{b} \rangle = \|\mathbf{a}\|\,\|\mathbf{b}\|\cos\theta \]

단위벡터라면 내적은 \(\cos\theta\) 그 자체 — 두 방향이 얼마나 정렬되어 있는가(angular distance)를 측정한다. \(\theta \to 0\)이면 최대(완전 정렬), \(\theta \to 90°\)면 0(직교 = 무관). 따라서 내적 기반 응답에서는 큰 값이 좋은 매칭이므로 max를 취하는 것이 옳고, 거리 기반이라면 작은 값이 좋은 매칭이므로 min을 취해야 한다. 연산의 의미가 pooling의 선택 규칙을 결정한다. (사영과 내적의 엄밀한 전개는 Math4ML의 inner product / orthogonal projection 절이 가장 깔끔하다.)

무선통신 관점: 이것은 수신기 설계의 두 등가 관점 — correlator 수신기 vs. minimum-distance 수신기 — 와 같은 이야기다. AWGN에서 ML 검출은 수신 벡터와 후보 신호점 사이 Euclidean 거리 최소화(\(\min\))와, (등에너지 성상이라면) 상관 최대화(\(\max\))가 동치다. Max pooling은 correlator bank에서 최대 상관 가지를 고르는 것, min pooling은 거리 기반 검출에서 최근접 후보를 고르는 것에 해당한다.

또한 pooling layer는 한 출력 뉴런이 바라보는 입력 영역, 즉 receptive field를 키우는 효과가 있다 — 깊이가 깊어질수록 더 넓은 공간 맥락을 요약하게 된다.

3.8 Part II 요약과 다음 주제

  • MLP는 UAT에도 불구하고 2D 입력에 대해 공간 구조를 활용하지 못해(픽셀 순서에 무관) 데이터·파라미터 비효율이 극심하다.
  • 해법은 patch 단위 인코딩 + 학습된 필터 + 전 위치 sweep이라는 inductive bias이고, 이를 정당화하는 가정이 stationarity(patch 통계의 위치 불변성)다.
  • 실제 구현은 flip 없는 cross-correlation이며, 출력 크기는 \(O = (N - F + 2P)/S + 1\), 파라미터 수는 \((F \cdot F \cdot C_{in} + 1) \times K\).
  • Pooling은 응답 풀에서의 선택 연산으로, 연산의 의미(유사도 vs. 거리)가 max/min의 선택을 결정한다.

이어지는 주제: dilated convolution, deconvolution, 효율적 CNN, CNN의 신경과학적 배경, ImageNet.

5 부록: Python으로 검증하기

출력 크기 공식과 파라미터 수를 PyTorch로 직접 확인한다.

import torch
import torch.nn as nn

# ---------- 1. 출력 크기 공식 검증 ----------
def out_size(N, F, S, P):
    return (N - F + 2 * P) // S + 1

# 32x32, 5x5 filter, no padding, stride 1 -> 28
print(out_size(32, 5, 1, 0))   # 28

# 7x7, 3x3 filter, stride 2 -> 3
print(out_size(7, 3, 2, 0))    # 3

# 32x32, 5x5 filter, stride 1, pad 2 -> 32 ("same")
print(out_size(32, 5, 1, 2))   # 32

# PyTorch로 동일 설정 확인
x = torch.randn(1, 3, 32, 32)
conv = nn.Conv2d(in_channels=3, out_channels=10,
                 kernel_size=5, stride=1, padding=2)
print(conv(x).shape)           # torch.Size([1, 10, 32, 32])

# ---------- 2. 파라미터 수 검증: (5*5*3 + 1) * 10 = 760 ----------
n_params = sum(p.numel() for p in conv.parameters())
print(n_params)                # 760
print(conv.weight.shape)       # [10, 3, 5, 5]  -> 750
print(conv.bias.shape)         # [10]           -> +10

# ---------- 3. MLP와의 비교: 뉴런 1개당 가중치 ----------
fc = nn.Linear(32 * 32 * 3, 1)
print(sum(p.numel() for p in fc.parameters()))  # 3073 (3072 + bias 1)
# 뉴런 1개만으로 conv layer 전체(760)의 4배 이상

# ---------- 4. convolution = flip된 cross-correlation ----------
import torch.nn.functional as Fn
sig    = torch.tensor([1., 2., 3., 4.]).view(1, 1, -1)
kernel = torch.tensor([1., 0., -1.]).view(1, 1, -1)

xcorr = Fn.conv1d(sig, kernel, padding=2)                 # PyTorch의 "conv" = cross-correlation
conv  = Fn.conv1d(sig, kernel.flip(-1), padding=2)        # 진짜 convolution = flip 후 적용
print(xcorr)   # tensor([[[-2., -2., -2., -2.,  3.,  4.]]]) 형태
print(conv)    # flip된 결과 — 둘은 커널 반전 관계

# ---------- 5. max vs min pooling: 유사도 vs 거리 ----------
patchs  = torch.randn(8, 25)          # 8개의 5x5 patch (flatten)
template = torch.randn(25)

sim  = patchs @ template              # 내적(유사도) -> max가 best match
dist = ((patchs - template) ** 2).sum(dim=1)  # 거리 -> min이 best match
print(sim.argmax().item(), dist.argmin().item())
# SymPy로 출력 크기 공식을 기호적으로 다뤄보기
import sympy as sp
N, F, S, P = sp.symbols('N F S P', positive=True, integer=True)
O = (N - F + 2*P) / S + 1

# "same" 출력 조건: O = N, S = 1 일 때 필요한 padding
P_same = sp.solve(sp.Eq(O.subs(S, 1), N), P)[0]
print(P_same)        # (F - 1)/2  ->  F=5 이면 P=2, F=3 이면 P=1
