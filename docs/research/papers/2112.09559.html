ColO-RAN 논문 정리

Developing ML-based xApps for Open RAN Closed-loop Control on Programmable Experimental Platforms

저자

Polese, Doro, Bonati, Restuccia, Melodia (IEEE TMC, 2022) · arXiv:2112.09559

공개

2026년 6월 23일

1 한 줄 요약

O-RAN 기반 closed-loop 제어를 위한 DRL xApp을 대규모 실험 플랫폼에서 설계·학습·검증한 최초의 체계적 연구. RAN 슬라이싱과 스케줄링을 데이터 기반으로 실시간 제어하는 xApp 3종을 만들고, 실제 무선 채널을 에뮬레이션하는 환경에서 73시간 이상의 full-stack 데이터로 학습·평가했다.

2 문제의식 — 왜 이 연구가 필요한가

O-RAN은 RIC 위에서 xApp으로 ML 기반 제어를 표준화했지만, 정작 ML 연구의 진척이 느린 이유는 인프라 부재라는 것이 출발점이다. 저자들이 꼽은 다섯 가지 실무적 난점:

  1. 대규모 데이터셋 수집 — 실제 RAN의 randomness를 반영한 데이터 부족
  2. 스케일에서의 테스트 — closed-loop 제어를 라이브망에서 검증하기 어려움
  3. 불완전한 입력 / 제약된 출력 — 실제 telemetry는 주기가 불규칙하거나 누락됨
  4. 일반화(generalization) — 학습에 없던 배포 환경으로의 적응
  5. feature 선택 — 차원 폭발 없이 의미 있는 상태 표현 구성

핵심 동기는, 통신사조차 상용망을 ML 학습/테스트에 내주기 어렵기 때문에 연구가 소규모 lab 데이터에 갇히고 결과가 일반화되지 않는다는 점이다.

3 ColO-RAN 플랫폼 구조

두 축을 결합한 실험 플랫폼이다.

3.1 Colosseum — wireless data factory

DARPA가 구축한 대규모 무선 에뮬레이터. 다수의 SDR(USRP)과 FPGA 기반 채널 에뮬레이터(MCHEM)로 실제 페이딩·전파 특성을 hardware-in-the-loop로 재현한다. 다양한 RF 시나리오에서 full-stack 데이터셋을 생성하는 “데이터 공장” 역할을 한다.

3.2 O-RAN 인프라

O-RAN Software Community(OSC) 릴리스를 경량화하여 컨테이너(LXC)로 구동하는 near-RT RIC. RAN 측은 srsRAN을 확장한 SCOPE 프레임워크를 CU/DU로 사용하며, E2 인터페이스로 RIC과 연결된다. 컨테이너 기반이라 실내 testbed(Arena)로 포팅도 가능하다.

노트실험 규모

7개 base station · 42개 UE · 3개 슬라이스(eMBB / MTC / URLLC) · 10 MHz(50 PRB). 수집 데이터 73시간 이상(약 3.4 GB).

4 xApp 설계 — 연구의 핵심

세 종류의 xApp을 설계했다.

xApp 3종
xApp 제어 방식 Action (출력)
sched-slicing 단일 DRL agent가 slicing + scheduling 동시 제어 슬라이스별 PRB 수 + 스케줄링 정책
sched 슬라이스별 병렬 DRL agent 슬라이스별 스케줄링 정책
online-training 라이브 RAN에서 온라인 탐색 학습 학습 액션

4.1 DRL agent 설계

  • 알고리즘: PPO (on-policy actor-critic). fresh data만 사용해 학습은 느리지만 off-policy(DQN) 대비 안정적이라는 이유.
  • Observation: rate, buffer size, PHY transport block 수, PRB ratio (DL 기준). 입력 차원이 크면 학습이 느려지므로 의도적으로 축소.

4.2 Autoencoder — 핵심 설계 novelty

RAN telemetry를 그대로 넣지 않고 encoder로 차원 축소(\(T \times N\) 행렬 → \(N\)차원 벡터)한 뒤 DRL agent에 전달한다. 두 가지 효과:

  1. 차원 축소 → state→action 매핑 품질 개선
  2. 결측 telemetry에 대한 robustness → 학습 시 입력의 일부 entry를 의도적으로 0으로 만들어, 운영 중 입력 텐서가 완전히 채워지지 않아도 의미 있는 상태 표현을 유지하도록 학습

이는 위 문제의식 (3)번(불완전한 입력)을 정면으로 다루는 설계다.

4.3 Feature selection

O-RAN E2SM-KPM은 수백 종의 KPM을 노출하므로, 상관분석(correlation matrix) 으로 redundancy를 제거한다. 예를 들어 transport block 수와 symbol 수는 상관이 거의 \(1.0\)이라 둘 다 넣을 필요가 없고, transport block 수와 buffer occupancy는 상관이 낮아 둘 다 정보 가치가 있다. 최종적으로 transport block 수 · buffer occupancy · DL rate 등을 입력으로 선택.

5 주요 실험 결과 / 교훈

  • 적응적 제어 > 정적 최적 설정: slicing까지 함께 조정하는 sched-slicing이 slicing을 고정한 sched보다 우수. 특히 하위 percentile 사용자·PRB ratio 등 corner case에서 개선이 컸다.
  • Action space 설계가 성능을 좌우: 액션 집합을 제약한 agent는 정책이 편향되어 URLLC의 buffer/PRB ratio 유지에 실패.
  • Autoencoder 효과 입증: autoencoder를 제거한 agent가 전반적으로 가장 나쁨.
  • 온라인 학습의 trade-off: 사전학습 모델을 라이브망에서 추가 학습하면 배포 환경에 적응해 성능이 오르지만, 탐색 단계 동안 일시적 성능 저하(disservice) 가 발생.
  • 일반화의 비대칭성: agent는 채널 조건 변화에는 잘 일반화하지만 트래픽 프로파일 변화에는 더 취약(traffic 전환 시 entropy loss가 더 크게 튐).

6 리서치 갭 (Research Gaps)

이 논문이 다루지 않았거나 열어둔 지점들. 후속 연구의 진입점이 된다.

6.1 예측(prediction) 모듈의 부재

DRL agent는 현재 상태에서 정책을 학습하는 반응형(reactive) 구조다. 채널 품질이나 트래픽 수요를 미래 시점으로 예측해 선제적으로 자원을 배분하는 predictive 메커니즘은 명시적으로 존재하지 않는다.

힌트진입점

channel quality prediction + traffic prediction을 스케줄러 입력(utility)으로 넣어 predictive AI-RAN scheduler로 확장하는 방향이 자연스러운 차별점이 된다.

6.2 트래픽 일반화의 취약성 (저자 스스로 인정)

본문의 일반화 실험에서 agent는 채널 변화에는 강건했으나 트래픽 프로파일 변화에는 성능이 흔들렸다. traffic-aware / traffic-robust 학습은 미해결 문제로 남아 있다.

6.3 온라인 학습의 안전성 문제

online-training은 탐색 과정에서 실서비스 품질 저하를 일으킨다. 상용망에서 이를 감내하기 어려우므로, sim-to-real 전이나 safe exploration으로 탐색 비용을 제거하는 접근이 비어 있다.

6.4 거친 QoS 입도 (coarse granularity)

제어가 슬라이스 / 스케줄링 정책 수준에 머문다. flow 단위, 더 나아가 application·semantic 수준의 미세한 우선순위 구분은 다루지 않는다.

6.5 단순화된 합성 트래픽

트래픽이 단순화된 합성 모델(full-buffer 등)에 기반한다. 로봇 offloading, AI inference 같은 실제 application-driven 트래픽으로의 검증은 범위 밖이다.

6.6 Cross-layer 신호의 부재

DRL 입력이 RAN telemetry로 한정된다. 상위 모델 계층(application/model layer)의 신호 — 예컨대 생성 모델의 token importance(entropy, logprob, attention) — 가 L2 스케줄러로 내려와 utility에 반영되는 cross-layer 경로는 존재하지 않는다.

6.7 하드웨어 스택의 한계

검증이 SDR 에뮬레이션(Colosseum + srsRAN) 기반이다. GPU 가속 RAN (NVIDIA Aerial / cuMAC, GH200) 위에서의 RAN + AI inference workload convergence, 즉 실시간 AI-RAN 융합은 다루어지지 않는다.

7 종합 — 후속 연구로의 연결

ColO-RAN은 DRL xApp 기반 closed-loop 제어의 기준 아키텍처를 제공한다. 위 리서치 갭들을 묶으면, 후속 연구의 차별화 축은 다음으로 정리된다.

모델 계층 신호(token importance) → MAC L2 자원 할당으로 내리는 cross-layer 매핑 + 채널·트래픽 예측 기반 선제 스케줄링 + 실제 GPU RAN 스택 (cuMAC / GH200 / ROS2) 상의 검증.

즉 ColO-RAN의 autoencoder + DRL 파이프라인을 계승하되, (i) 예측 모듈을 끼워 반응형을 선제형으로 바꾸고, (ii) 합성 트래픽을 실제 로봇·AI inference 트래픽으로 대체하며, (iii) SDR 에뮬레이션을 GPU 가속 실스택으로 옮기는 것이 명확한 기여 지점이 된다.
